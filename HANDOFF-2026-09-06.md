## Completed fixes in this release

### dsh 0.1.3 BrowserAuth

- Added strict `WebLaunchUrl` parsing for the process-local `dsh web: http://127.0.0.1:<port>/?token=...` line.
- `LaunchFragment` now probes and opens the upstream per-process launch URL, with the old `dsha_t` URL retained only for legacy dsh.
- HTTP readiness accepts only 2xx/3xx and does not follow the one-time 303 redirect during the probe.
- Diagnostics redact the upstream token and other credentials before displaying logs.
- Upstream-auth dsh installations automatically have the retired DSHA host-webserver patch reconciled. An old `.dsha-bak` is restored atomically when available, and the obsolete runtime overlay is removed.
- LAN root GET exchanges the proxy token for the upstream BrowserAuth token once. API, POST, and already-cookie-authenticated requests do not receive the upstream credential.

### Runtime scripts

- Runtime script hot updates and their signed manifest were removed.
- All runtime scripts are read from the APK `assets` directory and released with the Java code and offline rootfs.
