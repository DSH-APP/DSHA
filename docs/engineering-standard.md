# 现行工程规范

本规范采用外部 build150 审计中经当前源码与用户要求复核的部分。原资料与首次复核见 [build154 审计](audits/build154/FINDINGS-BEFORE.md)，当前逐项处置以 README 指向的本轮台账为准。附件中的另一会话决策不直接成为本仓库规则。

上手步骤见[现行接手指南](接手指南.md)，职责见[模块图](module-map.md)，约束来源见[ADR 0001](adr/0001-build154-boundaries.md)，构建与提交见[CONTRIBUTING](../CONTRIBUTING.md)。旧指南和验收报告的原字节由[历史文档清单](audits/build154/history-document-sources.json)记录，不把旧命令重新纳入部署。

## 分层与状态归属

界面读取状态、渲染和转发用户操作；一个生产控制器持有 Web 代次、队列及停止意图。启动准备、输出观察、停止协调、安装和平台执行由实际协作者承担。协作者通过显式窄端口回调，不能另造第二个生产状态持有者。

`util` 的纯逻辑不得导入 Android。平台文件与进程操作使用已有安全文件层和身份检查；不能只换包名就声称依赖环消失。组合根可以装配平台及界面适配器，runtime 不得直接查找 Activity 或核心维护权威。

Java 17，不引入 Kotlin。新类按具体职责命名，优先显式 import、不可变值和有界集合。现有公开组件名、偏好键、协议文本和存盘格式保持读取兼容；大范围格式化、重命名和协议变更分别评审。

## 文件、事务与进程

- 对外部/用户路径先做所属根、对象类型、设备、inode、链接边界核验。只可规范化 Android 框架提供的应用目录别名，不能解除 guest 子树的 NOFOLLOW。
- 原子写遵循临时独占创建、完整写入/同步、发布及目录同步。复用已经验证的文件层，不再自建截断写记录。
- 签名运行资产与用户归档有不同链接语义。可信 Ubuntu 必须保留正常 guest 绝对链接，用户包不能借链接覆盖外部；两种边界分别测试，不能为了“一套解析器”降低任何一方的规则。
- 不按裸 PID、端口、名称发信号。停止、恢复和提交依赖本次出生身份、会话及退出证据；未知结果保留现场与屏障。
- 不在持锁期间执行网络、IPC 或外部回调。任务持有明确 owner、取消入口和有界等待，结果未知时不重放写入或依赖生命周期脚本。
- 状态标记使用稳定 ID；旧语言标签只在历史读取处映射。显示边界再本地化，不从成功文案推导环境就绪。

## 输入、凭据与协议

结构化输入在边界校验版本、类型、大小和重复值；未知数据保留并报告，不解释成新的本机授权。受信任生成 JSON 与用户输入采用相应严格度，逐步迁移具体调用点，不机械替换所有解析器。

凭据路径、机器状态、会话回收站排除由 `credential-paths.json` 的不同组定义。外部读写限制不能误用于删除用户明确选择的项目内容。原生 API Key 默认不导出；新用户备份无密码 tar.gz，内部自动副本继续使用本机保护；历史密文读取验证完整认证。

桥凭据只走请求头。为已有合法 Node fetch 插件提供仅指定本机 GET 的有限迁移适配；未知 curl/HTTP 库不能被宣称自动兼容。已安装源码不强行改写，冲突或不明确的凭据不发送。HTTP 协议响应和真实命令/用户内容不随界面语言变化。

插件按现行开放策略解析、检验实际目录/摘要、事务提交并启用；不恢复审阅门槛。用户禁用、安全模式、加载失败以及依赖作者声明与本机实测必须分开。

## 文案与诊断

使用文案目录的完整模板及中英资源。新增文案不要拼接不可翻译的片段；动态参数、文件名、用户正文、配对码和第三方说明保持原样。现有 API 在迁移期保留，不靠替换函数名制造“统一”。

只记录有界应用事件及脱敏诊断。真实操作错误不能被空 catch 静默吞掉；尽力清理可明确降为警告，取消和核心数据错误不能降级。日志记录不得截断覆盖旧完整历史，崩溃处理器不得递归记录自身故障。

## 单一事实源与生成物

| 事实 | 权威来源 |
|---|---|
| 应用版本／文件名 | `app/build.gradle` |
| DSH npm 树 | `tools/dsh-runtime/package.json` 与锁文件 |
| pnpm／CA 资产 | `tools/runtime-tools.lock.json` |
| 签名内置插件 | `assets/builtin-plugins.json` |
| 凭据／机器状态分组 | `assets/credential-paths.json` |
| 当前／退役补丁 | `assets/runtime-patches.json` |
| 独立应急 | `tools/recovery-runtime/lock.json` |
| 正式签名身份 | `ci/release-identity.json` |
| 真实生成输入 | `managed-runtime-inputs.json` 与运行时描述符 |
| 宿主测试入口 | `tools/host-tests.manifest.json` |
| APK部署成员和动态读取契约 | `tools/asset-deployment.json` |

实际文本为 LF，二进制不做换行替换。生成器使用确定性输入，不写主机路径或临时时间。改输入后重新生成并核对；不让描述符忽略真实字节变化。

`tools/history` 保存退休源和文档的精确原字节，排除换行重写与自动部署/执行。许可证、完整内置插件树和扩展成员由显式部署清单及结构化读取契约保留；源归档到包内物理成员的转换须有明确映射，不能用粗正则删资源。`UnusedResources` 为构建错误；先以实际引用和Lint清理，不用R8或资源压缩掩盖生命周期、反射与原生依赖风险。

Python 校验不能使用可被 `-O` 删除的 assert；测试入口拒绝优化模式。子进程使用参数数组和明确环境，不把秘密放 argv；路径与临时槽位必须属于本次任务。Node、Shell、JSON 各保留实际运行环境支持的语法，不把格式工具的大量变动混入功能修复。

## 验证与证据

每个新纯逻辑类都要测试。修复使用实际入口、真实锁定上游模块、故障边界或隔离文件系统证明；源码检查只证明结构约束。关键夹具先验证版本、内容、平台和输入指纹，不读某个旧目录就称当前运行时。

当前正式 Standard/Low 单测、Release Lint、APK/ELF、签名和插件／应急门禁都需要运行。设备、断电、FUSE、隐藏 API 和厂商进程访问限制另外记录。退休手工审计源代码可以留作历史，不能生成或安装额外审计 APK，不能修改正式用户数据做故障注入。

每个审计项写明实际实现、检查和残余；软件改动与缺失设备/外部证据分别记录。当前剩余集合从逐项当前回执重建，不复制历史 residualActionIds。用户要求保留的开放插件/终端、历史读取、未知退出屏障与完整性核验属于契约，不当作未修 bug。可维护性建议按实际职责收敛；不以行数、覆盖率、白名单或未经校准的分数替代工程判断。
