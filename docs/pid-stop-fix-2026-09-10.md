# 1.5-alpha.2 停止检查修订

修复更新时「无法确认 Web 已停止」的阻塞，并按用户要求取消启动超时自动终止。版本名、版本码 115、Ubuntu 基础版本 10 和 dsh 0.1.5-alpha.2 保持不变。

## 原因与处理

旧维护入口直接读取 `.dsha-web.pid` 并调用 `kill(pid, 0)`。旧编号被其他 UID 的进程复用时，内核返回 `EPERM`，代码直接中断维护；它没有与普通停止路径共同判断这条记录是否仍属于 Web。`kill(2)` 的权限和不存在语义见 [Linux 手册](https://man7.org/linux/man-pages/man2/kill.2.html)。

现在由 `WebProcessManager` 统一处理：先写停止哨兵，再读取 PID、内核启动时刻和命令；只给直接运行 dsh web 的已核验 Node 进程发送 SIGTERM。Web 就绪时保存启动时刻，PID 复用不继承原进程的停止权限。

对于过期、无权限控制或指向无关进程的编号，还需确认当前启动器/管道已退出，并只读核验本应用可控进程中没有 Web，才能隔离旧记录。未知读取错误、无效 PID、软链接记录以及仍在运行的 Web 继续阻止环境替换。不会按名称批量终止，也不使用端口反查。

## 慢启动

等待鉴权超过 60 秒仅显示「启动时间较长，仍在等待鉴权；可查看日志或手动停止」。不结束启动代次，不累计失败，不写停止哨兵，不触发看门狗重启。稍后收到鉴权链接仍可完成同一次启动，停止按钮仍可使用。

此外，失败重试标记加入当前 APK 安装时间。覆盖修复包后可重试一次此前失败；同一安装内失败、旋转或重新打开不会重复执行，已就绪环境不因此重建。

## 验证

- Android 16 独立 cache 夹具重现真实外部 PID 的 `EPERM`，维护屏障通过；原数据标记和外部进程保留。
- 验证同 UID 无关进程、复用 PID、活跃 Web、未知 `/proc` 读取错误及启动器仍存活的分支。
- 注入原 60 秒计时器的回调，验证只提示、保持启动、不累计失败、不终止进程，且晚到的就绪信号仍被接收。
- 实际 dsh 连续六次启动并停止通过，鉴权耗时 7.426 / 7.183 / 7.224 / 7.226 / 7.222 / 7.280 秒，均未触发自动备份。
- dsh、内置插件、预览与离线环境内容保持此前 alpha.2 版本；本次更新原生控制逻辑。
