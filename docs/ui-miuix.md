# DSHA Miuix UI 迁移（2026-10-17）

本轮按用户指定使用 `compose-miuix-ui/miuix` 更新原生界面，并在追加要求后继续按页面用途优化布局。它覆盖以前“原生界面无 Kotlin”的限制。本 PR 提交 UI 源码、构建配置和必要文档；正式 APK 不在本次发布范围。2026-10-19 用户反馈已完成独立安装版的实际测试并要求提交 PR，该反馈不代表所有设备和功能矩阵已验证。

## 概念和职责

- **Miuix**：用户指定的界面组件库，由上游维护并发布到 Maven Central；本项目固定依赖版本，使用其导航、卡片、按钮、设置项、开关和加载提示。它负责外观和交互，不运行 Ubuntu 或 DSH。
- **Compose**：Android 的声明式界面工具，由 Kotlin 编译器插件将界面函数编译成可更新的 UI。本项目通过 `MiuixView` 接入现有 Android View 树；它与 XML 控件的区别是根据显示状态重新绘制，而非逐个查找 TextView 改文字。
- **Activity / Fragment**：Android 的窗口与窗口内页面。既有 `MainActivity` 继续选择页面，`LaunchFragment` 继续执行启动和鉴权判断，`SettingsFragment` 继续处理设置操作。Compose 不另建一套导航历史。
- **显示状态**：`MiuixLaunch.Label` 保存文字与可见性，`Action` 在此基础上保存禁用态和按钮回调。这些对象由启动页视图创建，只供界面读取；与后台控制器的进程、鉴权和停止状态不同，不能自行判断服务就绪。
- **生命周期所有者**：由 Activity、Fragment 或弹窗向内部控件提供的“何时开始、何时销毁”信息。Compose 依此释放界面。AppCompat 从 1.6.1 升至 1.7.1，使原有弹窗也能承载 Compose 卡片；测试实际覆盖了 `CardSheet` 弹窗中的入口点击。
- **Insets（窗口安全边距）**：Android 提供的系统栏、挖孔、键盘占用尺寸。仍由已有 `ModernAndroidUi` 配置；Miuix 导航关闭自身默认的系统栏留白，避免重复计算。

## 实际迁移范围

| 界面 | 实现 |
| --- | --- |
| 底部导航 | `MiuixNavigation` 使用 Miuix `NavigationBar`，保存选中页；回调发生在提交选中态之前，以保留原通知、重复点击和页面切换顺序；补充无障碍选中态和键盘选择 |
| 启动首页 | `MiuixLaunch` 使用 Miuix 卡片、主次按钮、快捷入口和加载提示；保留运行状态、实际端口、环境状态、启动/进入、重启、停止、安全启动和恢复入口 |
| 设置页 | `MiuixSettings` 使用 Miuix 分组、入口和开关；安装、配置、数据、设备授权、语言、省电、悬浮条、更新、自检、关于均连接原处理函数 |
| 共用管理页 | `CardPage.card/entry` 使用 Miuix 卡片和入口；通过 `MiuixPanel` 为原 Java 表单绘制 Miuix 卡片，已有控件、输入值和回调继续有效；覆盖使用 CardPage 的模型、存储、备份、更新、配对、恢复等页面 |
| 明暗配色 | Miuix 与 Java 页面共用 `values/colors.xml` 和 `values-night/colors.xml`，不新增主题偏好；明确提供默认文字前景色，避免深色页标题变成黑字 |
| 其它复杂界面 | 本轮追加逐页优化覆盖插件、配置、数据、授权、安装恢复、终端、欢迎、更新诊断及虚拟屏控制；表单和终端保留原 Java/XML 控件，详见下方清单 |
| DSH 网页界面 | 本轮未迁移；它与 Android 原生界面是两套技术，既有移动插件版本保持不变 |

启动页动作流程仍是：点击 Miuix 按钮 → 调用 LaunchFragment 原监听器 → 由原控制器核验并执行 → 原刷新逻辑更新显示状态 → Compose 更新对应控件。创建、重绘界面不发起后台任务，旧请求与新运行代次的比较仍在 Java 逻辑中。

日志继续使用原 `LogScrollView` 和可选中的 TextView，保留独立滚动及“仅位于末尾时跟随”。页面本身可滚动，大字体下成对按钮改为上下排列；不要求短屏同时显示所有内容。

## 逐页专项优化

### 共用展示组件

- `MiuixPanel` 是本项目创建的卡片容器，由 XML 页面或 `MiuixUi.card` 创建。它用真实 Miuix `Card` 绘制背景，原输入框、按钮、列表和监听器仍直接保留在 Android 控件树中。它与首页的纯 Compose 界面不同，不复制 Java 表单状态，也不等到 Compose 第一次绘制后才提供 `findViewById` 查找。背景不参与内容高度计算，避免短卡片被撑满整屏；隐藏原表单时，卡片高度也归零。
- `PageColumn` 是本项目创建的纵向正文容器，由阅读页和表单页使用。它按可用宽度计算两侧留白，在宽屏将正文有效宽度限制为 720dp；不改变网页、终端或预览画布的内部坐标。dp 是 Android 按设备密度换算的布局单位，与随用户字体设置缩放的 sp 不同。
- `ActionRow` 是本项目创建的操作排列容器。它按按钮文字实际需要的宽度决定横排或纵排；系统字体超过 1.3 倍时采用纵排。它只调整尺寸和排列，不改变按钮禁用状态或原点击处理。
- `CardPage` 继续由各 Java 页面创建。长值改为“上方标签、下方可复制完整值”，避免路径和版本号挤掉标签；操作区与正文处于同一滚动区域，防止短屏上多个长按钮占满固定页脚。选择和确认弹窗同样受窗口高度限制，关闭按钮可以滚动到。

## 独立体验版构建

`personal` 是新增的 Gradle 构建类型，负责选择签名、包名与调试标志；它与选择最低 Android 系统版本的 Standard / Low 产品类型不同。它继承 release 配置，使用 `.miuix` 包名后缀与 `-miuix` 版本名后缀，使用本机 Android 签名并明确关闭调试。

应用名 **DSHA Miuix**，完整包名 `com.dsh.client.miuix`，Android 为其分配独立数据目录。原 `com.dsh.client` 可以保留；该构建不自动导入原版数据或授权。后续覆盖独立版需要相同的本机签名。正式版继续要求原包名、E7E3 历史签名与完整资产证明。

```bash
./gradlew :app:assembleStandardPersonal
```

完整打包需要按 BUILD.md 准备并核验离线资产、当前原生二进制和运行时描述符。运行时描述符是由项目构建工具生成的资产与启动器摘要清单，用于核验安装的受管组件；它与 APK 版本号不同，不能用界面编译成功替代该清单的实际核验。本 PR 不上传本机恢复的归档、签名文件或安装记录。

Compose 引入的 `libandroidx.graphics.path.so` 来自固定依赖 `androidx.graphics:graphics-path:1.0.1`，依赖归档摘要受 Gradle 验证元数据约束。本 PR 将该 AAR 与 ARM64 成员的大小、摘要和适用版本纳入既有原生 APK 门禁；在现有测试文件补充缺失、字节被修改、AAR 被替换及锁记录丢失的检查，相关 18 项通过。第三方声明的生成与校验也已同步，相关 6 项通过。
