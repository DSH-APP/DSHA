# 议题、PR与证据流转

核验日期：2026-10-21。参考基线：已发布 F10 `087724c`；本页为F11新建流程说明，不代表恢复了旧流程原件，也不证明任何仓库权限、标签或保护规则已经配置。

## 从当前授权和真实状态开始

先确认用户指定的仓库、分支、开放条目与本轮目标，再读取对应issue/PR的当前内容、提交和讨论。当前维护只处理仍开放且在授权范围内的条目；已关闭条目不追做，插件收录跳过。不要把历史报告中的条目状态、另一个仓库或旧会话需求复制成新任务。

当前应用的私有预发布与历史原仓库分别由[README](../../README.md)说明，仓库名称不是写入授权。可用时用已有GitHub连接或`gh`读取；只读查阅、代码修改、发评论、开PR与发布是不同动作，发送对外消息须有相应授权。没有访问权限时保留本地可复核材料，不上传凭据/设备原日志来补证。

## 一条问题需要保留什么

1. 用户可观察的触发与期望、当前源码/APK/平台身份，最小复现与实际结果。
2. 真实生产调用链、失败层和数据/执行状态。UNKNOWN、超时和取消不能改写成“未执行”。
3. 修复范围、回归场景和未验范围；旧文档错误、实现缺陷、设计选择、验证不足分开。
4. 提交/PR、测试回执和产物摘要的对应关系；历史证据按原时间归属保留。

issue可作为需求/复现/依赖的讨论入口，PR作为具体变更与审阅入口。PR中的实测或修复线索可用作证据，但不能把未合并代码当作当前生产事实。子问题或依赖关系只在平台实际支持、用户授权和目标明确时设置，不在正文伪造已生效的原生依赖。

## 完成与交接

写清最终行为、修改文件、已跑检查及限制，再按授权更新对应状态；代码通过不自动代表设备通过或Release已上传。不能仅靠本地分支名、预备清单或草稿PR宣称用户可下载。当前未授权发布时交付本地可审阅结果。

常用判断词见[分诊标签](triage-labels.md)，领域边界见[接手领域](domain.md)，跨版本文档补齐结果见[缺口矩阵](../documentation-gap-matrix.md)。
