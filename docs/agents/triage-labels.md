# 分诊用语与标签边界

核验日期：2026-10-21。参考基线：已发布 F10 `087724c`；F11新建说明，不宣称以下标签已在远端创建、使用或获得写入授权。

以下五个名称用于解释分诊意图；实际更新前先读取目标仓库已有标签和用户要求，不擅自创建、重命名或批量改状态。

| 名称 | 含义 | 退出条件 |
|---|---|---|
| `needs-triage` | 还未确认范围、事实层或优先级 | 取得可复核触发/范围并完成初步归类 |
| `needs-info` | 缺少决定问题所必需的信息 | 得到指定信息；已能独立推进的工作继续处理 |
| `ready-for-agent` | 范围、授权、输入和可接受结果足以自动处理 | 产出修改及验证，交审阅或完成对应授权动作 |
| `ready-for-human` | 需要用户/维护者决策、权限或实际设备参与 | 明确列出具体阻塞和所需选择，不用模糊“请确认”替代已能完成的工作 |
| `wontfix` | 经明确决定不在当前产品范围或不采用该方案 | 记录理由和决定来源；不把无法复现/缺资料等同不会修 |

标签不替代事实分类。文档缺口直接补正文/链接；设计已变更则同步现行说明；实现缺陷须有明确承诺及调用证据；验证不足写出缺少哪项输入/运行证明。HMR字段、旧设备日志、静态未搜到调用等不能仅凭标签裁成成功或失效。

状态也不替代执行证明。`ready-for-agent`不是发布/发消息授权，`ready-for-human`不阻止先完成可审阅材料，`wontfix`不允许删除用户原件。分诊和收尾按[议题流程](issue-tracker.md)及[AGENTS](../../AGENTS.md)执行。
