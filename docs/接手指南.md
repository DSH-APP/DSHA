## 运行结构

APK 把完整 Ubuntu 基础环境解压到应用私有目录，在 proot/proroot 中运行 Node 24、锁定 pnpm 和 `@deepseek-ai/dsh` **0.2.0-rc.2**。Java 17、Material3、单模块 `:app`；没有 Kotlin。两版仅 arm64、共享 `com.dsh.client`：Standard 最低 API 30，使用系统 WebView；Low 最低 API 23，额外提供 Gecko 143。

Web 首选端口为 3080，实际端口由本轮官方启动信息确认；被占用时可以使用备用或动态端口。3090 是宿主能力桥，3081 是 LAN 入口。鉴权、保活和 LAN 都使用实际 Web 端口，不能按端口推测 PID。完整职责和状态归属见 [模块图](module-map.md)，决策边界见 [ADR 0001](adr/0001-build154-boundaries.md)。

`HarnessController` 负责唯一的生产启动代次和停止意图；启动、输出、退出、冷安装和平台操作由实际协作者执行。界面显示状态、发起操作，不以成功文案替代就绪检查。终端和 Web 跨页面、旋转与语言切换保持各自生命周期。

## 找到权威输入

| 内容 | 入口 |
|---|---|
| 工具链与构建参数 | [BUILD](../BUILD.md)、`ci/toolchain.lock.json`、`app/build.gradle` |
| DSH 版本和依赖内容 | `tools/dsh-runtime/package.json` 与 `package-lock.json` |
| 内置插件和运行期补丁 | `builtin-plugins.json`、`runtime-patches.json` |
| APK 资产成员与动态读取契约 | `tools/asset-deployment.json`、`tools/verify-asset-deployment.py` |
| 受管内容与生成器输入 | `managed-runtime-inputs.json`、生成的运行时描述符 |
| 独立应急归档 | `tools/recovery-runtime/lock.json` |
| 宿主测试入口 | `tools/host-tests.manifest.json` |
| 历史发布证书 | `ci/release-identity.json` |

基础 Ubuntu 版本保持独立身份，不能因普通 DSH 更新或 UI 更新而递增。`offline-rootfs.bin` 与 `dsh-runtime.bin` 使用 `split-runtime-v1`，冷安装读取两份，受管更新读取 DSH 覆盖层；不要把同一份大归档重复打包。离线归档和大型生成物不提交，生成和核验顺序以 CONTRIBUTING、BUILD 及当前 CI 工具为准。

资产生成采用显式部署清单。完整许可、内置插件和扩展目录保留动态成员；源归档转换为包内 `.bin` 时用明确映射。新增文件先登记用途与读取入口，不能仅靠字符串正则裁掉许可、Worker 或动态资源。`tools/history` 保存原字节，不参与 APK 部署，也不能被自动测试发现器重新激活。

## 修改后的验证

源码快速层不需要手机、模型凭据、发布密钥或完整离线环境：

```bash
python3 tools/run-host-tests.py --check-manifest
python3 tools/run-host-tests.py --stage fast
python3 tools/check-source-hygiene.py
```

Java 纯逻辑使用 JUnit。PR 源码检查可以生成当前资源和运行两版 JVM 测试；这是编译与 JVM 验证，不是生成或安装审计 APK。完整输入准备后运行：

```bash
./gradlew :app:testStandardDebugUnitTest :app:testLowDebugUnitTest \
  :app:lintStandardRelease :app:lintLowRelease
python3 tools/run-host-tests.py --stage runtime
python3 tools/verify-stability.py --stage software
```

缺少 AGP/aapt2 的宿主可用 `tools/run-unit-tests.py` 作为明确的后备。它需要实际依赖缓存及当前 R，不代替完整 Android 构建。Windows 设置 `DSHA_PYTHON` 指向真实 Python；避免由系统别名启动不可用的 `python3`。纯资源或源码验证若跳过归档生成器，报告必须列出跳过项，不能写成完整交付门禁通过。

运行时夹具先核版本、源输入、模块字节和宿主平台；行为回归使用真实锁定 DSH 或隔离文件系统。新增纯逻辑放在无 Android 依赖的 `util`，配独立断言。源码检查、宿主行为、Android 设备和外部模型请求分别记录。不要把测试未运行、平台跳过或只有字段存在写成通过。

## 数据、插件与恢复

宿主 v5 维护会话、附件、配置、用户插件和个人项目。新用户导出固定为无需密码的 `DSHA-data-v5-<UUID>.tar.gz`，没有新加密开关；内部自动副本仍受本机密钥保护，默认开启计划。历史加密原件仍需原密码并核验完整认证。本机副本和密钥不提供卸载存续保证，交付界面应引导导出。

用户禁用和安全模式意图优先保留。链接、本地包和更新检查真实格式、路径、依赖锁、目录摘要与事务后自动提交启用；正式插件允许未锁定重解析、生命周期脚本、pnpmfile 和修复 shell。不能复活旧审阅门槛，也不能将“作者声明”改写为本机完整依赖验证。

受管系统插件与用户数据分层，系统字节由当前 APK 的精确证明重建。宿主仍读取受支持的旧归档、配置快照和数据格式；退休 Python 工具的历史夹具留在 `tools/history`，其退出 APK 不代表可以删除旧数据读取代码。

停止和提交要求本次出生身份、会话与退出证据。数据维护先关闭 PTY 和简易终端，再取得既有屏障；未知结果保留原件、锁和现场。不按裸 PID、端口或名字强杀，不通过清数据逃避停止屏障。事务失败和取消不能自动换通道重放写入。

独立应急使用自己的运行根、HOME 和 workspace，不依赖正式 rootfs。五项工具受控，修复写入仍需原生确认；无模型凭据时先诊断，对话再填临时密钥。正式终端开放不改变应急写入或未知进程的约束。

## 正式产物与证据

正式 APK 使用原包名、E7E3 历史证书、递增版本码、`debuggable=false` 与 v1/v2/v3。口令必须显式提供，不能用临时、A3 或 debug 证书替代。

```bash
./gradlew :app:assembleStandardRelease :app:assembleLowRelease
```

完成对应的软件、资产、插件、应急、ELF 和签名门禁后，使用固定 `release/dsha-0.2.0-rc2.apk`、`dsha-0.2.0-rc2low.apk` 及 `.apk.sha256`；同版本同 flavor 替换，其他历史版本保留。源码快照与检查记录绑定最终字节。

本轮不操作手机、不生成额外调试或审计 APK、不在正式数据注入故障。未来获得对应设备验收授权时，只用同签名正式包覆盖安装，保留用户数据。Android 6/7、真实 16 KiB、FUSE、厂商 `/proc` 限制和外部模型服务只能按真实证据说明。

当前 CI 的源码、未签名完整包与受保护签名发布是分离入口。工作流文件存在不代表线上已经运行或发布成功；未签名包用于软件检查，不能用于手机安装或放入 release。未经明确要求，不上传 GitHub、不部署网站。
