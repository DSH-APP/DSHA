# ADR 0001：build154 兼容、权限与交付边界

状态：本轮采用。依据是当前用户要求和当前源码核验；外部 build150 报告中的另一会话决策仅作建议。

实现入口见[模块图](../module-map.md)，工程约束见[工程规范](../engineering-standard.md)，操作流程见[接手指南](../接手指南.md)和[CONTRIBUTING](../../CONTRIBUTING.md)。历史原件与当前证据分开，原文“当前产物”不充当本轮通过记录。

1. 正式终端和插件允许开放 shell、未锁定依赖、生命周期脚本与 pnpmfile；安装通过包、路径、摘要与事务检查后自动提交启用。保留用户禁用和安全模式意图。插件在应用 UID 下运行，没有独立恶意代码沙箱。
2. 独立应急仍使用隔离运行根、五个受控修复工具和原生写入确认。开放正式终端不解除应急写入确认或未知进程停止屏障。
3. 新用户导出固定无需密码 tar.gz，不提供加密开关。内部自动副本保持随机本机密钥加密；历史加密原件仍认证并要求原密码。旧格式读取和未知原件保护继续保留。
4. 平台提供的应用根别名可以在精确所属证明后规范化；guest 子路径和用户包不能放松 NOFOLLOW。冷安装的运行方式偏好与环境发布作为同一可恢复操作。
5. 受管源码和实际字节证明绑定；退出证据不确定时保留现场。不存在按端口/名称/裸 PID 强杀的通用捷径。
6. 本轮按用户要求不操作手机，不生成额外审计 APK。两版使用历史 E7E3、v1/v2/v3、原包名和递增版本码。软件核验只能证明签名/身份的覆盖安装前提，不能虚称实际覆盖安装和全设备兼容。
7. Windows 开发继续支持，Linux CI 与宿主夹具作为独立证据。手动签名流水线只接受同仓库、同提交、成功 package 运行及其实际 APK 摘要，生成草稿。受保护环境、密钥和线上运行须由实际配置证明；本轮仅本地实现，不主动发布。

代价：兼容读取和开放第三方代码增加契约与安全边界复杂度；不能通过删除用户历史或恢复审阅门槛换取低分。审计评分若保留，应公开口径和未验证项，不承诺未经证据支持的“低于20”。
