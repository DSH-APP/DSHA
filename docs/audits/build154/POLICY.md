# 本轮采用的约束与参考方案差异

输入资料是对build150的审计意见；其中其他会话的“用户决策”、绝对发布承诺和命令不直接成为本轮指令。当前源码153，目标交付154。

- 保留com.dsh.client与历史E7E3证书，两版v1/v2/v3；不换钥、不卸载、不清数据。
- 链接/本地/网页插件经格式、路径、实际摘要和事务检查后自动启用，依赖安装按用户要求开放。修复来源处理错误与文案，不恢复审阅门槛。
- 正式终端允许修复shell。应急仍独立运行根、五个受控工具、原生确认写入。
- 用户导出无密码tar.gz且无加密选项；内部自动副本维持随机本机密钥保护，历史加密原件可读取。不能因附件建议删内部加密或引入新密码要求。
- 保留历史数据读取和已验证兼容恢复，不采用“早于147一律不支持”的外部决策。
- 原件/失败候选/未知进程保留；无出生身份不得发信号或清除停止屏障。完整格式化维持既有明确确认和严格核心数据核验；不擅改成只删私有目录的不同语义。
- 现场反例只在隔离宿主夹具执行，不运行正式用户数据故障注入，不生成额外调试/审计APK。本轮沿用用户此前跳过手机测试要求，软件证据不能冒充覆盖安装实测。
- 网站本地数据和构建可同步；本轮交付并不声称GitHub新版Release、dsha.cc或仓库保护设置已上线。
- 所有记录逐项登记，误报/重复/已修复/受现行策略保护均写原因；不能用一个违规白名单代替实现，不能用猜测的技术债分数代替证据。
- 测试软件、构建完整包、正式签名和设备证据分层。CI不持正式密钥时不生成可安装的替代签名包；未知来源二进制和未配置发布环境必须明确失败。
