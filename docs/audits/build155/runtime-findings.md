# build155 runtime findings (working record)

- `ProotBootstrap` still combines command execution with environment readiness, managed asset markers, cold extraction, offline package installation and recovery maintenance. The cold path owns transaction publication and stop checks; extracting it must preserve `ColdInstallTransaction` candidate ownership, `RuntimeHostPorts` selection rollback, `BoundedGuestSessions` and `RuntimeWorkPort` retention on unknown exit.
- `InstallProcess.read` and `BoundedProcessRunner.collect` duplicate a 10 ms `available()`/read/exit poll. Their result contracts differ: install reports lines and throws for timeout/cancellation; bounded commands return a result with head, tail, truncation and timedOut. A shared poll primitive can remove the duplicated pipe race without collapsing those contracts.
- `IsolatedInstallProcess.exitValue` represents *guest session* completion, not only supervisor exit. A shared output collector must continue to query this wrapper and leave its identity-aware close path intact. Closing streams cannot stand in for process or guest exit.

Implemented: `ColdBundleTransaction` owns cold recovery, candidate creation, publication and rollback; `ColdBundleExtractor` owns signed archive extraction and candidate preparation; `ColdToolsInstaller` owns the frozen package slot, runtime probing, bounded command work lock and unknown-exit retention. `ProotBootstrap` retains its public methods and the shared launcher. `ProcessPipePoller` now owns the common available-byte/exit/final-tail/deadline loop used by both readers. The separate caller contracts remain intact. `IsolatedInstallProcess` still supplies the identity-aware guest exit result and group cleanup; no bare-PID or stream-close shortcut was introduced.

Validation: 19 focused JUnit tests passed in a standalone Java 17 harness using the repository's actual process classes; one new case confirms that a finished supervisor does not imply an unknown guest has exited. The four runtime sources compiled against both Standard and Low debug class outputs and SDK 37. Full Gradle unit tests remain blocked by concurrent `HarnessController` / debug audit compilation errors and an unrefreshed runtime descriptor input gate. No APK or device operation was run.

Residual architecture: plugin commands, data maintenance and PTY entrypoints still retain implementation inside `ProotBootstrap`. This pass materially thins its cold-install surface but does not claim every legacy path is a thin facade yet.
