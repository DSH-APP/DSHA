# build155：继续修复的范围与完成条件

本轮继承 build154 的 236 项台账，只处理可核对的当前源码问题，不把现场或来源未知改写为通过。子任务的具体问题在 `bridge-findings.md`、`runtime-findings.md`、`compat-findings.md` 中先记录后修订。

主要修订：HTTP 桥显式路由；运行环境薄门面与共用进程输出收集；浏览器回退、重复测试夹具和退休导航入口；应用范围的 Web 状态归属；当前项目 Java 源码格式化。默认无密码导出、内部自动加密备份、历史读取、开放插件与正式终端、未知退出停止屏障、独立应急根和历史 E7E3 签名均为保持的契约。

根代理发现：生产调用已使用 `HarnessController.get`，控制器仍把生命周期、队列、运行记录、诊断及停止结果散列为静态字段。重复创建控制器会重绑健康回调。`MainActivity.current` 只有声明和自赋值，没有生产读取者，却强引用页面。LAN 地址判断把所有 `172.*` 都当作私网。本轮将状态归到应用范围的单一拥有者，保留公开构造器在真实应用范围共享状态，隔离的测试 Context 使用独立状态；删除无用页面引用；精确检查 LAN 私网范围。

历史归档读取及尚不可证明关闭的记录继续保留，不能为了消除技术债把旧数据保护路径删掉。厂商 Root/Shizuku、Android 6/7、真实虚拟屏与后台生命周期、掉电、来源授权及失真的历史 SHA 仍须如实注明边界。若当前 Linux 宿主只读，核验可以换到隔离的可写宿主夹具，不修复或重启用户 WSL 服务。

所有源码协作者完成并冻结后，统一更新版本、生成受管描述符、两 flavor 完整单测与 Release Lint、正式 APK/ELF/插件/应急门禁，最后替换 `release` 中常规 APK 与校验文件并生成源码快照、逐项台账和报告。本轮不操作手机，不上传 GitHub 或部署网站。出现新失败时只修复真实原因并运行有关检查；完成本地交付后停止，不重复循环审计。
