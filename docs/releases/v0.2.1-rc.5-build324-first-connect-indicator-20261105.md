# build324 DSH 0.2.2 首次进入连接提示静默（2026-11-05）

本记录只说明 T58 的首次连接提示修复与本地软件验证（并入 build324，与 T54 的 user-only 技能审批同批发布），不替代 build323 的 S1 升级验收，也不代表已完成真机确认。

## 现象

DSH `0.2.2-rc.1` 首次进入页面时（页面挂载时会话仍处于 `connecting`），设置面板脚部先显示黄色「重新连接中」，随后显示绿色「已连接」。用户已确认这是首次进入的一次性显示、不是真实断线，但要求修掉。

目标行为：

- 首次进入页面（本页面从未连接成功过）不显示黄色 connecting 与绿色 recovered 提示。
- 曾经连接成功过之后，真实断开再恢复仍然显示黄 → 绿；设置面板重新挂载不应让真实重连提示再次静默。

## 根因

`@deepseek-ai/dsh-client-ui-settings-general/lib/client.js` 的 `SettingsRoot`（0.2.2-rc.1）：

- `previousConnectionState` 以挂载时的 `connectionState` 初始化；页面挂载时仍是 `connecting`，首次 `connected` 的 previous 即 `connecting`，命中 `showRecovery` 条件并显示绿色。
- `connecting` 状态无条件选择黄色胶囊；同时 `CONNECTING_MIN_VISIBLE_MS = 800` 的最短可见计时会把首连后的黄色继续保留到绿色之前。

## 补丁

新增受管补丁 [`first-connect-indicator-patch.json`](../../app/src/main/assets/first-connect-indicator-patch.json)（5 个逐字节锚点，标记 `DSHA_FIRST_CONNECT_SILENT_V1`），只修改上述模块：

- 模块级 `hasConnectedOnceInPage` 记录本页面是否已连上；每次挂载用 `firstConnectPending` ref 标记首个连接是否静默。
- 首次成功连接前，`dshaConnectionIndicator` 不返回 `connecting` / `recovered`；真实 `disconnected` 红色提示保留。
- 被静默的首次连接不记录 `CONNECTING_MIN_VISIBLE_MS` 计时，避免绿色前仍闪黄。
- 连接提示迁移抽成 `dshaAdvanceFirstConnect`；曾连上过之后的真实断开恢复仍返回黄 → 绿，跨设置面板重新挂载保留。
- `RECOVERY_CONFIRMATION_MS = 2e3` 与 `CONNECTING_MIN_VISIBLE_MS = 800` 未改。

登记与生成物：`runtime-patches.json` active（module / marker）、`managed-runtime-inputs.json` assetFiles、`tools/asset-deployment.json` packagedFiles；`dsh-runtime.bin`（不提交）按新补丁重建，`dsh-runtime.inputs.json`、`runtime-descriptor.json`、`managed-package-proofs.json` 随之重算。build324 同时包含 T54 的 `user-only-skill-approval-patch.json`，两条补丁在同一棵树上重建同一个运行时归档。
