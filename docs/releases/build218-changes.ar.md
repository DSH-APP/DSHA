# DSHA 0.2.1-rc.3-20261031.1800-dsh0.2.1-rc.5 / build218

- أُعيد بناء الدليل الأولي على أربع خطوات (ترحيب ← غرض ← أذونات ← إتمام) بدل ثلاث صفحات ViewPager2 وصفحة تحضير منفصلة. عند `welcomed == false` يبقى الدخول إلى الدليل فقط، ويتحقق Main واستعادة بدء التشغيل من العقد نفسه.
- أصبح النشر الأول مهمة صيانة خلفية على مستوى التطبيق، ويُعرض التقدم في كبسولة النشر على صفحة الدليل وفي الشريط العلوي لـ Main بدل انتظار ملء الشاشة. تبقى الشاشة مضاءة أثناء النشر، ولا تظهر صفحة الإتمام وبدء Web مرة واحدة إلا بعد النجاح. إذا توقف النشر داخل الدليل في الخلفية، يعود الدليل إلى خطوته السابقة (`welcomed` يُكتب فقط عند مغادرة الدليل إلى Main).
- يعود التحديث فوق الإصدار إلى صفحة صيانة بيئة التشغيل بملء الشاشة بالتنسيق الجديد (شريط المراحل وقائمة المراحل والإجراءات السفلية) بدل Main محدود مع نافذة حوار. إذا وُجدت على القرص معاملة صيانة غير مكتملة أو موقع تجربة معزولة غير مغلق، تنتقل صفحة الصيانة واللوحة والبدء التلقائي أولًا إلى «استئناف الصيانة المتقطعة» (التأكد من خروج عملية التجربة القديمة ثم إغلاق الموقع) بدل بدء تحديث محكوم عليه بالفشل بـ `TRIAL_RECOVERY_REQUIRED`. لا يزال البدء التلقائي يجرّب المرشح نفسه مرة واحدة فقط؛ ولا يُفتح Main المحدود إلا عندما يختار المستخدم صراحة «الدخول إلى الواجهة المحدودة»، ولا يكتب علامة جاهزية، لذلك تظل الطرفية وWeb والإضافات تمر عبر بوابات البيئة.
- أُضيفت بطاقات أذونات لسبع قدرات جهاز مع ADB، تُرتَّب حسب الغرض ويمكن تخطيها. يُطلب إذن الإشعارات بالنقر في Android 13+، ويُفحص تحسين البطارية للقراءة فقط دون طلب استثناء؛ ويُتعرَّف على مدير Stellar (`roro.stellar.manager`) ويمكن فتحه؛ ونُقِّص نص إعدادات إمكانية الوصول إلى الاسم الفعلي في قائمة النظام.
- الأجهزة اللوحية عند 600dp فأكثر تستخدم عمودين، ويُضغط رأس وتذييل الشاشة في الوضع الأفقي للهاتف، ويمكن تمرير المحتوى بخط 1.3×. رُفع versionCode إلى 218؛ وتبقى مراجعة DSHA 0.2.1-rc.3 وDSH المضمّن 0.2.1-rc.5؛ ولم يُتحقق في هذه الجولة من التثبيت فوق الإصدار على جهاز حقيقي، ويتبع نطاق البناء والقبول هذا الـ CI run وإيصال Release.
