# DSHA 0.2.1-rc.5-20261109.1400-dsh0.2.2-rc.1 / build349

- Plugin-card "config / current Web" status pills are now visible again (`93af9944d`): the small pill background used `shell_*_soft` (8% opacity), which was nearly invisible on the white card and looked like a text-only color change; it now uses an 18% fill of the same hue (`BADGE_FILL_ALPHA = 0x2E`, composited from `toneColor`), neutral keeps `shell_raised`, and the restart-todo warning chip is deepened to match. Display only: pill tone mapping and state decisions are unchanged.
- First-screen pill copy is trimmed to ≤4 characters: the config side keeps only a conclusion word (enabled / disabled / can enable / missing / error / temporary / working), and the current-Web side only loaded / loading / failed / waiting / not loaded / unverified; the full state and load history move into `contentDescription` for accessibility instead of filling the pill.
- Note banners no longer flicker: the rebuild signature drops `System.identityHashCode`. Every list refresh produces new Items, so the old signature changed and rebuilt the banner, making the update / last-operation notes flicker side by side; the signature now covers only note content, language, version and operation records, so an unchanged banner is not rebuilt.
- The managed runtime descriptor is unchanged (still `5fec6de5`): this batch only touches the `PluginFragment` display layer and `PluginFragmentRenderingTest`, `runtime-descriptor` launcher sources are unchanged; fixed inputs stay frozen at the locked 20261105e and the bundled `dsh-web-mobile` stays upstream 3.3.1 and default-enabled.
- Version and scope: versionCode raised to 349 (based on the released build348 / `2045b61d6`); the DSHA revision stays `0.2.1-rc.5` with bundled DSH `0.2.2-rc.1`. This batch contains only the UI fix above and does not change plugin state decisions, the device shell allowlist or relax execution-time guards. build348 is already released as a formal package (tag `dsha-a-su-build348-20261109-110000`).
- **Not verified / not accepted**: no device acceptance yet: visibility and contrast of the 18% fill under day-night / narrow screens / 1.3× font / RTL; whether ≤4-character copy is truncated next to progress text such as "working 42%"; wrapping of the short copy at COMPACT density; TalkBack reading of `contentDescription`; whether note banners truly stop flickering on list refresh. **build349 is not yet device-validated**: acceptance is a first 348→349 overwrite that succeeds, data intact, READY, an unchanged managed-runtime descriptor and the four behaviours above on device; build344–build349 formal-package overwrite acceptance is still pending with the user, and device acceptance of the released build338–build348 follows their own records.
