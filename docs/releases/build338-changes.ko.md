# DSHA 0.2.1-rc.5-20261108.0030-dsh0.2.2-rc.1 / build338

- 페이지 유지 K0–K2 (T110, `ba13ed5f` / `02e187e0`): Web 호스트 페이지가 같은 작업 안에서 네이티브 설정 / 터미널 / 플러그인 페이지로 전환될 때 WebView 문서를 더 이상 파괴하지 않는다. 돌아올 때 같은 generation / instance 로 원래 페이지를 인계하며 `loadUrl` 을 다시 호출하지 않는다. 새 `BrowserPageKeeper` 는 페이지 소유권을 애플리케이션 범위로 올리고, `onDestroy` 를 구성 변경 / 정상 종료 / 시스템 회수 세 갈래로 처리한다. 중지, 유지보수, Web 프로세스 교체, renderer 종료, origin-restore, 작업 제거, 저메모리 trim 은 명시적으로 퇴역시켜 실제 중지가 유지 기능에 가려지지 않게 한다. K0 는 익명화 진단 `WEB_ENGINE` / `WEB_PAGE_DESTROY` / `WEB_KEEPALIVE_ATTACH|DETACH|RETIRE` 를 추가한다(사유 코드 허용 목록만, URL·cookie·페이지 제목은 기록하지 않음).
- 앱 내 왕복에서 재연결 없음, 전체 페이지 재렌더링 없음 (T110 / K5 시나리오 1, `b80d8225` / `7f13f06f`): Web 으로 돌아오면 호스트가 `dsha-browser-resume` 을 보내고, 관리 대상 `app-integration/client.js` 가 읽기 전용 `session.control` 스트림 하나로 현재 carrier 를 먼저 탐색한다. 프레임이 반환되면 Connection 을 유지하고 Remote 기준선을 재구축하지 않아, 긴 페이지도 전체 재렌더링이나 긴 로딩 정체가 없다. 탐색이 시간 초과해도 Connection 이 여전히 `connected` 이면 재설정하지 않는다(진짜 죽은 carrier 는 서버 하트비트 / socket close 에 맡긴다). Connection 이 끊겼거나 탐색 기능이 없으면 기존 동작으로 돌아간다. 익명화 `WEB_PAGE_RESUME` 진단(impl / trigger / state / probe / reset / hiddenMs / inApp)을 추가해 향후 회귀 분석에 대비한다.
- K5 실기기 영수증: 시나리오 1(스트리밍 긴 페이지의 앱 내 왕복)은 LENOVO TB321FU / Android 16 / WebView 140 에서 사용자 실측으로 통과했다——노랑→초록 재연결이 사라지고, 스트리밍 출력이 전체 페이지를 다시 불러오지 않으며, 긴 로딩 정체도 없고, 초안은 유지된다. 검증 패키지는 2차 진단 테스트 패키지 `3d3866f7`(이번 병합과 동일한 수정 내용, 패키지 `io.github.sunsetrne.dsha.test`)이다. 나머지 시나리오(2–13: Home / 앱 전환, 시스템 회수, 프로세스 사망, 회전과 다크 / 언어 / 글꼴, PiP, 중지 / 유지보수 / 백업, origin-restore, renderer, 다중 창, 업로드·다운로드·마이크, 로그 익명화)와 두 번째 기기 / 두 번째 WebView 는 실행하지 않았으며, 사용자 결정에 따라 실험적으로 선언하고 병합을 막지 않는다.
- 실제 화면 가림 판정 수정 (`bfe82527`): `MainScreenWindowPolicy` 가 먼저 display 0 에서 대상보다 높은 layer 이며 교차하는 cover 를 모은 뒤 각 변의 최대 잘라내기 양으로 일괄 계산하므로, 결과가 창 목록 순서·layer 에 의존하지 않는다. 시스템 장식과 IME 의 가장자리 판정에 2px 허용과 "가장자리 따라 ≥80% 덮음" 규칙을 더하고, 덮음이 부족해도 안쪽으로 대상 수직 방향 1/4 이내만 들어오는 가장자리 띠·작은 오버레이는 그 변에서 잘라낸다. 내부 덮음은 기존대로 창 전체 좌표를 거부하며 부분 가림 상태를 새로 도입하지 않는다. 영역 0·역방향·null bounds 는 기하학적으로 픽셀을 덮지 않으므로 건너뛴다(P2). ZUI 실기기 형태(중앙 taskbar + 가장자리 게임 오버레이)는 전체 거부에서 잘라내기로 바뀐다. 플로팅 IME·분할 화면·PiP 와 ZUI/vivo 실기기 재검증은 하지 않았다.
