## 一、决策

2026-11-05 用户批准暂时默认禁用；同日经主会话转达更严格口径（原文）：

> 竖屏适配插件没有回归修复之前，默认禁用，以相关文档为准，覆盖更新也禁用。只有明确回归之后
> 才能默认启用。

执行范围：

- **全新安装**：默认禁用；
- **覆盖更新后同样禁用**（不保留旧版本「已启用」状态）；
- 只有用户**在当前安装里**从原生「插件」页显式重新启用才生效；该启用跨 Web 重启保持，但
  **下一次 APK 覆盖更新会再次收敛为禁用**；
- 用户显式禁用始终优先。

## 二、为什么禁用（要保留的原因记录）

1. **适配面与宿主变化脱节**：build324 起宿主新增或改动了主界面、维护页、首次连接提示、
   技能调用确认、插件页、设置项、会话与侧栏导航等页面和逻辑；插件侧大量渲染代码没有同步
   做竖屏适配。
2. **已发生用户可见事故**：build324 覆盖安装后主界面白屏 + 侧栏 footer 重复。插件用
   `:has()` 依赖宿主 `ConnectionIndicator` 是否存在，宿主改变首连渲染方式后整条渲染链失效；
   禁用插件后白屏与重复都消失。
3. **修复只覆盖了一处契约**：build325 的 `DSHA_GEAR_FIT_V1` 只把齿轮让位改为实测宽度，
   同类「依赖宿主结构」的隐患仍在。
4. **风险控制**：在新页面 / 新逻辑的竖屏适配补齐并验证前，全新安装与覆盖更新都收敛为禁用，
   先保证主界面与维护流程可用；恢复默认启用需要回归修复与真机证据。

## 三、实现（最小默认值改点 + 覆盖安装代次迁移）

现有机制保持不变（未新增第二套启停开关）：

- `app/src/main/assets/builtin-plugins.json` 是内置插件注册事实源；
- `app/src/main/assets/register-builtin-plugins.py` 在 Web 启动前把未禁用的内置插件并进
  `dsh.profile.bundles`，`profiles/web/node_modules/<name>.disabled` 标记表示禁用意图；
- 原生插件页 `enable-state` / `disable-state` → `plugin-manager.py` →
  `register-builtin-plugins.py --enable/--disable`，仍是唯一启停入口。

本版改动：

1. `builtin-plugins.json` 的 `dsh-web-mobile` 行新增 `"defaultDisabled": true`；注册器读取同一
   字段派生 `DEFAULT_DISABLED`，并校验字段类型（`BUILTIN_REGISTRY_DEFAULT`）。
2. `register-builtin-plugins.py` 新增默认禁用收敛与安装代次记录：
   - `apply_default_disabled()`：没有「本安装代次显式启用」记录时，写与原生禁用一致的空
     `.disabled` 标记（插件随后移出 `bundles`、不建立 `node_modules` 入口）。全新安装、旧版本
     启用过、上一代次显式启用过，都会走到这里；
   - `.enabled` 记录：原生启用时写 `DSHA_DEFAULT_OFF_ENABLED_V1\n<安装代次>\n`；显式禁用或
     收敛禁用时清除。当前代次匹配才保持启用；
   - `apk_generation()`：优先读宿主写的 `/usr/local/share/dsha/apk-generation`；标记缺失时
     回退受管资产身份，便于本地测试/手工运行，同时不让空串让旧启用意外延续。
3. 宿主写入安装代次：`RuntimeTools` 在插件注册前写当前 `versionCode`；纯逻辑
   `util/ApkGeneration.java` 生成稳定 ASCII 标记，配 `ApkGenerationTest` 单测（不依赖 Android）。
4. 未改 `app/src/main/assets/builtin-plugins/dsh-web-mobile/lib/client.js` 本体，也未改
   `tools/apply-mobile-client-patches.mjs`（build325 成果保持原样）。

行为矩阵：

| 场景 | 结果 |
|---|---|
| 全新安装、干净 profile | 默认禁用；插件页可见、可启用 |
| 覆盖更新（如 build326→327），旧版本启用过 | 收敛为禁用（无本代次启用记录） |
| 覆盖更新，上一安装代次显式启用过 | 收敛为禁用（记录代次不匹配） |
| 当前安装内显式启用后重启 Web | 保持启用（`.enabled` 代次匹配） |
| 之后再次覆盖更新 | 再次收敛为禁用 |
| 显式禁用（原生空标记或 Web 精确标记） | 保持禁用；旧启用记录清除 |
| 禁用后再显式启用 | 恢复启用并记录当前代次 |
| Web 插件页的精确禁用标记 | 保留内容与受管入口；只移出加载列表 |

## 六、真机待验（未做，需用户 / 主会话确认）

1. **覆盖安装（build326 → build327，升级前插件启用）**：进入主界面不白屏、侧栏只有一个设置
   入口；插件页里 `dsh-web-mobile` 为**禁用**（升级迁移生效），且可显式启用。
2. **本安装内显式启用 → 重启 Web**：插件启用状态保持；再覆盖安装同类修复包后重新变为禁用。
3. **全新安装 / 干净环境**：插件页可见 `dsh-web-mobile`，默认关闭；打开并重启 Web 后移动端
   界面生效；关闭并重启后恢复默认禁用。
4. build325 齿轮可见 / 可点、build326 首连提示与维护入口等既有真机项按各自记录补确认。
5. 插件页禁用态文案、开关与重启提示在中文 / 英文下均正确。

## 七、回退与恢复默认启用

- 恢复默认启用**只有**满足插件页「何时可以恢复默认启用（硬门槛）」才可执行；恢复到默认启用
  的提交必须引用该判据并附真机证据。
- 代码回退：删除 `builtin-plugins.json` 中 `dsh-web-mobile` 的 `defaultDisabled`（或改为
  `false`），重跑 `generate-builtin-plugins`、`prepare-runtime-descriptor --write` 与发布前门禁。
- 注意：回退默认值**不会**自动启用已有 profile 中已禁用的插件（`.disabled` 标记仍在），用户需
  在插件页显式启用。这是有意为之——默认值变化不能覆盖已记录的禁用意图。
