# build163：聊天 shell 子进程临时目录修复

本地交付日期 **2026-10-07**，版本 `0.2.14-20261007.1400-dsh0.2.0-rc.2` / **163**。原包名 `com.dsh.client`、E7E3 历史发布证书、非调试正式构建；DSH `0.2.0-rc.2`、Ubuntu 基础环境 `10` 保持。

基础归档实际没有 `/tmp`，只有模式0700的 `/var/tmp`；预配置工具归档不含这两个目录。以前离线安装脚本会创建并准备临时目录，改用预配置工具包后跳过了这一职责。DSH的本地shell子进程提供者在执行命令前通过 `os.tmpdir()` / `mkdtempSync()` 准备输出及启动临时目录，目录缺失便会在子进程启动前失败。已核对当前真实随包DSH源码和归档成员；本次真机原环境继承旧版本，原已有这两个目录，因此不冒充其为故障原机复现。

`RuntimeTemporaryDirectories` 将目录准备独立到宿主工具准备阶段，并在缓存提前返回前执行。缺失目录按guest临时目录约定建立，已有内容与权限保留；文件、链接或不可写目录会明确失败，原件不覆盖。新候选和普通启动共用该入口，现有安装可通过覆盖更新修复，不要求清数据、格式化或重新下载安装基础环境。

两版各 **45项关联单测全部通过、0跳过**，只选4个关联类，包括实际临时目录创建/文件读回、已有内容与权限保留、冲突文件保护及冷事务门禁。Release Lint无Error/Fatal，Standard230、Low157条Warning与162相同。构建与关联检查 **84.796秒**。包名、版本、E7E3、v1/v2/v3、非调试、API30/23、arm64和实际资产门禁通过；大归档与所有native库和162实际APK逐字节一致，不重复全量归档/native矩阵。

Standard163在Android13真机同签名覆盖，安装时间和UID保留，受管更新后回到READY。使用随该APK安装的实际 `dsh-bash-local` 与 `dsh-subprocess-local` 提供者，在本应用UID的guest中创建临时目录、执行子bash、写入并读回标记文件，退出码0。用户提供的临时key仅在桌面验收进程内存中使用：真实 `deepseek-flash` 模型发起工具调用、实际手机执行、结果回传并获得最终模型回复。工具调用格式按[官方接口说明](https://api-docs.deepseek.com/guides/tool_calls/)核对。此过程使用独立验收编排和受保护本机回调，**不是原生聊天GUI全流程验收，也不是全部模型或sandbox模式矩阵**。应用原有凭据没有修改，key未写入源码、终端、配置或取证文件。

验收临时目录、设备脚本与本轮ADB转发已清理，未删除用户对话、配置、插件或文件。原真机已有临时目录，空目录回归为真实JVM文件系统证据；本轮未额外重测完整首次安装。Low最终163包只完成软件与签名资产门禁，本轮未再覆盖Low或验证Android6/7。未上传GitHub、未合并PR、未修改线上Release或网站。
