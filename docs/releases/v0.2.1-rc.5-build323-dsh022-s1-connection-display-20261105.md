# build323 DSH 0.2.2 S1 连接提示对照记录（2026-11-05）

本记录只记录 T55 S1 的连接提示对照与当前结论，不替代测试包真机验收，也不把页面白屏一次性现象扩写成已确认回归。

## 结论

DSH `0.2.2-rc.1` 的首次连接提示更容易被用户看到，但现有证据更符合上游 ConnectionIndicator 的首次连接显示行为，而不是一次已证实的网络断线：

- `dsh-client-ui-settings-general` 的 `ConnectionIndicator` 只有在此前状态为 `connecting` 或 `disconnected`、随后变为 `connected` 时显示绿色恢复提示；首次页面挂载时若 Connection 尚处 `connecting`，同一组件会先显示黄色 connecting 状态，并在首次 connected 后显示绿色 recovered 状态。
- rc5 与 rc1 的 `dsh-client-connection/lib/client.browser.js` 字节相同，连接 URL、Cookie、backoff、generation ready 警告/超时和状态机没有变化。
- rc1 与 rc5 的前端入口均按 `__DSH_BOOT_READY__`、立即插件预取、完整 manifest 插件激活、最后 `uiRenderer.mount` 的顺序运行；没有证据证明 rc1 把 UI mount 提前到 Connection generation ready 之前。
- rc1 gateway 新增的 `perMessageDeflate` 对照已在真机上验证无效：profile 设置为 `websocketCompression: none` 后仍出现黄色连接提示。该对照已由 `6f6826b2` 回滚。
- 心跳单变量对照已在真机上验证无效：heartbeat 从 2 秒放宽到 15 秒后仍出现黄色连接提示。该对照已由 `3b01abac` 回滚。
- 停用 `dsh-web-mobile` 后黄色提示几乎不可见但绿色仍出现，说明移动插件只放大可见性，不是首连提示的根因。

## 验证范围

- `tools/test-browser-stream-resume.mjs`：rc1 fixture 7/7 通过。
- 真实 Node `ws` gateway fixture：`deflate` 与 `none` 均完成一次 Upgrade 并收到 `$events` 首帧 ready；压缩只改变 `Sec-WebSocket-Extensions` 协商结果。
- App 侧没有 `shouldInterceptRequest`、LAN 代理或 web-compat WebSocket 包装路径介入 `/api/remote.mux`；Cookie 写入等待 `CookieManager.setCookie` 回调后才导航。
- WebView 的 `onPause()` 只在 Activity `onStop()` 中调用，`onStart()` 对应 `WebView.onResume()`；没有启动阶段显式 `pauseTimers()`。首次覆盖安装后的白屏只出现过一次，之后未复现，继续单独观察。

## 后续

该首次连接 UI 行为应作为 DSH 上游/宿主体验问题在 S2 跟进：可反馈首次 `connecting` 不应使用“重新连接中”文案，或在首次 generation ready 前不显示 recovered 状态。S1 不再为此修改上游客户端状态机。
