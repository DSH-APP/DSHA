## Issue #63：DNS 兼容

[问题报告](https://github.com/DSH-APP/DSHA/issues/63)描述某些网络拒绝 AAAA 查询，glibc 双栈解析返回 `EAI_AGAIN`，导致 dsh API 请求报 `TRANSPORT`。

配置页新增三种 DNS 模式，保存后重启 Web 或新建终端使用：

| 模式 | 行为 |
|---|---|
| 自动兼容（默认） | 正常双栈解析保持原样。Node 的 `dns.lookup` / Promise 接口仅在 `EAI_AGAIN` 或 `EAI_FAIL` 时重试一次 IPv4 查询；显式指定 IPv6 时不降级。 |
| IPv4 DNS 兼容 | 在受管 `resolv.conf` 中添加 `options no-aaaa`，同时覆盖使用 glibc 的 curl/git/Python 等工具。代价是这些解析接口无法解析 IPv6-only 域名。 |
| 原生双栈解析 | 关闭 Node 自动回退并移除 DSHA 自己添加的 `no-aaaa` 行。 |

保留用户已有 nameserver、search 和其他 options；用户手写的 `no-aaaa` 也保留，切换模式只增删 DSHA 标记的行。注释里的 nameserver 不会被误认为有效配置。正常启动不重建 Ubuntu；Web、插件、shell、PTY 共用随包预加载环境，不依赖用户安装额外软件。适配发生在 DNS 阶段，不重放 HTTP 请求，也不修改 TLS 校验。

参考：[Node DNS API](https://nodejs.org/api/dns.html)、[glibc resolv.conf 选项](https://man7.org/linux/man-pages/man5/resolv.conf.5.html)。
