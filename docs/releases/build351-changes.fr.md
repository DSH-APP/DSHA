# DSHA 0.2.1-rc.5-20261110.0400-dsh0.2.2-rc.1 / build351

- Exécution privilégiée sur l'écran physique, phase A (T130, `4e8c80e0e`, expérimentale, désactivée par défaut) : le Core privilégié géré `app_process` recopie le display 0 (`VIRTUAL_DISPLAY_FLAG_AUTO_MIRROR`), capture les images via ImageReader avec des bornes `maxWidth` 320–1920 / `jpegQuality` 30–90 / `maxFps` 1–10 (par défaut 1280 / 60 / 6 ; les images presque noires sont marquées `SECURE_OR_BLACK` ; les images ne sont jamais écrites sur disque ni dans les journaux) et injecte les verbes fixes tap / swipe / key (3 / 4 / 66 / 67) — **le chemin ne dépend pas de l'accessibilité**. Ajout de `/app/priv/{info,frame,config,tap,swipe,key,benchmark,close}` et de `PhysicalScreenManager` / `PhysicalScreenCore` / `PhysicalScreenDisplaySession` / `PhysicalScreenLauncher` ; le reçu d'une action renvoie en un seul aller-retour une image neuve et une observation neuve, l'identifiant vit 30 secondes, est à usage unique et lié à la generation et au paquet cible, `EXECUTION_UNKNOWN` n'est jamais rejoué, et les échecs sont fail-closed sans repli silencieux vers l'accessibilité. Quatre portes : Réglages → Autorisations de capacités de l'appareil → Exécution privilégiée (`privileged_execution_v1`, autorisation native, désactivée par défaut, révocable, jamais restaurée depuis une sauvegarde ou l'environnement, sa désactivation coupe la connexion au Core), l'identité de la tâche téléphone en cours (`taskSessionId` / `turnId` après `/app/ui/task-begin`), un paquet cible vérifiable (`PRIV_TARGET_UNVERIFIABLE`), le refus des applications sensibles (`PRIV_SENSITIVE_TARGET_UNSUPPORTED`) et `ScreenConfirmationPolicy.allows` ; la phase A n'affiche pas de confirmation native par action, donc ASK vaut toujours `NOT_SENT` (`SCREEN_CONFIRMATION_REQUIRED`) et seuls « tout autoriser » ou `ALLOW` par application passent. `/app/priv/benchmark` exécute N chaînes d'actions complètes et renvoie `roundTripMs` côté App et p50 / p95 / max de `inputMs` / `frameWaitMs` côté Core (rang le plus proche, sans interpolation) avec `accessibilityRequired:false` ; `waitMs` va de 0 à 500, `n` de 1 à 20 et `n × (waitMs + 400) ≤ 8000`. Rotation / écran partagé / changement de résolution reconstruisent le miroir et changent la `generation`, invalidant tous les anciens identifiants ; la détection d'image noire est une heuristique d'échantillonnage à 48 pixels pour l'appelant, pas une reconnaissance de contenu. Documentation : `docs/privileged-screen-core.md` ; 27 tests unitaires ajoutés (politique / routes / lanceur / gestionnaire).
