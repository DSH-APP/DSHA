# DSHA 0.1.5-rc1.1 修订与验收

本次交付标准版 `dsha-0.1.5-rc1.1.apk` 与兼容版 `dsha-0.1.5-rc1.1low.apk`，版本码 **120**，沿用历史发布签名。dsh 保持 **0.1.5-rc.1**，Ubuntu 基础环境保持 **10**。从 rc1 或早期 rc1.1 覆盖安装只更新受管运行时与适配工具，个人目录、会话和第三方插件保持原位。

按用户要求继续叫 rc1.1，并覆盖同名交付文件。版本码 120 修复旧 WebView 的插件加载与 PDF、插件检测、页面定位和 Agent 预设切换；下方保留版本码 117–119 的既有验收记录。

## 版本码 120 的修复

- **插件加载与 PDF**：真机 WebView 116 的官方文档预览模块在初始化时访问 `Iterator`，导致整页报告插件加载失败。随包增加锁定的 core-js 3.50.0 兼容代码，在官方模块加载前和独立 PDF Worker 内补齐实际使用的 Iterator、URL、Promise、集合及二进制接口。对旧 Chromium 的 `dsh-resource://file/` 主机解析问题单独修正文件资源分派，保留普通 URL 行为。补丁针对锁定版本校验唯一锚点，保留源码行号和 Worker 生命周期。
- **原生插件检测**：本机 proroot 的 glibc 初始化崩溃也影响辅助插件命令。插件注册与管理从启动时就使用稳定 proot，避免变更执行后重试；Web 自身保留原有的退出核验与一次兼容重试。
- **安装与修复页面**：首次进入从顶部显示。追加日志只滚动内部日志区域，不再通过焦点移动把外层页面拉到中间；用户已滚动的位置保持。
- **备份 API Key 选项**：移入「备份与恢复」，沿用原偏好值并即时保存；配置页保存不再覆盖此选项，环境维护期间仍受操作门禁保护。
- **启动日志（[Issue #61](https://github.com/DSH-APP/DSHA/issues/61)）**：操作区固定，日志占剩余空间并独立滚动；矮横屏使用左右布局。用户上翻历史时暂停自动跟随，回到底部后继续跟随。
- **Agent 预设**：会话页原来的只读标签改为可点击菜单，提供标准、PTC、极简和创造四种预设。空会话直接切换；已有内容的会话保留，并在原工作区创建所选预设的新会话，菜单明确提示。只有服务端确认目标预设后才更新显示；拒绝、断网、重复点击和切换期间导航均有处理。

## 修复与调整

- **个人目录保护**：使用独立 rootfs 映射读取待迁移文件，避免把运行时外部挂载纳入扫描；归档时同步计算源文件摘要，使用较低压缩级别，保留压缩归档和恢复后的逐文件验证。可用时走经过退出核验的 proroot 快速迁移，否则在探测安全退出后使用 proot。显示阶段、文件数、字节数和耗时。
- **终端回收**：PTY 子进程在 exec 前自读出生身份，父进程登记并确认后才启动 shell，避免非调试版创建时首次读取失败后永久保留空身份。先查询内核会话号，再检查本次 PTY 的成员；失败保留保护状态，下一次维护重新核验。启动器退出后仍确认 guest 已结束，未确认时不切换环境。
- **维护失败入口**：维护页提供受限主界面，允许查看日志和修改原生配置；恢复提示持续可见，插件、终端及 Web 启动仍受环境门禁保护，不伪造就绪标记。
- **启动日志**：本机日志显示当前完整 Web 鉴权链接，可长按复制。导出诊断继续脱敏。日志只在固定区域内部滚动，启动、重启、停止及恢复操作保持可见；小屏下使用紧凑按钮布局。
- **短信预授权**：设置新增设备能力授权。默认逐次确认，明确开启后允许本 Android 用户的短信查询，可随时撤销；不支持短信发送、写入、跨用户或其他内容提供者。需 ADB 及 Android 实际访问权限，Shizuku 不执行此敏感查询。系统备份与换机恢复不恢复这项授权。
- **ADB 说明**：区分无线配对端口和连接端口，说明同机分屏操作、配对确认及不同安卓版本的入口；按实际策略说明设备能力，不再把安装应用和系统设置写入说成允许操作。
- **插件与设置界面**：统一圆角、描边、渐变、图标和按钮状态；插件管理保留检测、启停、详情、导入、导出、更新、回退和移除入口。
- **网页会话**：单击选中，同一条目连续双击打开；仅保留一个选中状态，键盘与辅助功能可显式激活。单击不会收起移动侧栏，实际打开后收起；移除打开会话时编辑器自动获取焦点的行为。

## 版本码 118 的终端身份修复

早期 rc1.1 的 Java 层在 Termux 创建子进程后只读取一次 `/proc/<pid>/stat`。非调试真机包中该读取失败后永久保留空身份；稍后同一进程已能读取，维护仍报“无法确认终端身份，原环境保持保护”。将子进程暂停在 exec 之前进一步确认：子进程能自读 stat，而父进程读取同一条目返回 `ENOENT`。

修复在 `setsid` 后通过本次 fork 创建的专用 socketpair 回传身份。父进程验证 PID、PPID、启动时间、独立进程组和会话号，保存到 Java 会话后才确认子进程 exec。登记在 Termux 启动 waitFor 线程之前完成，快速退出也不会丢失身份；停止时不临时认领未知 PID。握手失败在子进程尚未执行容器命令且 PID 尚未交给 Termux 回收前结束该子进程；初始化异常也必须确认会话为空才能释放保护。

固定的 Termux 上游 C 文件原样保留，构建时按六个唯一锚点生成补丁。API 23、16 KiB LOAD 对齐及 4 KiB / 16 KiB RELRO 检查通过。非调试插桩包用于回归；最终交付包没有插桩入口。测试日志及交付报告位于本地 `app/build/rc112-20260910/`，目录名只是本轮测试记录标识。
