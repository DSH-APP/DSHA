# DSHA 0.2.1-rc.5-20261106.0130-dsh0.2.2-rc.1 / build329

- Adiciona a página nativa de login do GitHub (T71): mostra a conta, os escopos e a origem do `hosts.yml` do contêiner, informa se o `gh` gerenciado está disponível e usa `gh api -i /user` somente para leitura para distinguir falha de CA/TLS, token 401, não conectado, rede e timeout; oferece login, nova autorização e logout. A página em si não exibe o token. Lacuna conhecida: o token continua no `hosts.yml` do contêiner e pode ser lido por páginas web e plugins com o mesmo UID; o isolamento está registrado à parte em T50 e não faz parte deste lote.
- Corrige a busca do CA do `gh` (T73): o `RuntimeTools` passa a definir `DSHA_GH_HOST_ROOT` a partir da raiz canonical do host, e o wrapper do `gh` procura o CA gerenciado nas duas visões de dados `/data/user/0` e `/data/data`; quando ambos faltam, ou `DSHA_GH_CA` aponta para um arquivo inexistente, ele sai com erro explícito em vez de recuar silenciosamente para o CA antigo do sistema, que não tem o novo certificado raiz. As entradas fixas não são reconstruídas.
- Unifica o rodapé da 4ª etapa do onboarding (T72): a página de conclusão das boas-vindas passa a usar o mesmo `ExtractFooter` compacto de duas linhas da página de manutenção do ambiente, mostrando x/5 durante a atualização, restaurando a ação principal e entrando na interface principal quando pronto.
