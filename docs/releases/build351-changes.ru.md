# DSHA 0.2.1-rc.5-20261110.0400-dsh0.2.2-rc.1 / build351

- Привилегированное исполнение на физическом экране, этап A (T130, `4e8c80e0e`, экспериментально, по умолчанию выключено): управляемый привилегированный Core `app_process` зеркалирует display 0 (`VIRTUAL_DISPLAY_FLAG_AUTO_MIRROR`) и снимает кадры через ImageReader с ограниченными `maxWidth` 320–1920 / `jpegQuality` 30–90 / `maxFps` 1–10 (по умолчанию 1280 / 60 / 6; почти чёрные кадры помечаются `SECURE_OR_BLACK`; кадры никогда не пишутся на диск и в журналы) и вводит фиксированные глаголы tap / swipe / key (3 / 4 / 66 / 67) — **путь не зависит от специальных возможностей**. Добавлены `/app/priv/{info,frame,config,tap,swipe,key,benchmark,close}` и `PhysicalScreenManager` / `PhysicalScreenCore` / `PhysicalScreenDisplaySession` / `PhysicalScreenLauncher`; ответ на действие за один обмен возвращает новый кадр и новое наблюдение, учётные данные живут 30 секунд, одноразовые и привязаны к generation и целевому пакету, `EXECUTION_UNKNOWN` не повторяется, а сбои fail-closed без тихого отката к специальным возможностям. Четыре шлюза: Настройки → Разрешения возможностей устройства → Привилегированное исполнение (`privileged_execution_v1`, нативное разрешение, по умолчанию выключено, отзывается, не восстанавливается из резервной копии или окружения, при выключении соединение с Core сбрасывается), идентичность текущей задачи телефона (`taskSessionId` / `turnId` после `/app/ui/task-begin`), проверяемый целевой пакет (`PRIV_TARGET_UNVERIFIABLE`), отказ для чувствительных приложений (`PRIV_SENSITIVE_TARGET_UNSUPPORTED`) и `ScreenConfirmationPolicy.allows`; этап A не показывает нативное подтверждение на каждое действие, поэтому ASK всегда `NOT_SENT` (`SCREEN_CONFIRMATION_REQUIRED`), проходят только «разрешить всё» или `ALLOW` для приложения. `/app/priv/benchmark` выполняет N полных цепочек действий и выдаёт `roundTripMs` на стороне App и p50 / p95 / max для `inputMs` / `frameWaitMs` на стороне Core (ранговая оценка без интерполяции) с `accessibilityRequired:false`; `waitMs` 0–500, `n` 1–20 и `n × (waitMs + 400) ≤ 8000`. Поворот / разделённый экран / смена разрешения пересоздают зеркало и меняют `generation`, старые учётные данные становятся недействительными; определение чёрного кадра — эвристика по 48 пикселям для вызывающей стороны, а не распознавание содержимого. Документация: `docs/privileged-screen-core.md`; добавлено 27 модульных тестов (политика / маршруты / лаунчер / менеджер).
