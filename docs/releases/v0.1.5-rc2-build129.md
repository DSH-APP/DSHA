# DSHA 0.1.5-rc2 · 构建 129

修复 [#64](https://github.com/DSH-APP/DSHA/issues/64) 的多文件选择丢失，并增加 Shizuku 兼容管理器的主动连接恢复。版本码 **129**，dsh **0.1.5-rc.2**，Ubuntu 基础环境 **10**，移动插件 **2.4.1-dsha.2**。保留此前界面、终端、语言、DNS、平板升级与顶栏修复。

## 文件多选

系统文件选择器把多个 URI 放在 ClipData；旧 WebView parseResult 只读取 getData，导致多选被当成取消。WebView 与 Gecko 现在共用 WebUploads.parseChooserResult：ClipData 优先，空列表回退到单选，忽略无 URI 项、按顺序去重，拒绝非 content 来源。后续复制、20 个文件 / 256 MiB 上限、生命周期回调与 FileProvider 隔离保持。

## Shizuku 改版

参考 [thedjchi 管理器的 Binder 请求实现](https://github.com/thedjchi/Shizuku/blob/master/manager/src/main/java/moe/shizuku/manager/shell/ShellBinderRequestHandler.kt) 和 [改包名实现](https://github.com/thedjchi/Shizuku/blob/master/manager/src/main/java/moe/shizuku/manager/utils/ApkUtils.kt)：

- 按 API_V23 权限所属管理器识别与打开，兼容保留标准协议的改包名版本；不再仅查询官方包名。
- 未收到 Binder 时，用户点击授权会调用管理器的标准 REQUEST_BINDER 入口，再由应用原有 Provider 完成 API 握手与授权流程。
- 回调限制管理器 UID、服务描述符、单次响应和 15 秒等待；不执行附带 APK 路径，不放宽 Provider 的系统权限，也不替代管理器授权。
- 管理器服务未运行时给出启动及隐藏模式提示；已经发送的设备命令不切换通道重放。

当前连接设备安装的是 Shizuku **13.6.0.r1086.2650830c**。标准 API 13.1.5 与兼容 API 12.2.0 都已实测重新获取 Binder、保留现有授权、绑定 UserService 和执行 id，返回 uid=2000(shell)。**未在实际 thedjchi 改版安装实例上复测**；兼容以其公开协议为依据，不承诺修改了协议、禁用了组件或故意隐藏 DSHA 的任意改版。

## 旧 WebView / PDF

此前 rc2 已包含 Iterator 及 PDF.js 所需 API 的兼容库，本次保留并重新验证。新增 Iterator 能力检查；修复打包器把含换行字符串改成模板字面量后，PDF 单行前导可能改变换行含义的问题。HTML 在应用脚本前注入兼容代码，PDF 模块与 Worker 也保留独立前导，原始插件错误不会被隐藏。
