# F12：插件响应、恢复后的局域网鉴权与欢迎说明保存

本批沿用 build170 基座、versionCode 190、内置 DSH 0.2.1-rc.2、Ubuntu base10，默认 proot、可选 proroot。标准 APK 保持 `com.dsh.client`、E7E3 历史发布签名、非调试，文件名保持 `dsha-0.2.1-rc.2.apk`。诊断版本含实际构建日期和时间；最终身份、摘要与软件验证结果由本批冻结记录和关联 Release 绑定。

用户要求本轮暂停真机验收。本记录不包含设备、ADB、真实账号登录、模型对话或新的四/八小时持续测试。F11 是本地软件检查点，未推送源码或创建对应 Release；不能把 F11 的测试数量、APK SHA 或设备历史转记给本批。

## 修复范围

- 插件发现先筛选真实 bundle，再核对签名受管内容；一次查询只认证一次证明，同一查询内合并 canonical 别名。文件内容、模式、软链及目录前后稳定性检查继续保留，下一次查询和提交重新核验。
- Node 插件内容证明改为异步、有界文件读取。只读列表不持 profile 写锁；删除在提交时重新完整核验实际目标。原生启停先返回精确名称、Boolean 状态与实际持久化读回结果，再独立刷新列表。保存启停意图不等于运行组件已经完成重载。
- 原生插件查询合并刷新，保留最近一次已确认列表并支持取消；排队、准备边界及执行共用剩余期限。准备中的单次系统 IO、monitor、Binder 无法抢占；未知退出保留既有屏障。失败不再同步补扫整张列表。
- 严格认领仍在运行的 Web 后，在第二次进程核验和当前代次检查通过后发布已经验证的 LAN cookie。复用实际端口与原鉴权结果，不再重复认证或重放启动、迁移、业务操作。
- 同一代次后来失去进程身份证明时，拒绝尚未完成的 LAN 发布，并撤销该代次已有的 LAN 鉴权、监听及连接；不影响新代次，不给身份不明的 Web 进程发信号，也不解除停止屏障。
- 欢迎说明保存的丢响应、后台完成及 revision 冲突路径单独核验。只有真实 Host 确认持久状态才能关闭说明；未保存或未知结果不能显示为已保存。
- 补齐中文分发文件和现行英文维护文档，保留原历史证据与新建导航副本的区别。英文入口见 [English index](../en/index.md)，本记录的英文版见 [English release record](../en/releases/v0.2.1-rc.2-build190-fix12-20261021.md)。

## 自动 Web 端口调查

原生插件助手走 guest 命令，不使用 Web 端口；网页插件管理使用当前 Connection。宿主受控测试中，官方语音插件真实启用、禁用后 HTTP 实例及端口保持一致。现有证据证明耗时扫描会阻塞 Node 事件循环，不能据此断言所有手机现象都由同一个原因引起。

自动模式优先复用本机上次成功且仍可用的端口，必要时由内核分配。恢复与 LAN 发布都绑定当前 generation、实际 URL 和实际端口。端口改变会改变网页 origin，旧网页数据、OAuth 本次临时回调路由和 LAN 代理各有独立规则；OAuth 路由属于当前 WebServer，不另开临时监听端口。详见[端口](../ports-and-networking.md)、[LAN](../lan.md)与[启动诊断](../startup-and-diagnostics.md)。
