# build161：issue95/97/98 与 PR94

本地交付日期 **2026-10-07**。版本 `0.2.12-20261007.0900-dsh0.2.0-rc.2` / **161**，包名 `com.dsh.client`、E7E3 历史发布证书、非调试正式包。DSH `0.2.0-rc.2`、Ubuntu 基础环境 `10` 保持。

- [#95](https://github.com/DSH-APP/DSHA/issues/95)：Android 11 独立虚拟屏进程在已准备主 Looper 的 shell/root 主线程创建系统 Context，避开 ROM 的 `systemMain/attach` 钩子；保留真实安装包与 classpath 检查。启动握手允许有界 ROM 普通输出，仍只接受精确 48 位受管标记。子进程 stderr 不再丢弃，退出后先消费已到达的错误标记；错误按阶段、SDK、异常类型传播到原生诊断，不记录启动凭据、不换通道重放。原 vivo Android 11 尚未复测，不能宣称该设备已通过。平台参考为 [scrcpy 独立进程上下文初始化](https://github.com/Genymobile/scrcpy/blob/master/server/src/main/java/com/genymobile/scrcpy/Workarounds.java)；实现仅在 API30 的独立核心入口使用此分支，其他 Root/Shizuku 上下文职责保持。
- [#97](https://github.com/DSH-APP/DSHA/issues/97)：截图显示的是 E7E3 **证书指纹**，发布页 `f8115dd…` 是 **APK 文件摘要**，二者不能比较。历史发布 APK 实际 SHA、85 字节侧车及 GitHub 资产摘要一致。补充[中英文下载校验说明](../download-verification.md)和 README 入口，保留已发布包。
- [#98](https://github.com/DSH-APP/DSHA/issues/98)：401 区分缺失、不匹配与凭据未就绪，说明回 DSHA 重新复制链接；503 区分等待 DSH 认证与代理繁忙，502、408 和非法请求各自提供指引。返回标准状态短语、机器可读 `X-Dsha-Lan-Reason`、UTF-8 实际字节长度；HEAD 无正文，401 只清 LAN cookie。凭据撤销和代次边界保持，链接弹窗说明重启后的失效规则。
- [PR #94](https://github.com/DSH-APP/DSHA/pull/94)：集成显示摘要方向，并修正原正则过度转义、不同数字归并、截短后记录碰撞、跨事件重排和最终截断丢失败原因的问题。只压缩显示副本，原记录写入和事务状态不变；省略提示提供中英文。详见 [PR 审阅](build161-pr94-review.md)。
