# DSHA 0.2.1-rc.5-20261106.0230-dsh0.2.2-rc.1 / build330

- Recusa iniciar o próprio host na tela virtual (T76): o `/app/vscreen/launch` não aceita mais o pacote do próprio DSHA como alvo. O sistema não cria uma instância separada para a tela secundária; ele reutiliza o mesmo processo em execução, e a WebView já vinculada ao display padrão cai com ponteiro nulo em `libmonochrome` na tela secundária (evidência do dispositivo relay: display 4, Looper da thread principal entrando na WebView, processo 14715 em execução reutilizado). O bridge recusa antes de qualquer pedido de autorização, o Manager antes do claim e o Core antes de enviar `am start`, todos pela mesma verificação, retornando `VSCREEN_SELF_LAUNCH_REFUSED` (`state=NOT_SENT`, nenhum comando de início é enviado e não há queda); o plugin embutido classifica esse código como pre-dispatch, o seletor nativo de aplicativos não lista mais o host e a página de resultado mostra o motivo em chinês/inglês. Esta é uma recusa de segurança, não suporte a self-launch em tela secundária; para suportar depois é preciso `createDisplayContext` com uma instância de WebView separada. O runtime descriptor é regenerado (runtimeId `35e3f499`); as entradas fixas não são reconstruídas.
- Correção do ativo gh gerenciado no APK (T79, conclusão B do T78): os APKs oficiais build328/329 contêm apenas `assets/gh-cli.tar` (38.727.680 B, STORED), sem `gh-cli.tar.gz` — a fusão de ativos do AGP 9.1.1 faz gunzip automaticamente de arquivos `.gz` e remove a extensão, então a instalação gerenciada que abre `gh-cli.tar.gz` falha necessariamente (o bootstrap do wrapper ainda pode recuperar). O nome da entrada fixa de origem e o pin do `runtime-descriptor.json` não mudam e as entradas fixas não são reconstruídas; o nome de empacotamento no APK passa a ser `gh-cli.bin`, o `RuntimeTools` abre o nome empacotado e recorre ao nome de origem, e o novo portão de release `tools/verify-apk-managed-assets.py` verifica os nomes reais dos membros, os resumos byte a byte e o membro gh fixado nas cadeias de build do pacote de produção e do pacote de teste, para que uma renomeação silenciosa não volte. O runtimeId acompanha a mudança do gerador gerenciado e passa a `35e3f499` (as entradas fixas não são reconstruídas).
