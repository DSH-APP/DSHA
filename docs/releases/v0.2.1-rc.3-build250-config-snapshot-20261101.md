## 2. 问题

- 配置快照“删不掉”：捕获中断（超 4 MiB、链接、源变化、取消）留下无 `metadata.json` 的半成品目录；轮换只删除校验通过的目录，半成品与“删除到一半”的目录永久残留。
- 半成品累计到 72 份后，`prepare`、`before`、`create` 全部 `RECOVERY_RETENTION_LIMIT`，且只有成功捕获后才轮换，系统无法自愈；插件卸载因前置 `before` 失败而不可用。
- 目录引用的快照损坏或被手动删除后，选槽位时逐个 `load()` 抛出，修复前快照、新建配置与插件卸载全部报 `RECOVERY_CHECKSUM` / `UNSAFE_ROOT`。
- 轮换删除失败在目录已提交后仍向调用方报错；恢复页没有删除入口，DocumentsProvider 按私有根拒绝访问。

## 3. 改动

- `ConfigurationSnapshots`：捕获失败只回收本次新建且 inode 未变的目录；删除改为先 rename 到 `retiring/` 再递归清理；未引用且无法校验的目录移入 `retained/`（上限 32，不计入 72 份上限、不参与恢复与轮换）；选槽位顺序为坏/悬空 → 空 → 最旧；`catalog.json` 不可读时回退 `.previous`，两份都不可读时不整理、不新建；已提交后的整理失败只进诊断；全部写入口进程内串行；旧状态标记保留最近 8 份。
- 新命令 `discard`（slot + id 或旧检查点 inode/大小/修改时间绑定；候选与 `pending` 不可删）与 `discard-retained`；均要求维护屏障。
- 启动恢复页：损坏快照显示错误码并可删除；普通快照点开后选择“恢复”或“删除”（选择框不是安全确认，全局确认不会代选恢复）；隔离区一次清空。
- 启动诊断改记受控错误码（`ConfigurationSnapshots.errorCode`）。
