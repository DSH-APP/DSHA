## 实现范围

### CAS轻入口、FD扫描和分段时序

普通启动调用专用 `python3 -u /root/.dsh/materialize-cas-links.py`，仍固定使用proot。主Web显式选择proroot不会把该兼容事务改成proroot。轻入口保留内置registry校验、两把共享锁、事务恢复及原V1唯一末行 `PLUGIN_RESULT` 合同，去除plugin-manager在派发小命令前的SSL、下载和归档通用初始化。

POSIX扫描使用已打开目录FD和NOFOLLOW锚定实际目录。每个child复核当前目录边，进入/返回时复核上层边；各目录保留fstat稳定性和二次names枚举，最终由reader.parent完成全路径identity核验。Windows路径回退保留逐child递归祖先复核。持续目录换链会被拒绝；不承诺捕获根之上瞬时移走又移回的每次事件，FD读取不会因此被重定向到替代树。需要转换的CAS内容仍由原proot事务处理，保留O_PATH pin、原件、提交前全链身份/时间核对和分批恢复语义。

**普通启动仍完整扫描相关profile实体依赖树。** 未新增根mtime、manifest或“上次成功”缓存；关闭插件也不保证其实体依赖目录不被扫描。此次减少重复祖先核验和无关解释器导入，没有证明可以免除深层任意终端/pnpm写入后的完整检查；宿主Java只读扫描、不可变代次索引、Node编译缓存、核心预打包和惰性激活均未据外部建议自动启用。

| 诊断字段 | 覆盖的工作与限制 |
|---|---|
| `CAS_HOST_TIMING` | 原生文件准备、launcher准备、进程创建、输出收集、退出收尾；使用单调时钟，失败记录独立阶段 |
| `CAS_TIMING` | Python入口导入、data/profile锁等待、事务检查、扫描、复制提交和入口总时长；扫描记录条目/目录/最大组件深度/候选，复制记录字节/批次 |
| 输出预算 | Java最多保留24条CAS计时行，每条最多4096字符；属于有界诊断，不记录用户文件正文 |
| 成功判据 | 先确认非超时、零退出、输出未截断及guest/launcher收尾，再验证唯一类型化回执；计时行不能替代成功回执 |

Python成功行在锁释放后输出；host和Python时钟测量不同边界，不能把其中重叠span直接相加。`changed=false`只表示未复制CAS内容，不表示未扫描、未等待锁或完全无维护工作。已有受管预加载/环境、退出不确定屏障和未知写入不重放规则保持。

### 账号资料在途请求合并与HTTP错误说明

账号资料与赠额通知身份查询在**凭据detailsLifetime、issuer/token及实际请求headers均相同**时，共享尚未完成的profile/users-current读取。完成后移除在途项；失败不缓存、不新增HTTP重试。不同凭据或请求上下文不共享结果，不能拿旧账号成功缓存证明新账号身份。

收到HTTP403时，日志准确记为 `http-error` / `forbidden`；抛给现有UI/schema的 `network` 合同保留兼容，不能据该旧字段断言断网/DNS/TLS失败。403不清空凭据，也不被直接归为token过期；HTTP401及成功HTTP业务码40003继续遵守原过期机制。账号后端错误和前端read-failed使用固定非敏感字段的单字符串JSON，避免这几条错误因对象拼接退化为 `[object Object]`。

这减少并发消费者产生的重复GET和诊断歧义，不修复服务端拒绝规则，也不把模型目录接口成功解释为账号资料403恢复。此次没有真实账号外部请求验收；令牌、请求headers值及响应正文不写入本轮源码文档。

### 启动里程碑和运行期诊断分离

| 字段或事件 | 当前含义 |
|---|---|
| `START_ADMISSION_MS` / `START_QUEUE_MS` | 补充启动准入和排队观察；不把原trace起点自动称为点击时刻 |
| `backendReadyMs` | 官方鉴权地址被本代次接受的时点；未知为-1，不用“离开等待阶段”替代 |
| `browserReadyMs` | 首次有效网页ready时点，不等于所有插件/模型/设备功能可用 |
| `elapsedMs` | 启动记录在首次网页ready或失败/停止后冻结 |
| `runElapsedMs` | 该运行代次的记录时长；ready后的错误继续带运行时间，和启动耗时分开 |
| `SESSION_REATTACHED` | 恢复接入原有Web，0ms表示本次接入观察，不是新进程启动测速 |

ready后原始脱敏错误仍保留，并明确标注运行期；结构化问题只作为 `RUNTIME_ERROR`，不再污染启动问题或使已ready运行被误判为启动失败。移除根据关键词/后续12行堆栈推测复制的 `RELATED_PLUGIN_LOG`，原始行保留一次；页面问题仅按明确entry ID归因，不借依赖路径把错误归给base插件。观察器覆盖等待鉴权显示阶段时只记录“切换离开”，不再声称鉴权已经完成。

时间线仍从 `diagnostics.begin` 起算；新准入/排队字段增加可见范围，但不是Android创建进程、用户点击、导航、渲染和真实核心操作成功的完整端到端贯通证据。

### 删除截图中的DSH权限策略

移除运行配置中的“完整访问 / 工作区写入 / 只读”三选项和说明。正式Web启动命令固定 `DSH_PERMISSION_MODE='danger-full-access'`，不再接收该档位参数。覆盖升级清理历史 `permission_mode`；用户备份/系统偏好迁移不再导出或导入它，旧中断恢复事务接受旧字段但忽略其值，其他字段继续正常恢复。既有DSH会话自身权限、插件配置与独立应急只读策略不在此处改写。

用户要求删除的是该DSH运行模式选择。屏幕操作的“全部手动 / 按应用自定义 / 全部允许”是另一套原生确认规则，继续保留；Android无障碍、ADB、Root、Shizuku、麦克风、SAF和虚拟屏能力仍遵守各自系统授权、目标/运行代次/最新帧核验。终端和第三方插件执行能力不因这次UI删除而成为强沙箱。
