# DSHA 0.2.1-rc.5-20261110.0700-dsh0.2.2-rc.1 / build352

- Overwrite-upgrade first-start plugin registration fix (T135, `092b8848d`): the registration budget is tiered by managed-asset identity — 90 s for a normal start and 240 s for a first start. The host reads `runtimeId` from `runtime-descriptor` and the guest reads `managed-assets-v2`; after a successful registration `register-managed-asset-id` is written atomically, a timeout-killed attempt leaves it unwritten so the next start still gets the wide budget. The registration script gains `--clear-stale-profile-lock` (it bypasses `operation_lock` and only removes locks whose holder has been confirmed exited), and the host runs one 10 s-budget cleanup after a registration timeout; `plugin-manager list` reports `PLUGIN_PROFILE_LOCK_STALE` (retryable) for dead holders instead of the vague "configuration is being modified". `StartupRecoveryState` gains `Kind.REGISTER`, recognising `BUILTIN_REGISTER_TIMEOUT` / `EXIT_` / `RECEIPT_MISSING` and `PLUGIN_PROFILE_LOCK_TIMEOUT` / `STALE`; titles and descriptions say "plugin registration timed out / did not finish / has a lock pending confirmation — retry directly", and `StartupText` keeps only the actionable conclusion, dropping the raw `exit=` / `timedOut=` / guest JSON (the raw text stays in the startup history and logs). Host-side staged timing: the registration command goes through a Runner line callback and the failure message appends `hostElapsedMs` and the last `REGISTER_TIMING` stage, with `GUEST_TIMING_MISMATCH` set explicitly when the guest's self-reported time exceeds the host wall clock. No duplicate overlay install on first start: `RuntimeTools` writes a cross-process `.runtime-tools-prepared` completion stamp (relative managed file set + `RuntimeAssetStamp`), reused only when the APK identity, registered descriptor identity and metadata stamp all match, falling back to full preparation on any mismatch. Registration joins the maintenance readiness check: the update `RuntimeTrial` static validation becomes `register=true`, `requireCompleted` + `BUILTIN_REGISTER_OK`, registration finishes before the Web trial and a failure rolls back with the transaction. New `RegisterBudget` / `GuestTimingEvidence` / `RuntimePreparedProof` unit tests plus registration-budget, timing-evidence, timeout lock cleanup, `REGISTER` classification and `StartupText` folding cases; `tools/` gains lock-state / takeover / cleanup, identity-marker and stale-lock listing tests. **The 479409 ms figure is not attributed to any single sub-stage** — only host and guest timings plus the last stage go into diagnostics, and the first start after an overwrite upgrade still needs device validation.
- External-device page observation channel (T134, `24130f244`): new `/app/extdev/watch` (`mode=events` / `window`) continuously samples the target events buffer inside one dedicated ADB session, so a check no longer restarts the server; it returns the foreground package / Activity, a digest bound to the target generation, `sequence` and `settle`, and its `since` cursor strings calls together into "wait for the page to change". `operate` supports `observe=1`: when an action has been dispatched (not UNKNOWN) it attaches a 4-sample observation; an observation failure only writes `observationUnavailable` and never rewrites the action status, while `NOT_SENT` / `POLICY_BLOCKED` / `UNKNOWN` semantics are unchanged. Pure logic `ExternalFocusEvents` / `ExternalWatchPolicy` / `ExternalRateLimit` is extracted with unit tests; sampling stays on the read-only command allowlist (no `logcat -t`: on device it truncates the raw tail first and then filters, yielding empty results). Device measurement (OnePlus PJD110 / Android 16): logcat events sampling detection p50 123 ms, `dumpsys window` 128 ms, `screencap` 922 ms; `screenrecord` h264 first frame 37–43 ms but needs decoding / frame diffing, left for Phase C. `/app/help` (Chinese and English), the documentation index and `tools/java-format-files.json` are updated, and the runtime descriptor is recomputed (`HttpShellService` / `BridgeRoutes` are launcher inputs). **`/app/extdev/watch` is a new endpoint and has no endpoint-level device acceptance yet; it needs item-by-item acceptance with a test package on the PJD110.**
- Build351 overwrite-upgrade first-start failure root-cause report (T133, `bf59e8864`, documentation only): classified mainly as ③ missing mechanism (fixed 90 s registration budget, no staged budget / renewal, no lock cleanup on timeout), aggravated by ① design chain (duplicate managed overlay on first start, a residual profile lock reported again by the recovery page) and ② insufficient semantics (`BUILTIN_REGISTER_TIMEOUT` unclassified / landing on `STARTUP_FAILED`, raw `exit=` / JSON surfaced). Evidence is the recovery / maintenance page timeline plus a local build351 normal-start baseline (register 870 ms, stamp 65 ms, 101 items); the report records that the guest 479409 ms is inconsistent with the host 90 s budget and lists it as a gap awaiting field evidence, **without deriving a sub-stage from it**. The report gives the minimal fix above and a test-package reproduction / evidence checklist, and changes no production code.
- Managed runtime update: the T135 registration scripts and launcher inputs plus the T134 `HttpShellService` / `BridgeRoutes` feed `runtime-descriptor`, and the merged tree recomputes `runtimeId` to **`b8c59df9`** through `tools/prepare-runtime-descriptor.py` (205 inputs); fixed inputs stay frozen at the locked `fixed-inputs-20261105e`, with bundled `dsh-web-mobile` 3.3.5 and default-enabled unchanged.
