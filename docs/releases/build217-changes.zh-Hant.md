# DSHA 0.2.1-rc.3-20261031.0700-dsh0.2.1-rc.5 / build217

- 修正插件列表在容器內經 apt 等安裝或升級系統函式庫後一直讀取失敗：Playwright 等工具經 apt 安裝 `libsqlite3-0` 時會把 `libsqlite3.so.0` 換成指向 `libsqlite3.so.0.8.6` 的符號連結，唯讀查詢原先只認一般檔案，因此每次都顯示「執行工具或資產不完整」，而「安裝與修復」又因判據不同而不會改寫該檔案。
- 插件唯讀查詢與 Python 動態函式庫修復現在共用同一 guest 判據：在 Ubuntu 執行根內逐層解析符號連結（相對連結、guest 絕對路徑與 `.l2s` 等本機執行根路徑），只接受最終落在執行根內的一般檔案；`/system`、`/proc`、`/sdcard` 等外部綁定、越界與循環連結仍判為未就緒。不論連結由容器內 proot 模擬的 root 或外部 su 授予的 root 寫入，判斷方式一致。
- 修復流程只刪除無法解析的懸空連結本身後寫回隨包函式庫檔案，已可用的連結不再被改寫；插件就緒結論變化時在診斷記錄中寫明具體檔案與原因（如 `libsqlite3.so.0:MISSING`），不再只有籠統提示。
- 新增純邏輯 `GuestRegularFile` 與單元測試；該類別加入受管執行階段啟動輸入，執行階段描述元隨之重新產生。版本碼提升為 217；DSHA 修訂號維持 0.2.1-rc.3，內建 DSH 為 0.2.1-rc.5；建置與驗收範圍以本輪 CI run 與 Release 回執為準。
