# DSHA 0.2.1-rc.3-20261031.0700-dsh0.2.1-rc.5 / build217

- 修复插件列表在容器里通过 apt 等安装或升级系统库后一直读取失败：Playwright 等工具经 apt 安装 `libsqlite3-0` 时会把 `libsqlite3.so.0` 换成指向 `libsqlite3.so.0.8.6` 的符号链接，只读查询原先只认普通文件，于是每次都显示「运行工具或资产不完整」，而「安装与修复」又因判据不同而不会改写该文件。
- 插件只读查询与 Python 动态库修复现在共用同一 guest 判据：在 Ubuntu 运行根内逐级解析符号链接（相对链接、guest 绝对路径和 `.l2s` 等本机运行根路径），只接受最终落在运行根内的普通文件；`/system`、`/proc`、`/sdcard` 等外部绑定、越界与循环链接仍判为未就绪。不论链接由容器内 proot 模拟的 root 还是外部 su 授予的 root 写入，判断方式一致。
- 修复流程只删除无法解析的悬空链接本身后写回随包库文件，已可用的链接不再被改写；插件就绪结论变化时在诊断记录中写明具体文件与原因（如 `libsqlite3.so.0:MISSING`），不再只有笼统提示。
- 新增纯逻辑 `GuestRegularFile` 与单元测试；该类加入受管运行时启动输入，运行时描述符随之重新生成。版本码提升为 217；DSHA 修订号保持 0.2.1-rc.3，内置 DSH 为 0.2.1-rc.5；构建与验收范围以本轮 CI run 与 Release 回执为准。
