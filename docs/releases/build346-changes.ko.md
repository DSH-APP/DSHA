# DSHA 0.2.1-rc.5-20261109.0700-dsh0.2.2-rc.1 / build346

- 화면 켜짐 유지와 절전 모드 강제 배타 (`d540dfe9d`): 순수 로직 `util/PowerModePolicy` 추가. 둘 다 기본 꺼짐이며 한쪽을 켜면 다른 쪽을 강제로 끄고 영속화·서비스·창 켜짐 유지를 동기화한다. 한쪽을 끄거나 같은 쪽을 다시 켜도 다른 쪽을 건드리지 않는다. 설정 페이지는 동기 가드로 프로그래밍 방식 `setChecked` 재귀를 막고, 다른 쪽을 강제로 끌 때 중영 토스트를 표시한다. 시작 시 과거의 "둘 다 켜짐"은 화면 켜짐 유지를 남기고 절전 모드를 끄는 것으로 정규화해 영속화에 기록하며 알리지 않는다. `PowerModePolicyTest` / `ConfigStorePowerModeTest`가 기본값·상호 비간섭·시작 분기를 검증.
- 실기기 메인 화면 활동 기록 M1 (`19d928f3c`): `ScreenActivityFeed`(약 120초 / 64건 메모리 링), `ScreenActivityEvent` / `ScreenActivityPolicy` / `ScreenActivityQuery`, `ScreenActivityRecorder` 추가. 휴대폰 작업 중에만 대상 전환·사용자 탭/스크롤·내용 변화·어시스턴트 동작을 기록하며 task-end·일시정지·접근성 서비스 연결 해제/재연결 시 즉시 지운다. 디스크·백업·진단 로그에 남기지 않는다. 민감 앱은 대상 전환만, 비밀번호 입력란은 "입력됨"만 남기고 IME와 자체 오버레이 이벤트는 버린다.
- 응답과 도구: `/app/ui/*`의 JSON 응답에 `recentActivity`(이전 응답 이후 최대 3건)를 자동 첨부. `GET /app/ui/history?since=<순번>&limit=20` 추가(기본 20, 최대 100, `since`는 `nextSince`로 이어 읽기, M1은 이미지를 반환하지 않고 `frames`는 빈 배열). 내장 `dsh-computer-use-android`에 `android_history` 도구를 추가하고 `/app/help`와 동기화. 접근성 설정에 `typeViewClicked|typeViewScrolled`를 추가하고 동작 실행기는 `ASSISTANT_ACTION`을 명시 기록하며 1.5초 디스패치 창으로 user/assistant를 구분한다. 대상 비교·자격 증명 TTL·확인 정책 등 실행 시 가드 의미는 그대로다.
- 관리 런타임 업데이트: `DshaAccessibilityService` / `HttpShellService` / `screen/ScreenActionExecutor` / 새 `screen/ScreenActivityRecorder` / 접근성 설정과 내장 플러그인 `server.cjs` 변경으로 `runtime-descriptor`가 스크립트에 의해 `7b1ca97d`로 재계산된다. fixed-inputs는 고정된 20261105e를 유지하고 내장 `dsh-web-mobile`은 업스트림 3.3.1과 기본 활성을 유지한다.
- 버전과 범위: versionCode 346(공개된 build345 / `917295a5a` 기반), DSHA 리비전은 `0.2.1-rc.5`, 내장 DSH는 `0.2.2-rc.1`. 이번 배치는 위 두 축만 포함하며 장치 shell 화이트리스트를 바꾸지 않고 실행 시 가드도 완화하지 않는다.
- **미검증 / 미검수**: 실기기 검수 미실시: 두 스위치의 상호 강제 끄기와 토스트, 과거 "둘 다 켜짐"의 시작 정규화, 실제 휴대폰 작업 중 기록/삭제, `recentActivity`와 `/app/ui/history` / `android_history`의 실제 응답, 민감 앱과 비밀번호 입력란 마스킹을 실기기에서 항목별로 확인하지 않았다.
