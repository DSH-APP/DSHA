## 问题与修复

### 覆盖更新后插件仍报错

之前只要已安装环境存在 `.runtime-descriptor.json`，`RuntimeTools.prepare` 就会提前返回。这会让覆盖更新后的插件管理、内置插件和共享依赖链接继续使用旧文件；`.runtime-links-cache.json` 也只看目录时间戳，没有绑定 APK 带来的受管资产。

现在的处理是：

- 新增 `managed-assets-v2` 标记，内容绑定实际 `runtime-descriptor.json` 的 64 位运行时身份。
- 已登记运行时在身份匹配但标记缺失/过期时，会重新安装 DSHA 自有管理脚本、App Integration 和内置插件文件，然后核验共享 `node_modules` 链接。
- 运行时身份变化时，仍走已有的受管运行时事务、隔离试运行和健康回执，不在普通启动中跨版本偷换运行树。
- 链接缓存升级为 version 2，同时记录 `managedAssetId`；旧缓存或身份不同时必须重新检查，不会直接命中。
- 插件注册和原生插件管理都通过同一准备入口，避免一个页面已更新、另一个页面仍运行旧脚本。

以上操作只覆盖 DSHA 自有受管文件。用户会话、`settings.yaml`、凭据、工作区、profile 选项和第三方插件原件不在覆盖清单内。

### 旧缓存与图标不显示

- 覆盖更新后调度空闲清理。它只处理精确白名单中的可重建目录：插件链接缓存、DSH/Cordis 缓存、受管内置插件的 `.cache` / `dist-cache`，以及 WebView 的 Cache / Code Cache / GPUCache。
- 删除逻辑使用 `lstat` 语义且不跟随符号链接。Cookie、Local Storage、IndexedDB、会话、配置、凭据、工作区和插件源码均不在清理列表。
- AndroidManifest 改用 `@mipmap/ic_launcher_v137`，并显式设置 `@mipmap/ic_launcher_round_v137`；所有密度 PNG 与 Android 8+ adaptive icon 均已打包。新资源 ID 配合版本码 137，让 MIUI/Launcher 将本次安装视为需要重新解析的图标资源。
