## 2. 功能实现

- App 策略新增 `DeviceShellPolicy.Mode`：`strict`（默认）/`relaxed`/`full`；非法配置回落 `strict`。
  `Plan.kind=SHELL` 保存原始命令和档位，只有 root 特权路径能消费。
- `RootShellMain` 只接受显式 `operation=root-unrestricted`；`ShellService.execUnrestricted()`
  不在 AIDL 接口里，并再次校验 uid 0、命令长度、NUL、生命周期，执行 `/system/bin/sh -c`。
- `/device/execute` 的 SHELL 计划只交给真实 root：本机 `su`，或明确 `forceAdb` 时由 guest
  `su -c`；Shizuku 通用执行器不接收 SHELL 计划，root 不可用时不降级。
- `adb-shell.py` / `device-shell-policy.py` 接受并复核 SHELL 计划（`version=1`、UTF-8 ≤ 16384 字节、
  无 NUL、`mode∈{relaxed,full}`、`rootOnly=True`、`su=True`），SMS 痕迹在 guest 侧再拒一道。
- 三档都保留短信原生授权闸门；`relaxed` 额外拦截格式化/刷机/写块设备/重启/关机/SELinux/
  清应用数据和递归删除存储根或一级目录；`full` 只保留原生闸门与 root 身份检查。
- UI：设置 → 设备能力授权 → Root 卡片新增档位摘要和“更改”；选择放宽/完全放宽需要二次风险确认。

## 3. 本轮发现并修复的 UI 缺陷

首装 build207 在真机点“更改”时，只弹出说明文字和“取消”，三个档位不可见、无法选择。
原因是 Android/Material 对话框同时设置 `setMessage` 与 `setSingleChoiceItems` 时只渲染 message。
已改为 `setItems`，并把三档说明并入选项文案：

- 严格（默认）· 仅放行白名单内的命令
- 放宽 · 允许任意命令，仍拦截不可逆操作
- 完全放宽 · 不按命令内容拦截

修复前后截图在交付目录 `shots/before-fix-no-options.webp`、`shots/after-fix-three-options.png`。
修复后以同包名、同版本、同签名重装，`base.apk` SHA 与签名产物一致，应用数据保留。

通过测试包自己的 3092 桥（`X-Token`，不经过正式包 3091 桥）执行 `/device/execute?su=1`：

| 档位 | `settings put global …` | 复合脚本 `echo relaxed-ok; id -u` | `shutdown -r now` | `content query --uri content://sms` |
|---|---|---|---|---|
| strict | `[POLICY_BLOCKED]`/126 | 白名单外脚本拒绝 | 拒绝 | `[POLICY_BLOCKED]`/126 |
| relaxed | root/0 | 输出 `relaxed-ok`、`0` | `[POLICY_BLOCKED] 禁止关机`/126 | `[POLICY_BLOCKED]`/126 |
| full | root/0 | 允许；`echo mkfs.ext4 …` 也允许输出 | 不按内容拦截 | `[POLICY_BLOCKED]`/126 |

strict 下 `id -u` 仍走 root 通道并返回 0；三档切换后 UI 摘要同步；最后已切回 strict。
