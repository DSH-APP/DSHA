# DSHA 0.2.1-rc.5-20261109.2300-dsh0.2.2-rc.1 / build350

- أدنى قدر من أدلة النوافذ وتلميح قابل للتنفيذ عند تعدد النوافذ في الشاشة الافتراضية (T98، `33ceab2c7`): ردود `FRAME_NOT_READY` المقسمة من `see` وردود «النافذة غير متاحة» من tree / node / editor / anchor تحمل الآن لقطة نافذة دنيا للقراءة فقط عندما تتمكن إمكانية الوصول من قراءة النوافذ (`util/VirtualScreenWindowEvidence`): عدد نوافذ التطبيقات / النظام / إدخال النص، و`focusedWindowId` / `activeWindowId`، و`windowAmbiguous`، وعند وجود نافذة واحدة فقط displayId / id / type / layer / bounds / focused / active / عنوان / حزمة النافذة الهدف. تُزال أحرف التحكم من العناوين وتُطوى المسافات وتُقصّ إلى 64 نقطة رمز، ولا تُحفظ الحزم إلا بعد التحقق من صيغة اسم الحزمة، وتُحذف كل قيمة غير صالحة أخرى. لا تحتوي اللقطة على نص العقد أو محتوى عناصر التحكم أو لقطات الشاشة أو قائمة النوافذ الكاملة. يميّز `NO_UNIQUE_APPLICATION_WINDOW` بين سببين بالعدد: عدة نوافذ تطبيقات جنبًا إلى جنب (شاشة مقسومة / نافذة عائمة) → `reason=VSCREEN_WINDOW_AMBIGUOUS` و`nextAction=ASK_USER_TO_CLOSE_SPLIT_SCREEN`؛ نوافذ النظام / إدخال النص فقط دون نافذة تطبيق → `reason=VSCREEN_NO_WINDOW` و`nextAction=LAUNCH_APP_FIRST`. يُستخدم الدليل فقط لتفسير الفشل والخطوة التالية و**لا يشارك أبدًا في التفويض أو اختيار النافذة أو إعادة المحاولة**: المسار الدلالي ما زال يقبل فقط النتيجة الوحيدة من `VirtualScreenWindowPolicy.selectDetailed`، ومسار المرساة ما زال يقبل فقط windowId الذي حملته الملاحظة الأصلية (تكرار المعرّف نفسه يُرفض كما قبل بـ `ANCHOR_WINDOW_AMBIGUOUS`)، ولا يُنتقل تلقائيًا إلى نافذة أخرى بسبب «تعدد النوافذ».
- مستويات الشاشات الحساسة وتسليمها في الشاشة الافتراضية (T119، `dc6f9642e` / `c3a4e3c30` / `241e06159`): أُضيف `util/SensitiveScreenClassifier` و`util/SensitiveScreenPolicy` (منطق خالص) لتصنيف الشاشة كاملة بشكل محافظ فوق حاجز التركيز على كلمة المرور الصارم في 6.1 (كلمة المرور / رمز لمرة واحدة / الدفع / أمن النظام / حساس لكن الشجرة غير مقروءة `SECURE_UNKNOWN`)، والوضع الافتراضي `ASK` لكل فئة؛ ويمكن ضبط كل فئة على `HANDOFF` — إيقاف المساعد مؤقتًا قبل إرسال أي إدخال، وإلغاء الطلبات الجارية وإسقاط الملاحظات، وإرجاع `ok:false` / `state=NOT_SENT` / `error=SENSITIVE_SCREEN_HANDOFF` / `sensitivity=<الفئة>` / `readOnly:true` / `retryable:false` / `nextAction=HANDOFF_TO_USER`؛ وبعد استئناف المستخدم يجب أن ينفّذ المساعد `see` من جديد ولا يعيد التشغيل تلقائيًا. `OFF` يعطّل مستويات الشاشة الكاملة فقط ويعود إلى سياسة التأكيد العادية. يبقى قراءة وكتابة نص كلمة المرور محظورين صراحة في طبقة الإدخال ولا يرفعهما أي مستوى أو تأكيد. `ALLOW_ALL` وقاعدة `ALLOW` لكل تطبيق تتجاوز التأكيدات العادية فقط ولا يمكنها تجاوز `ASK` للفئة الحساسة؛ والتأكيد الحساس لمرة واحدة و**لا يُكتب في ذاكرة «السماح لهذا التطبيق في هذا الدور» لخمس مرات** (التطبيقات العادية ما زالت تُسأل كل 5 مرات). أُضيف في «الإعدادات ← صلاحيات قدرات الجهاز ← رصد الشاشة» صف مستقل «تسليم الشاشات الحساسة» لاختيار السؤال / التسليم لكل فئة، مع قائمتين بأسماء حزم دقيقة (التسليم الإجباري والتطبيقات الموثوقة؛ فارغتان افتراضيًا، وبحد أقصى 64 لكل منهما، ومتضادتان، والبيانات التالفة تعود إلى ASK). يجمع `policyRevision` للشاشة مراجع `screen_confirmation_v1` و`sensitive_screen_v1`، لذا يُبطل أي حفظ التأكيدات القديمة والطلبات الجارية، مع حد أدنى أحادي داخل العملية؛ ونقاط النهاية التي تحقن الإدخال تعيد التصنيف بعد التأكيد وقبل الإرسال — الشاشة غير المقروءة تُرجع `SENSITIVE_SCREEN_UNVERIFIED` وتغيّر الفئة يُرجع `SENSITIVE_SCREEN_CHANGED`، وكلاهما غير مُرسل ويحتاج إعادة ملاحظة.
- إصلاحات الجزيرة (كبسولة الإشعار) (PR #12، `ccd4b81d7`، مدمج في main): تُبقي الحالة الموسّعة مؤشر الدور في subText وحده، ولا يكرر النص «الدور N»، ولا تُكتب قيمة الثواني كل ثانية أثناء التشغيل، فتبقى بصمة المحتوى مستقرة ولا تعود عمليات إعادة بناء الإشعار بسبب نبضة القلب تبتلع نقرات أزرار الخيارات؛ وأعطال الإجابة في الخلفية يجب أن تكون مرئية — HTTP غير 200، أو إرسال فارغ، أو خيارات منتهية، أو مدخل منتهٍ تستدعي Toast (مع حالة HTTP ورمز خطأ الخادم، مثل `HTTP 409 NO_WAITING`) وتوجّه المستخدم لفتح المحادثة، ويُسجَّل في سجل التطبيق `TASK_ANSWER_REJECTED <status> <body>`؛ وعند فتح المحادثة من الإشعار أصبح المعيار وجود صف خيارات فعلي في بطاقة السؤال (`Mbwy4a_optionRow`) — فحاوية الخيارات `Mbwy4a_options` تُرسم لكل بطاقة وتكون صحيحة دائمًا — ومع وجود خيارات لا يُسرق التركيز وتبقى لوحة المفاتيح مغلقة حتى لا يُدفع زر «إرسال» أسفل البطاقة خارج الشاشة. أُضيف إلى `docs/island-status.md` جدول حالة التحقق للمنصات: Android الأصلي 16 و16 QPR1+ وHyperOS وColorOS 16 وOriginOS 6/7 مصنّفة بندًا بندًا (دعم حسب فرع المنصة / دعم بالكود دون تجربة على الجهاز / ملاحظة مساهم على الجهاز غير مُودعة / معلومات عامة دون تجربة على الجهاز / دعم متوقع دون سجل على الجهاز)، وOriginOS 7 (Android 17) مُدرج صراحةً دون سجل تشغيل على الجهاز في المستودع.
