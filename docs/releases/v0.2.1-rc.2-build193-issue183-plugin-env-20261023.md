本次 Standard 更新将正式受管 DSH 精确升级到 **0.2.1-rc.3**，并补充 issue183 相关无障碍读屏调度、插件依赖命令及启动诊断修订。软件检查、设备边界和交付范围见下文。

- 常规文件名仍为 `dsha-0.2.1-rc.2.apk`；文件名中的 rc.2 不代表内置正式 DSH 仍为 rc.2。

## 本轮变化

**issue183 相关应用侧调度。** 无障碍配对读屏移至专用工作线程，只保留一个正在执行的读取和一个最新待处理事件；连接 epoch、取消状态和最终许可检查阻止旧服务或已取消请求继续派发。服务断开与撤销不再等待许可回调持有生命周期锁。树展开采用时间、节点及深度预算；截图回调队列有界，饱和时不把重处理退回系统回调线程。增加有限的无障碍服务生命周期诊断。这些措施约束应用自己的工作和排队，不能中断已经进入的 Android Binder 调用；已消费许可后的未知执行结果仍不重放。不能据此宣称 Android16 的系统或设备故障已修复。

**插件 pnpm 参数修正（V3）。** 实际原因是 pnpm 10 对 `view/info/show` 的 npm 转派依赖命令位于参数首位；此前受管策略参数放在命令之前，还进入元数据预检，使 pnpm 尝试执行名为 `view` 的程序。V3 仅把精确匹配的受管参数后缀移到真实命令及其参数之后，保留调用方的可执行程序前缀、registry、来源 spec 和已开放的生命周期脚本设置。它没有将该问题归因为网络失败，也不通过关闭 Git prepare 或其它已获准脚本来规避问题。

**正式 DSH rc.3。** 直接 DSH 依赖采用精确 rc.3 版本与新锁文件；干净解析和安装使用正常 peer 校验，没有使用 `--force` 或 `--legacy-peer-deps`。本地补丁按 rc.3 的真实模块与完整补丁顺序重新核对，并保留上游新增代码。已记录的宿主数据夹具覆盖部分存储、会话、附件、凭据引用与 Profile 读写重开路径；它们不是用户设备数据完整比对，也不授权运行时回退。

**独立应急同步升级 rc.3，并复用包内相同归档字节。** 按本轮明确决定，应急 DSH 的独立 pin 也推进到 `0.2.1-rc.3`，归档 SHA-256 `d77261bf677a83c2440aab7a60cacf9c95876b59777b74f9de4fa6be9c2ba514`，与正式归档逐字节相同，从而允许 APK 只存放一份物理归档。应急锁、运行根、HOME 和工作区继续独立，不借正式安装后的 rootfs。应急浏览器配方按自身版本单独保存并绑定摘要，历史 rc.2 配方保留。rc.3 新增入口定制依赖已禁用的插件管理服务，因此仅在应急 Profile 同时禁用该入口，仍只有五个受控工具，HTTP 不能确认写入，修复继续要求原生确认与事务屏障。隔离候选已在 rc.3 raw/受管宿主运行时通过真实扩展 prepare、应急工作区、Chromium 输入和正常停止检查；合成临时密钥检查未发现写入文件、会话、浏览器持久存储、cookie 或日志。本轮精确APK已核对同摘要去重映射，最终字节与摘要见下文。
