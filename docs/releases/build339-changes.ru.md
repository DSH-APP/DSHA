# DSHA 0.2.1-rc.5-20261108.0300-dsh0.2.2-rc.1 / build339

- Второе подтверждение при переключении режима распознавания экрана (T113, `29c5028b`): при выборе физического или виртуального экрана в «Настройки → Разрешения устройства → Распознавание экрана» сначала показывается подтверждение `DshaDialogBuilder` (объясняет область чтения и возможность отзыва), и переключение происходит только после подтверждения. Успех, ошибка, ожидание очистки и повторный выбор получают строчный статус и toast; подтверждение не пропускается режимом «разрешить всё». Новый `ScreenModeFeedback` — единственный источник правила подтверждения, названий режимов и текстов результата; повторные нажатия во время переключения игнорируются; диалог прокручивается на коротком экране 320 dp и при шрифте 1,3×.
- Компактная страница запуска аварийного DSH и одноуровневый поток подтверждения (T92, `da0b9b71`): объяснение первого экрана сжато до одной строки-вывода + ⓘ; статус и три основных действия (запуск / вход / остановка) объединены в одну карточку; временный API-ключ по умолчанию свёрнут, диагностика / журналы / резервная копия / возврат на страницу восстановления убраны в «Ещё»; статус и результаты действий появляются через затухание UiMotion. В поток подтверждения добавлен `RecoveryRepairSheet`: выбор и предпросмотр переключаются в одном диалоге, «назад» поднимает ровно на один уровень, повторные нажатия при генерации предпросмотра отключены, выполнение / отказ остаются в прокручиваемом содержимом (короткие экраны и крупный шрифт прокручиваются), при пустом ID предложения нет входа к выполнению; заголовок аварийного Web становится однострочным: заголовок + короткое действие «Предложение исправления» + значок перезагрузки + разделитель.
- Проверка фокуса пароля перед записью текста ассистентом на виртуальном экране (T97 P1, `8b82e4f7`): быстрый путь чистого ASCII в `/app/vscreen/type` выполнял `input text` напрямую в Core и обходил проверку пароля в специальных возможностях. Добавлены `VirtualScreenTextInputPolicy` (жёсткий отказ при фокусе пароля, разрешение безопасного фокуса, fail-closed при наличии семантического канала, но нечитаемом фокусе, сохранение документированной ASCII-возможности с пометкой `passwordFocusChecked=false` при отключённых специальных возможностях) и `VirtualScreenPasswordProbe` только для чтения (повторно проверяет единственное окно приложения на текущем дисплее через ACTION_AUTHORITY и читает `FOCUS_INPUT`; при смене окна возвращает `SCREEN_TARGET_CHANGED` без отправки). Перед ASCII-отправкой выполняется проверка: пароль возвращает `PASSWORD_INPUT_UNAVAILABLE` (`state=NOT_SENT`, `nextAction=REPORT_TO_USER`), нечитаемый фокус — `PASSWORD_FOCUS_UNVERIFIED` (`retryable`, `SEE_AGAIN`); также заблокированы не-ASCII type и запись в узлы пароля через node `set_text`; нативная панель работает по отдельной аренде и не затронута. Кнопки «всё равно разрешить» нет.
- Исправление CI-шва T97 (`d16b0c14`, тестовая инфраструктура): в `VirtualScreenInput` добавлен экземплярный флаг forced-available, чтобы тестовые экземпляры не перехватывались проверкой хоста `/system/bin/input` (на GitHub runner этого файла нет, из-за чего юнит-тесты T97 падали); в production флаг не ставится, реальное отсутствие команды по-прежнему отклоняется, `systemCommandExists` не ослаблен.
- Пресеты белого списка спецификаций виртуального экрана (T99, `c33f358d`): по умолчанию остаётся 1008×1792@320 (16:9 / 504×896 dp), добавлена совместимая базовая линия compat-720 = 720×1600@320 (20:9 / 360×800 dp); неизвестные / пустые / превышающие бюджет спецификации откатываются к умолчанию, произвольные размеры и dpi не принимаются. Manager при создании и повороте передаёт в Core только preset id и ориентацию, Core разрешает белый список и применяет dpi, считывая обратно preset / density / logical размеры; `VirtualScreenDisplaySettings` сохраняет выбор, на странице виртуального экрана появляется радиогруппа «Размер экрана», влияющая только на следующее создание или пересоздание при повороте, но не на идентичность текущего кадра и входной шлюз. Бюджет наблюдения остаётся 2 кадра / 24 MiB, два кадра 1440×2560 (~28,1 MiB) в белый список не входят; проверка compat-720 на устройстве не проводилась.
- «Действие как наблюдение» и settle по событиям для физического экрана (T105, `c6a2ea84` / `c94df74d` / `00dd7a90`): конечные точки действий `/app/ui` принимают необязательный `observe=1` — после `COMPLETED` тот же запрос выполняет settle (первое событие доступности ≤800 мс, тишина 250 мс, общий предел 2,5 с; прерывается отменой задачи и дедлайном, без занятого опроса) и перечитывает дерево, возвращая в ответе новые `treeId` / `nodeId`, текстовое дерево и метаданные settle; координатные действия по-прежнему не возвращают скриншот, а для координатных учётных данных всё ещё нужен отдельный скриншот. Без параметра поведение прежнее; сбой наблюдения пишет только `observationUnavailable` и не меняет статус действия; UNKNOWN не повторяется; отказы из-за истёкших учётных данных прикладывают новое дерево текущего экрана для повтора с новыми данными. Встроенный `dsh-computer-use-android` получает необязательный `observe` в семи инструментах действий (при пропуске MCP-сервер подставляет `observe=1`, `observe:false` отключает; добавляются только необязательные поля, строгая проверка аргументов не ослаблена). Последовательные вызовы `/app/sense/state` по умолчанию возвращают дельту: изменение более чем на треть, смена окна / размера / фокуса / источника / состояния обрезки, смена поколения или цели и `full=1` дают полный снимок, без изменений возвращается `mode=same` одной строкой; в ответ добавлены `mode` / `deltaReason` / `previousSid` / `changedElements`, `format=v4-preview-3`. `k***` остаётся номером позиции в порядке чтения, действия по-прежнему используют одноразовые аренды `treeId` / `nodeId`. `/app/help` обновлён на китайском и английском.
- Руководство по несовпадению версий пользовательских плагинов после обновления рантайма (T93, `bebc01b4`, документация): обновления APK / DSH поверх не перезаписывают сторонний список плагинов профиля пользователя или `node_modules`; проверка совместимости DSH пропускает несовместимые bundle и отключает соответствующие записи по `engines.dsh` / диапазонам peer `@deepseek-ai/dsh*` (fail-safe, без удаления и перезаписи). Решение — переустановка через управление плагинами и точные исключения версий в `compatibility.json`, без ручного редактирования профиля; также объясняется, что повторяющиеся строки запуска от нескольких cordis entry одного bundle не являются повторным импортом модулей (StartupTrace дополнительно удаляет соседние идентичные строки).
- Оценка дизайна двух путей наблюдения физического экрана (T107, `ee5adfde`, документация): рекомендуется направление C (привилегированное зеркальное чтение плюс обнаружение физического ввода через evdev); обнаружение действий пользователя не зависит от кадров, зеркальные кадры никогда не выдают координатные / action-учётные данные, а лёгкий вариант A остаётся непривилегированным резервом с `userActivity=UNKNOWN`; разрешения по умолчанию выключены, активируются на задачу, отзываемы, отказ fail-closed. В этом выпуске только оценка: продуктовый код не реализован, проверка захвата кадров / evdev / разрешений каналов на устройстве не выполнялась.
