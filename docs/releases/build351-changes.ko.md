# DSHA 0.2.1-rc.5-20261110.0400-dsh0.2.2-rc.1 / build351

- 실제 화면 특권 실행 Phase A(T130, `4e8c80e0e`, 실험적, 기본 꺼짐): 관리형 `app_process` 특권 Core를 재사용해 display 0을 `VIRTUAL_DISPLAY_FLAG_AUTO_MIRROR`로 미러링하고 ImageReader로 프레임을 캡처합니다(`maxWidth` 320–1920 / `jpegQuality` 30–90 / `maxFps` 1–10, 기본값 1280 / 60 / 6; 거의 검은 프레임은 `SECURE_OR_BLACK`으로 표시하며 프레임은 디스크나 로그에 남기지 않음). 고정 동사 tap / swipe / key(3 / 4 / 66 / 67)를 주입하며 **경로 전체가 접근성에 의존하지 않습니다**. `/app/priv/{info,frame,config,tap,swipe,key,benchmark,close}`와 `PhysicalScreenManager` / `PhysicalScreenCore` / `PhysicalScreenDisplaySession` / `PhysicalScreenLauncher`를 추가했습니다. 동작 응답은 한 번의 왕복으로 새 프레임과 새 관찰을 반환하고, 자격 증명은 30초·1회용·generation 및 대상 패키지에 바인딩되며 `EXECUTION_UNKNOWN`은 재생하지 않고, 실패는 fail-closed로 접근성으로 조용히 대체하지 않습니다. 네 가지 게이트: 설정 → 기기 기능 권한 → 특권 실행(`privileged_execution_v1`, 네이티브 승인, 기본 꺼짐, 철회 가능, 백업·환경에서 복원하지 않음, 끄면 Core 연결 폐기), 현재 휴대폰 작업 신원(`taskSessionId` / `turnId`, 먼저 `/app/ui/task-begin`), 검증 가능한 대상 패키지(`PRIV_TARGET_UNVERIFIABLE`), 민감 앱 거부(`PRIV_SENSITIVE_TARGET_UNSUPPORTED`)와 `ScreenConfirmationPolicy.allows`. Phase A는 동작별 네이티브 확인 창을 띄우지 않으므로 ASK는 항상 `NOT_SENT`(`SCREEN_CONFIRMATION_REQUIRED`)이고 "모두 허용" 또는 앱별 `ALLOW`만 통과합니다. `/app/priv/benchmark`는 N회의 전체 동작 체인을 실행해 App 측 `roundTripMs`와 Core 측 `inputMs` / `frameWaitMs`의 p50 / p95 / max(최근 순위, 보간 없음)를 `accessibilityRequired:false`와 함께 보고합니다. `waitMs`는 0–500, `n`은 1–20이며 `n × (waitMs + 400) ≤ 8000`입니다. 회전 / 분할 화면 / 해상도 변경 시 미러를 재구축하고 `generation`을 바꾸어 모든 이전 자격 증명을 무효화합니다. 검은 프레임 판정은 48픽셀 샘플링 휴리스틱으로 호출자에게 알려 줄 뿐 내용 인식이 아닙니다. 문서는 `docs/privileged-screen-core.md`를 보세요. 단위 테스트 27건 추가(정책 / 라우트 / 런처 / 매니저).
