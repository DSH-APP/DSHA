# PR #94 的处理建议

审阅对象：[PR #94](https://github.com/DSH-APP/DSHA/pull/94)，读取头为 `fix/compact-diagnostic-logs` 的两次提交。建议保留“只压缩显示副本、保留磁盘原始记录”的方向，按当前源码重新整理后集成。

原实现需要先处理以下问题：

1. **正则多转义了一层。** 原 `LogCompactor.java` 把数字模式写成 Java 的 `"\\\\d"`，运行时匹配的是反斜线和字母 d。时间头和记录边界无法按预期识别。build161 使用真实时间、秒数与多条记录的断言约束这一行为。
2. **不同数字并不等于重复。** 端口 3090/3091、退出码和文件路径编号都可能是关键差异。只去掉已识别的时间前缀，正文完全一致且连续时才合并；保留次数和首末时间。跨越其它记录不归并，保留事件顺序。
3. **必须在截短前比较整条记录。** 两次输出可能只有中间一行不同。先比较完整正文，再各自缩短，不能先截头尾再判为同一次。
4. **最终截断不能再次丢掉中间的失败原因。** 显示摘要先安排失败线索，再提供头尾上下文；字符上限包含省略标记本身，Unicode 代理对不能被切开。超过容量时明确标记省略，不能承诺有限摘要保留无限条错误。
5. **文案和日志职责分开。** 省略、摘要和上下文提示提供中英文目录；第三方输出只脱敏和缩短。原始写入、事务阶段、失败状态和成功判断不因摘要改变。

本地已集成冷安装、操作记录、上次启动失败和维护页显示入口。原 PR 未在 GitHub 合并或评论。验证和本地 APK 交付范围见 build161 发布报告；定向回归覆盖数字差异、记录碰撞、时间范围、错误优先级、超长行、Unicode 和短提示。
