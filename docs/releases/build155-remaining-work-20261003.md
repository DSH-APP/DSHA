# DSHA build155 未完成事项清单

整理日期：2026-10-03  
对应版本：`0.2.6-20261003.1704-dsh0.2.0-rc.2`，版本码 **155**。

build155 的本地修订、两版正式 APK 和源码交付已经完成；仍未完成的是部分架构降债、真机验收、线上发布及历史来源核实。**“236 项已核对”不代表“236 项全部修复并验证完毕”，目前也没有充分证据证明技术债低于 20。**

本清单依据 [build155 最终交付报告](v0.2.6-build155-20261003.md)、[236 项最终台账](../audits/build155/execution-ledger-final.json)及[架构评估](../audits/build155/architecture-assessment.md)整理。

## 1. 架构上仍可继续重构的部分

| 剩余内容 | 当前做到哪里 | 尚欠什么 |
|---|---|---|
| `ProotBootstrap` 职责仍过多 | 已拆出冷安装、解压、离线工具安装和公共输出收集 | 插件命令、数据维护、PTY 入口仍集中在原类 |
| `HttpShellService` 仍较庞大 | 已建立明确路由表及处理器映射 | 各端点的具体动作仍在服务类内部，可继续拆分 |
| 全局状态与依赖耦合 | Web 状态已归应用拥有，移除了 `MainActivity.current` 强引用 | 运行时端口、虚拟屏等仍有全局依赖，尚未完成全面解耦 |
| rc1 遗留迁移流程 | 有缓存、异步核验及历史数据保护 | `prepare/finalize` 仍进入每次启动链，尚未建立完整退出策略 |
| 移动插件 HTTP 压缩 | 大响应和多次写入已改为流式处理 | 小于等于 1 MiB 的完整响应仍有同步压缩；全局 HTTP 钩子的长期影响未实测 |

这些属于真实的结构或性能取舍。尤其 rc1 流程，后续可以减少重复工作，但需要继续保留旧数据读取和迁移保护。

## 2. 关键功能仍欠 build155 真机验收

本轮按此前要求没有操作手机，因此以下内容不能说“已经保证没有问题”：

- **覆盖更新与数据保留**：包名、版本码、E7E3 证书及 v1/v2/v3 签名已核对；尚未实际覆盖旧版本并检查对话、配置、插件和文件。
- **后台输出卡住**：尚未验证前后台反复切换、息屏、长期 Doze 后，输出能持续或恢复。这是优先级最高的缺口之一。
- **插件实际体验**：读取、启停、更新、用户修改后重启的手机行为，以及耗时改善幅度，尚缺实测。
- **Web 与设备工具**：暂停请求、截图工具、真实虚拟屏，以及旧 WebView 到 Gecko 的回退，尚缺设备端验证。
- **备份与存储**：无密码 tar.gz 已实现，但实际 SAF 导出/导入、图片草稿配额、重建峰值空间和 Android FUSE 行为尚未验证。
- **平台兼容**：Android 6/7、16 KiB 页设备、不同 Root/Shizuku/ROM、VPN 和 private DNS 尚未完成矩阵验证。
- **平台相关风险**：特权文件操作的检查与执行间隙、隐藏 API、进程身份读取及日志分享流程仍需进一步证据，不能宣称风险完全消除。

台账有 **7 项明确标为“需要设备证据”**；其他软件测试通过的条目，也可能保留上述设备范围限制。源码层面发现特权文件操作的检查与执行间隙，不等于已经证明在实际 Android 共享存储中可被利用；此处仍需核验真实文件系统与权限条件。

## 3. 软件验证仍有边界

- 两版各 **1042 项单测，1041 通过、1 项跳过**；跳过项没有计为通过。
- Release Lint 已无 Error/Fatal，但 Standard **307 条警告**、Low **240 条警告**尚未全部清零，需进一步分类处理。
- Linux 原子发布测试已实际通过，但使用的是 **tmpfs**，尚未证明持久磁盘、Android FUSE 或掉电恢复行为。
- **线上 CI 和全部外部模型服务矩阵**尚未执行。

## 5. 两项历史证据仍无法补齐

- `ShellService.java` 带有 CFR 反编译标注，**外部源码来源及授权仍未明确**。
- 两份旧发布说明中的 SHA-256 只有 **63 位**，记录已标明无效，但尚无可信原件或官方旁证补回真实摘要。

## 6. 需要继续保留的功能契约

历史备份读取、未知进程退出时的停止屏障、原件保留和最终完整性复核，都是有意保留的功能契约，应继续维护。不能为了降低技术债评分而删除这些保护机制。

## 7. 后续建议顺序

1. 验证同签名覆盖更新、用户数据保留和后台输出卡住。
2. 实测插件管理、启停与修改后重启，以及暂停请求和截图工具。
3. 按调用边界和测试证据继续架构拆分，并分类处理 Lint 警告。
4. 完成对应版本的 GitHub 源码与 Release 发布，以及 dsha.cc 部署和下载验收。
5. 持续补齐平台矩阵、来源证明和历史摘要证据，按实际证据更新状态。

继续只做源码审查，无法补上真实设备缺口。每项完成后应记录实际执行范围和回执；不能把未执行的设备或服务矩阵标为通过。
