# DSHA 0.2.1-rc.5-20261107.0140-dsh0.2.2-rc.1 / build335

- build334 실기기 결론(P0, 미통과): 333→334 첫 덮어쓰기 설치가 실패했고 두 기기 모두 trial 마무리에서 `TRIAL_PROCESS_UNCONFIRMED`에 멈췄습니다(트랜잭션은 `c4299668…` 등). 런타임 업데이트 트랜잭션이 반커밋 상태로 남고 유지보수 장벽이 시작을 막았습니다. 이후 유지보수 페이지에서 유지보수를 한 번 더 실행하자 334/READY와 데이터 무사고로 복귀했습니다. build334는 "첫 시도 실패, 두 번째 사용 가능"으로 기록하며 통과로 쓰지 않습니다. 이 빌드는 그 현장 결론에 따라 첫 실패 경로와 복구 후 상태를 고칩니다.
- trial 마무리에서 종료되지 않은 guest를 유계 강제 종료(T103, `a5168f99`): `manager.stop()`이 비어 있지 않은 값을 반환해도 즉시 `TRIAL_PROCESS_UNCONFIRMED`로 판정하지 않습니다. 먼저 이번 런처를 3초 동안 유계 대기하고, `WebProcessManager.forceStopTrialGuest`가 이번 라운드의 기록, 유일한 profile, 저장된 출생 신원을 연속 읽기로 재확인한 뒤 이번 guest에게만 SIGKILL을 보내고, 이어서 기록된 정지와 전역 무-WEB 검증을 다시 실행합니다. 그래도 확인되지 않을 때만 실패로 처리하고, 마스킹된 상세를 내보낼 수 있는 작업 기록과 기록 디렉터리에 씁니다(성공한 시험의 마무리 실패는 `failure.json`, 복구 경로는 `recovery-stop.json`, 기존 실패 상세는 덮어쓰지 않음). `TrialRecovery`도 같은 순서를 써서 `recover-maintenance` 한 번으로 guest 미종료에 멈춰 있던 이전 trial을 닫을 수 있습니다. 강제 경로는 출생 신원 누락, PID 기록 불일치, 두 관측 사이 변화에서 fail-closed이며 맨 PID나 이름으로 스캔하지 않습니다. 유지보수 페이지는 `pendingTrial`의 2초 캐시를 없애고 `onResume`에서 `BackupTask` UI 캐시를 버리므로 외부 복구가 끝나면 곧바로 "이전 런타임 업데이트 대기"로 돌아갑니다.
- 복구 시 출생 신원 재확인과 신원 증거 보충 기록(T100, `903974db`): 시작 복구와 전후면 재확인은 `observeRecoveredSession`을 공유합니다. 엄격한 PID / 신원 파일 검증이 UNKNOWN이면 전체 출생 증명(boot / PID / 출생 시각 / 명령줄 / UID / generation+instance+nonce)으로 내려가고, 엄격 검증이 LIVE / EXITED를 내면 내려가지 않으며, 증명판을 읽지 못하면 fail-closed를 유지합니다. 재접속 성공 후 검증된 출생 신원으로 `/root/.dsha-web.pid`와 `.dsha-web.identity`를 보충 기록하고(pid 기록이 다른 번호를 가리키면 그대로 둠), 신원 파일이 오래되었거나 은퇴된 뒤 시작할 때마다 `IDENTITY_UNKNOWN`으로 떨어지는 코드 공백을 메웁니다. 최종 UNKNOWN은 내보낼 수 있는 진단 `WEB_SESSION_RESTORE_FAILURE`(stage / reason / attempts)를 쓰고, `IDENTITY_UNKNOWN` 안내는 "정지 → 일반 정지로 확인할 수 없을 때 신원 검증으로 강제 종료 → 재시작 후 재확인"이라는 다음 단계를 제시합니다.
- 가상 화면 미리보기 개편(T96, `71010565`): 기본으로 172dp 페이지 내 작은 창을 자동 확장하지 않고, 호스트 페이지 상단의 파란 호흡 막대(3dp 호흡선 + 대상 앱 문구 "앱 이름 · 패키지 이름", 시각 27dp, 터치 영역 40dp)로 바꿉니다. 탭하면 가상 화면 페이지가 열리고 ×로 접습니다. 세 단계 "막대(기본) / 전체 미리보기(이전 페이지 내 작은 창) / 끔"을 추가했고 설정 → 기기 기능 권한 → 가상 화면 미리보기에서 단계를 고르면 접힘 의도가 지워집니다. 접힘 상태는 앱 전용 설정에 저장되어 가상 화면 세대와 App 재시작을 넘어 유지되고 더는 generation별로 기억하지 않습니다. 가상 화면 정지 / 철회, 호스트 포그라운드 이탈, 가상 화면 페이지 자체 표시, 시스템 플로팅 미리보기 표시 시 제거됩니다. 대상은 Manager의 읽기 전용 `targetStatus`에서만 가져오며, 얻을 수 없으면 "가상 화면 조작 중"을 표시하고 시작 기록으로 추측하거나 프레임을 가져오거나 입력 자격 증명을 발급하지 않습니다. 호흡 애니메이션은 `UiMotion`을 따르며 애니메이션이 꺼져 있거나 동작 줄이기 설정이면 정적입니다.
