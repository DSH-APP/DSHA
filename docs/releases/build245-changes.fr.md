# DSHA 0.2.1-rc.3-20261101.1430-dsh0.2.1-rc.5 / build245

- Récupérer la maintenance interrompue distingue désormais les transactions en attente des enregistrements illisibles. Quand un enregistrement est illisible, il indique lequel, pourquoi et quoi faire ensuite, au lieu d’un simple code d’erreur brut, et ne relance plus une analyse vouée à l’échec.
- Quand les journaux de transactions de plugins sont illisibles, la page de maintenance propose Isoler les journaux de plugins illisibles. Après confirmation native des enregistrements listés, ils sont déplacés tels quels dans `plugin-install-quarantine` avec un inventaire ; rien n’est supprimé ni rejoué, et l’action est refusée si les enregistrements ont changé après la confirmation. Les sessions et paramètres ne sont pas touchés ; les plugins concernés devront peut-être être réinstallés. La page de réparation d’urgence propose la même action.
- Les transactions de données hôte, d’environnement d’exécution et de reconstruction peuvent être appliquées à moitié ; lorsqu’elles sont illisibles, elles ne sont donc pas isolées automatiquement : la cause exacte est indiquée et l’export du diagnostic pour le support est suggéré, plutôt que d’ignorer un retour arrière et de laisser des données personnelles incohérentes.
- Corrige un blocage lorsque l’ancien et le nouveau dossier de données existent tous deux : toutes les vérifications échouaient à la lecture et Choisir le dossier de données était alors refusé. Ce choix n’est plus bloqué par cet état ; les autres transactions en attente restent prioritaires.
- Portée de la vérification : les tests unitaires locaux et les régressions Python des transactions de plugins passent ; aucune vérification sur appareil. versionCode passe à 245. La révision DSHA reste 0.2.1-rc.3 et le DSH intégré reste 0.2.1-rc.5.
