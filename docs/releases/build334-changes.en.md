# DSHA 0.2.1-rc.5-20261106.2228-dsh0.2.2-rc.1 / build334

- P0 overwrite-update fix (T91, `a70232fc`): after overwriting build333 on a device, the proroot launcher could exit late or linger after the trial guest had already exited (observed on OnePlus PJD110 / Android 16 / WebView 156, including with no other Web process in the background). The `RuntimeTrial` finish step misread "launcher object still alive" as a trial failure `TRIAL_PROCESS_UNCONFIRMED`, leaving the runtime update transaction half-committed (`files-committed` / `settings-committed`); startup was then blocked by the maintenance barrier and a restart did not help. The trial finish step now confirms only on this record's guest-exit evidence, so launcher lingering no longer changes the conclusion. `RuntimeTrial` performs one bounded cleanup of the `Process` handle it holds for this instance, and a timeout or failure only writes a `TRIAL_LAUNCHER_RETENTION` diagnostic. For `launched` records lacking `.dsha-web.pid` / `.stale` evidence, `TrialRecovery` now asks the platform to confirm that the derived trial profile has no such process (same UID, two consistent birth identities); still present, unreadable or changed identity stays fail-closed, so an unhealable evidence gap is no longer left behind.
- Diagnostics for maintenance failures and stale-failure cleanup: maintenance task start/failure now write exportable operation records (`MAINTENANCE_TASK_START` / `MAINTENANCE_TASK_FAILED`), and the failed state keeps the emergency DSH, maintenance records, the exportable readable copy and "enter limited main UI" clickable. After an external recovery, as soon as the environment is runnable and no maintenance is running or pending, the page drops the stale failure snapshot (`RuntimeUpgradeState.clearStaleFailure`), returns to the standard "previous runtime awaiting update" state with the update entry, and no longer asks the user to press retry again. Startup records now label "auth link obtained but final ready/failed not written" as "ready · awaiting entry" instead of "interrupted · no result".
- Overwrite update retires the previous build (I10): only when the installed APK identity differs from the recorded session identity may the maintenance/force-stop path verify the recorded birth identity twice (boot, PID, birth time, command line, UID, generation/instance/nonce), then stop the recorded guest first and the corresponding old proot launcher second (SIGTERM → short wait → recheck → SIGKILL). If the guest exit is not confirmed, the launcher is untouched; any failed check, unreadable environment, PID reuse, other UID or change between the two observations sends no signal and keeps the original environment. Normal stop, the current instance, terminals, the virtual screen and the isolated trial path are unchanged (I9). The force-stop dialog states "abandon the previous Web and force-stop" and the guest → old-launcher order.
- build333 incident and acceptance status: on 2026-11-06, overwriting build333 over build332 on a OnePlus PJD110 (Android 16, WebView 156) triggered the half-commit described above (transaction `69ebb4f7…`); startup was blocked and a restart did not help. The emergency DSH `recover-maintenance` plus a retry then restored READY / 42117 with data intact. **build334 has not been validated on a device yet**; the acceptance item is that an overwrite install over build333 no longer jams on `TRIAL_PROCESS_UNCONFIRMED` and maintenance completes into the web UI. "Passed" is not pre-written.
