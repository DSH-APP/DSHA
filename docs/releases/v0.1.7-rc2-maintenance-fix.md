# DSHA 0.1.7-rc2 维护恢复热修复

日期：2026-09-25  
基线：DSHA `0.1.7-rc2` / versionCode `147`，内置 DSH `0.1.7-rc.2`，Ubuntu 基础环境 `10`

## 触发问题

旧版设备日志在“停止旧 Web 进程”阶段记录 `Permission denied`，任务被保留为未完成；
下一次启动先命中维护门禁，恢复操作又重复同一条停止路径，形成无法进入 Web UI 的闭环。
另一张用户截图显示格式化在“准备数据快照”阶段失败。格式化的首个阶段文字同时覆盖了
停止 Web 和自动备份作业静默屏障，因此该现象与同一停止屏障错误一致，不能仅凭页面文字
把故障归因到删除数据阶段。

## 本次修复

- Web 停止失败时，先保留 PID/出生身份核验；只有当前应用仍持有的本次启动器句柄才允许
  受控优雅退出。未知 UID、无法核验的 PID 和 proot/proroot 启动器不会按裸 PID、端口或
  名称强杀。
- 全局 `/proc` 扫描区分已确认其它 UID、无法读取的普通进程，以及完整读到 dsh Web 身份
  的本应用候选；旧 guest 把 `/root` 或 Web 记录改成不可写时，仅在 lstat 确认归本应用
  所有后补齐 owner 权限。
- 维护屏障读取停止任务的结构化结果，避免等 45 秒后把真实停止失败压成无上下文的权限
  文案；旧记录中的 `Permission denied` 和新记录中的 `WEB_PROCESS_SIGNAL_DENIED` 都给出
  可重试入口，未确认时继续保留原件。
- 格式化前自动备份的 JobScheduler 取消在部分 ROM 被拒绝时不再阻断私有格式化；持久化的
  `factoryResetPending` 门禁仍使迟到的 Job 立即退出。普通权限错误统一为
  `PERMISSION_DENIED`，不会被显示成成功。

- UI 回归：32/32 通过。
- rc1 迁移回归：14 项，0 失败，2 项 Windows 符号链接权限跳过。
- 插件统一升级门禁：通过；APK 资产检查、DeepSeek Messages、Lexical、会话撤回和设置迁移
  回归通过。
- 当前小米 M2012K10C / Android 13：同签名覆盖安装，`firstInstallTime` 保持
  `2026-09-21 15:06:35`，数据目录保持 `/data/user/0/com.dsh.client`；运行时更新完成后
  Standard 启动显示 DSH `READY`、端口 `3080`，可打开 `WebPreviewActivity`。未发现应用
  `FATAL EXCEPTION`；系统输入法和内核 wakelock 的 `Permission denied` 不属于 DSHA 进程。
