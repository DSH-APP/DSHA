# DSHA 0.2.1-rc.3-20261031.0700-dsh0.2.1-rc.5 / build217

- コンテナ内で apt などによりシステムライブラリをインストール/更新した後、プラグイン一覧の読み込みが毎回失敗する問題を修正しました。Playwright などが apt で `libsqlite3-0` を入れると `libsqlite3.so.0` が `libsqlite3.so.0.8.6` へのシンボリックリンクに置き換わります。読み取り専用クエリは通常ファイルしか認めず「実行ツールまたはアセットが不完全」と表示し続け、「インストールと修復」は判定基準が異なるためこのファイルを書き直しませんでした。
- 読み取り専用のプラグインクエリと Python 共有ライブラリの修復は同じ guest 判定を共有します。Ubuntu 実行ルート内でシンボリックリンクを段階的に解決し（相対リンク、guest 絶対パス、`.l2s` など本実行ルートを指すホストパス）、最終的に実行ルート内に収まる通常ファイルだけを受け入れます。`/system`、`/proc`、`/sdcard` などの外部バインド、範囲外リンク、循環リンクは引き続き未準備です。リンクをコンテナ内で proot が模擬する root が書いたか、外部の su で与えられた root が書いたかにかかわらず判定は同じです。
- 修復処理は解決できないダングリングリンク自体だけを削除してから同梱ライブラリを書き戻し、使用可能なリンクは書き換えません。プラグイン準備状態の判定が変わると、診断記録に具体的なファイルと理由（例 `libsqlite3.so.0:MISSING`）を残し、汎用メッセージだけではなくなりました。
- 純粋ロジックの `GuestRegularFile` と単体テストを追加しました。これは管理ランタイムの起動入力に含まれるため、ランタイム記述子を再生成しています。versionCode を 217 に引き上げました。DSHA リビジョンは 0.2.1-rc.3、内蔵 DSH は 0.2.1-rc.5 です。ビルドと受け入れの範囲は今回の CI run と Release の記録に従います。
