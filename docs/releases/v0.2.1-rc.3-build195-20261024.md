# DSHA 0.2.1-rc.3 / build195：电脑连接与悬浮助手

本轮新增原生工作区选择、电脑 DSH 远程访问、已配对手机工具、可展开聊天的悬浮助手，以及可自行部署的发现/中继组件。手机可在未初始化本机 Ubuntu 时进入电脑工作区；电脑对话、模型和项目继续由电脑自己的 DSH 管理。

## 已实现的使用路径

启动入口先显示原生工作区选择：本机 DSH 继续经过本机环境检查；电脑入口独立连接已配对主机，不启动本机 guest、launcher 或本机 Web 来伪装远程连接。可保存多台电脑，一次连接当前选中的一台；电脑身份、连接代次及具体会话共同确定请求归属。

远程网页使用电脑提供的前端和接口，通过专属网关转发登记的 DSH HTTP、WebSocket及文件流。它运行在独立的远程浏览器进程和对应电脑的 WebView 数据目录中，不注入本机 `window.DSHA`、插件管理或设备执行桥。远程网页权限请求不会自动获得手机摄像头、麦克风或定位；附件上传通过用户选择的内容 URI，下载/保存通过手机系统文档入口。

电脑配套由独立 companion 与 `dsha-connect-device` 插件组成。companion 负责设备身份、配对、传输及本机 DSH 转发；插件提供实际手机状态、任务和物理屏幕工具。任务归属从执行工具的真实 DSH agent 会话与轮次取得，模型不能自行指定另一个会话。截图传回真实图片字节，保存到电脑 DSH 附件存储，不把手机路径当作电脑文件。

悬浮助手可绑定本机或电脑的具体会话，收起显示状态及输出，展开后查看文字、发送消息或调用系统语音识别。语音结果成为草稿，不自动发送；它依赖手机可用的系统识别服务及用户当次麦克风授权，不是连续双向语音通话。展开、键盘输入及语音期间先暂停手机控制；收起不自动继续，用户需要明确继续。暂停/停止封住后续手机动作，并请求对应会话取消；停止后经真实空闲核验，仍可在同一会话发送新的用户消息。取消或发送结果未知时保留未知状态，不自动重放。

## Windows / WSL 操作方法

配套包按平台区分，Windows 使用 `dsha-connect-windows-amd64.zip`，WSL/Linux x86_64 使用 `dsha-connect-linux-amd64.zip`。压缩包内分别为 `dsha-connect.exe` 或 `dsha-connect`、使用说明、插件 `dsha-connect-device-0.1.0.tgz` 及依赖许可；不含私有身份、手机配对记录或 DSH Cookie。各配套包最终大小和摘要见下表。

1. 先在电脑启动现有 DSH，并在该 DSH 中安装随包插件。companion 不安装、替换或启动电脑 DSH；Windows 原生 DSH 与 Windows companion 使用同一用户运行域，WSL DSH 则使用 WSL 内的 Linux companion 和插件。
2. 从对应解压目录运行下列命令，用电脑 DSH 实际提供的本机启动链接替换整个引号内容：

   ```powershell
   .\dsha-connect.exe --dsh-url "http://127.0.0.1:实际端口/?token=DSH本次启动令牌"
   ```

   WSL 使用同等参数运行 `./dsha-connect`。这里只接受带显式端口的数字 loopback HTTP 目标；启动令牌仅在电脑本机交换 DSH Cookie，不进入手机二维码。不要把实际启动链接、二维码或状态目录复制进公开日志。
3. 打开 companion 输出的本机页面。在手机选择电脑工作区，扫描二维码或粘贴配对内容，核对并确认电脑身份。首次二维码三分钟有效；记住设备后使用独立长期密钥，二维码过期不使既有信任失效。
4. 连接后打开电脑网页，或在悬浮助手中选择该电脑的会话。本机与电脑的列表、草稿、附件及认证按各自环境处理，切换不会自动搬迁对话或凭据。
5. 电脑 AI 读取手机状态后开始任务，再读取当前屏幕。手机可暂停、停止或撤销信任；系统能力、敏感确认和最新观察身份仍检查。

Windows 状态默认放在 `%LOCALAPPDATA%\DSHA\Connect`，目录 DACL 限当前用户；WSL 默认 `${XDG_CONFIG_HOME:-~/.config}/dsha-connect`，目录和文件分别为 0700/0600。可通过 `--state-dir` 显式选择状态目录，插件通过同一用户的 `ipc.json` 发现 companion；自定义时可设置 `DSHA_CONNECT_IPC`。不要将状态目录随程序包分发。

companion 保存 LAN TCP/QUIC 监听端口，同一 IP 上正常重启沿用端口；占用时报错。PC IP 变化时，已信任电脑页面可显示“更新电脑地址”二维码。刷新二维码不带长期密钥，只能更新已有同一电脑；手机使用原密钥完成端点认证、握手及实际探测后才保存新地址，原标签和授权保持。重连建立新的进程/连接身份，旧动作、旧帧和旧许可不会迁入新连接。没有发现服务时，IP 地址变化仍需要这次显式地址刷新。

在电脑页面撤销手机，或退出后运行 `dsha-connect --revoke`；手机也可删除对应信任。撤销退休当前流及待完成配对状态，再次配对使用新二维码。退出 companion 停止连接，电脑原有 DSH 及其数据继续由电脑自己管理。完整参数与源码构建方式见[配套程序说明](../../tools/remote/companion/README.md)及[插件说明](../../tools/remote/dsh-plugin/README.md)。

## 自托管发现与中继

仓库提供真实 Circuit Relay v2、签名发现协议、Linux 服务程序及[部署工具和操作说明](../../tools/remote/deploy/DEPLOY.md)。本地交付包名为 `dsha-relay-selfhost-linux-amd64.zip`，包含程序、完整构建源码、配置示例、部署脚本、依赖许可、SBOM及成员摘要；9,644,047 字节，SHA-256 `91f3af3ef4e8fd42825c72c714b783fd290519dd0dd0aba50adf8a9b1cad07a0`。它是未签名的自托管工具包；生产安装流程仍需部署者按说明使用自己的发布密钥签名。本地签名夹具只验证封装/校验流程，不是生产运营方签名，也不是已经部署的服务。

部署者需要独立保管服务身份文件，配置真实 HTTPS 域名、受信 TLS 证书与固定 relay PeerID。配置示例中的 `relay.example.invalid` 无法使用；现有网站的监听、域名和配置不能被中继安装覆盖。systemd、Docker及独立反向代理的配置路径见部署说明，本轮没有在真实服务器安装它们。

服务程序当前支持如下命令；其中绝对路径是部署者填写的占位，父目录与配置须先按部署说明准备：

```sh
./dsha-relay init-identity -out /absolute/private/identity.key
./dsha-relay -config /absolute/config.json -check
./dsha-relay -config /absolute/config.json
```

创建身份不会覆盖已有文件。配置中的 `identityFile` 应指向该私有文件；`publicAddresses` 填真实公网 WSS 地址，明文发现/WS维持 loopback，由独立 TLS 虚拟主机转发。也可使用 `DSHA_RELAY_CONFIG` 指定配置路径，`-config` 优先。生产发布签名和服务身份是不同密钥；签名安装流程须使用部署者独立信任的发布公钥，不把包中自带的测试公钥当作信任来源。

完成服务外部验证后，电脑端显式配置实际地址；以下字段均为占位，没有预置官方端点：

```text
dsha-connect --discovery https://实际发现服务 --relay /dns4/实际中继主机/tcp/443/wss/p2p/实际中继PeerID --dsh-url 本机DSH启动链接
```

发现服务只保存签名的短期地址及绑定元数据，不持有应用配对密钥、对话或图片。PC 用持久身份签名恢复已确认的精确手机绑定，手机再独立签名建立和续租自己的许可；这不延长未配对二维码的首次认领窗口。已信任连接可先尝试缓存 LAN 地址，发现不可达时保留可用的直接连接并后台重试；尚未完成的发现撤销仍须先完成安全门才能创建新邀请。

发布自托管地址前，部署者还须从另一网络核验 TLS、固定 PeerID、`/readyz`、`/v1/info`、实际签名发现及 WSS 中继、无关设备拒绝、撤销后断流与原网站健康。宿主回归不替代这些外网检查。

## 数据、权限与传输边界

手机本机 Ubuntu、对话、配置、插件和文件保持本机归属；电脑项目、模型凭据和会话留在电脑 DSH。远程使用不复制整套环境，也不把电脑凭据导入手机本机环境。用户明确发送的消息、选择上传的附件，以及允许观察的手机屏幕会交给所连接电脑；电脑如何调用其模型，仍取决于电脑的配置。

手机长期配对状态通过本机密钥保护并放在不参与系统备份的位置，换机恢复不自动恢复授权。电脑长期身份与 Cookie 保存在上述私有状态目录；进程连接已建立不等于电脑 DSH 已就绪。切换、停止、撤销及断线使对应控制身份失效；重连只恢复连接，不自动提交旧消息、输入或工具动作。

本轮远程设备工具覆盖原生无障碍的物理屏读取、截图及受控输入，仍依赖手机已开启的无障碍服务、悬浮窗能力及对应用户策略。配对不授予 Android Root、ADB、Shizuku 或虚拟屏权限；远程工具没有任意 shell、任意手机路径或本机运行时启动路由。现有 ADB、虚拟屏和本机终端继续按各自原有前提使用，不能把这些能力一并称为“无 Ubuntu 远程模式已支持”。

屏幕操作仍校验当前目标、运行 owner、代次、最新帧/节点与策略修订。展开助手和输入法改变可操作区域，继续后需要重新观察。“全部允许”只影响相应 DSHA 确认，不能替代系统权限或放行过期目标。`UNKNOWN`、`PARTIAL`、断线、超时和没有回执都不能作为自动重试写动作的理由。已有通知或截图返回不等于已完成用户业务。

传输使用 libp2p 的端点身份认证和加密传输，提供 TCP/QUIC 直接流及经配置的加密中继流；实际 NAT、防火墙、移动网络和代理仍会影响连通。中继看不到应用流明文，但可以观察连接 IP、peer ID、时间和流量。中继连接/预约、时长和字节有配额；发现租约续租与有限 circuit 配额是两件事，不承诺永久后台连接或无限文件传输。

网页文件采用有界流式转发。宿主已通过真实 Noise/libp2p HTTP 代理完成上传、下载各 5,000,000,000 字节并核对相同 SHA-256；另有强制中继流的大字节量和摘要证据。它们分别覆盖本机 HTTP 路径和中继传输，手机文件选择器、手机落盘、重启续传及公网大文件尚未验收。相同输入继承与最终重跑范围以负责人回执为准。proot/proroot、venv及插件工具审批均不构成同 UID 任意代码的强沙箱。
