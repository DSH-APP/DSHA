- proot 运行根自镜像绑定（T123，`424b4a015`）：proot 用宿主路径 exec / mmap，`/proc/self/maps` 里是内核解析后的 canonical 路径；而运行根通常以 `/data/user/0` 别名传入，maps 却是 `/data/data`。不绑定时，guest 按 maps 回读会被翻译成 `<rootfs>/data/data/...`（rootfs 内同名骨架）并报 ENOENT。`baseArgv()` 现增加 `-b <canonical rootfs>:<canonical rootfs>`，canonical 由 `getCanonicalFile()` 解析（`/data/user/0` → `/data/data`），解析失败回退传入路径；proroot v1.2.8 的 vendor 已把 `-r` 解析后的 canonical 根绑进 guest，App 侧不重复绑定（升级 proroot 时需复核）。该改动落在 launcher 源，受管运行时 descriptor 由 `2ae3f266` 重算为 **`f65796a2`**，属受管运行时更新；固定输入未重建、未新增受管运行时。新增 `ContainerRuntimeSelfMirrorTest` 覆盖「别名→canonical」与「与 `.l2s` 绑定共存」。**proot 真机核对未做**（切换 proot 会重启 Web 并中断当前会话），留待用户安排。
