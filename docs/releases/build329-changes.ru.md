# DSHA 0.2.1-rc.5-20261106.0130-dsh0.2.2-rc.1 / build329

- Добавлена нативная страница входа GitHub (T71): показывает учётную запись, области доступа и источник из `hosts.yml` контейнера, сообщает, доступен ли управляемый `gh`, и с помощью `gh api -i /user` только для чтения различает сбой CA/TLS, 401 по токену, отсутствие входа, сеть и тайм-аут; поддерживает вход, повторную авторизацию и выход. Сама страница не показывает токен. Известный пробел: токен по-прежнему хранится в `hosts.yml` контейнера и доступен для чтения веб-страницам и плагинам с тем же UID; изоляция вынесена в T50 и не входит в эту партию.
- Исправлен поиск CA для `gh` (T73): `RuntimeTools` теперь задаёт `DSHA_GH_HOST_ROOT` от canonical корня хоста, а обёртка `gh` ищет управляемый CA в двух представлениях данных `/data/user/0` и `/data/data`; если оба отсутствуют или `DSHA_GH_CA` указывает на несуществующий файл, она завершается с явной ошибкой и больше не откатывается молча на старый системный CA без нового корневого сертификата. Фиксированные входы не пересобираются.
- Унифицирован нижний колонтитул 4-го шага онбординга (T72): страница завершения приветствия теперь использует тот же компактный двухстрочный `ExtractFooter`, что и страница обслуживания среды: показывает x/5 при обновлении, возвращает основное действие и переходит в главный интерфейс по готовности.
- Объём проверки: хост-тесты, полная группа contracts, проверка форматирования всего дерева и целевые модульные тесты (страница обновления, вход GitHub, корень gh, онбординг); локальная проверка на устройстве не выполнялась. Код версии повышен до 329 (на базе build328); редакция DSHA остаётся 0.2.1-rc.5, встроенный DSH — 0.2.2-rc.1.
