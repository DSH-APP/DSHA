# DSHA 0.2.1-rc.5-20261109.0900-dsh0.2.2-rc.1 / build347

- SAF folder selection now targets the system file picker (`479302313`): new `ui/SystemDocumentPicker` points the tree intent explicitly at `com.android.documentsui` / `com.google.android.documentsui`, falling back to default resolution when it is not exported, disabled or missing; when an OEM has replaced the default handler, the app explains that SD cards / USB drives may not be visible and offers three entries — system picker / the overriding app's info (clear its default) / keep the default; if no handler exists it shows a toast instead of crashing. The permission page, the workspace backup directory and the native-data project backup source all use the same picker; the manifest `<queries>` adds both system packages and `OPEN_DOCUMENT_TREE`; `SystemDocumentPickerTest` adds 7 cases for the forced system entry, OEM takeover detection and fallback.
- Device-channel status pills no longer squeeze out buttons and switches (`cfad29009`): the Root / Shizuku / ADB / external-device rows become a weighted "title column + status pill", with in-row verify / pair buttons and switches measured first and long status wrapping inside the left column; new `ShellChannelStatusPill` (at most 6 lines, no ellipsis, 2dp line spacing) and the external-device status joins the title column; `DeviceGrantsLayoutTest` adds long-status / Chinese-English / 1.3× font regressions where actions keep their width and stay on screen.
- Hidden-from-recents gains a content guard and an experimental strict mode (`76b3a44a6`): Android 13+ RecentTasks keeps the "most recent visible task", so swiping from inside the app straight to Recents still shows the current card; public APIs cannot remove only that card without ending the UI. The new `ui/RecentsPrivacyGuard` (application-level lifecycle) disables recents screenshot content on all screens when the switch is on (API 33+); experimental strict mode (default off) ends the UI task 700ms after the whole app goes to background, but not while a result-type picker such as SAF is in flight, in picture-in-picture, in multi-window, or during rotation; failures are written to the diagnostic log without crashing or replaying; `BrowserTasks` now re-reads the task list and root Intent flags after applying, so an empty task list or a flag mismatch is reported as failure (`RECENTS_HIDE_APPLY` / `RECENTS_HIDE_VERIFY`) instead of a fake success; Settings adds the strict-mode sub-row (hidden while the parent switch is off) and ten-language strings `m9500`–`m9502`.
- Managed-runtime update: changes to `DshaApp` / `ConfigStore` recompute `runtimeId` to `28dc573a`; fixed inputs stay frozen at the locked 20261105e; the bundled `dsh-web-mobile` stays upstream 3.3.1 and default-enabled.
- Version and scope: versionCode raised to 347 (based on the released build346 / `86f91ba0a`); the DSHA revision stays `0.2.1-rc.5` with bundled DSH `0.2.2-rc.1`. This batch does not change the device shell allowlist and does not relax execution-time guards.
- **Not verified / not accepted**: on the OnePlus C16, whether the current card's content is blank when swiping from inside the app to Recents, whether the card disappears after pressing Home, and whether strict mode removes the card while dsh Web / terminal / ADB keep-alive still run; the system picker entry and actual tree grant in the OEM-takeover case; visual acceptance of the four device-channel rows under day-night, short screens, 1.3× font and RTL; the real `BrowserTasks` read-back result on a new ROM. **build347 is not yet device-validated**: acceptance is a first 346→347 overwrite that succeeds, data intact, READY, the managed-runtime update and the three features above; build344–build347 formal-package overwrite acceptance is still pending with the user.
