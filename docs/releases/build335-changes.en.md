This build fixes the first-failure path and the post-recovery state according to that field evidence.
- Bounded force-kill of a guest that has not exited during trial finish (T103, `a5168f99`): a non-empty `manager.stop()` no longer fails immediately with `TRIAL_PROCESS_UNCONFIRMED`. The finish step first waits for this instance's launcher for a bounded 3 seconds, then `WebProcessManager.forceStopTrialGuest` rechecks this round's record, the unique profile and the saved birth identity in consecutive reads and sends SIGKILL only to this round's guest, then reruns the recorded stop and the global no-Web check. Only if the guest still cannot be confirmed does it fail, writing redacted details into exportable operation records and the record directory (a finish failure after a successful trial writes `failure.json`; the recovery path writes `recovery-stop.json`; existing failure details are not overwritten). `TrialRecovery` follows the same order, so one `recover-maintenance` can close an old trial that was previously stuck on a guest that had not exited. The forced path is fail-closed when the birth identity is missing, the PID record does not match, or two observations differ; it never scans by bare PID or process name. The maintenance page drops the 2-second `pendingTrial` cache and discards the `BackupTask` UI cache on `onResume`, so after an external recovery it immediately returns to "previous runtime awaiting update".
- Recovery rechecks by birth identity and rewrites identity evidence (T100, `903974db`): startup recovery and foreground/background rechecks share `observeRecoveredSession`. When the strict PID / identity-file check is UNKNOWN, it falls back to the full birth proof (boot / PID / birth time / command line / UID / generation+instance+nonce); a strict result of LIVE / EXITED is never downgraded, and an unreadable proof version stays fail-closed. After a successful reattach it rewrites `/root/.dsha-web.pid` and `.dsha-web.identity` from the verified birth identity (a pid record that points at another number is preserved as-is), closing the gap where a stale or retired identity file made every startup fall back to `IDENTITY_UNKNOWN`. A terminal UNKNOWN writes the exportable `WEB_SESSION_RESTORE_FAILURE` diagnostic (stage / reason / attempts), and the `IDENTITY_UNKNOWN` text gives the next step: stop → if normal stop cannot confirm, force-stop by identity check → restart and recheck.
- Virtual-screen preview redesign (T96, `71010565`): the default no longer auto-expands the 172dp in-page panel; it becomes a blue breathing strip at the top of the host page (3dp breathing line + target application text "app name · package name", visual 27dp, touch target 40dp); tapping opens the virtual-screen page, × collapses it. New three levels — strip (default) / full preview (old in-page panel) / off — under Settings → Device capability grants → Virtual-screen preview; choosing a level clears the collapsed intent. Collapse state persists in app-private preferences across virtual-screen generations and app restarts and is no longer remembered per generation; it is removed when the virtual screen stops or is revoked, the host leaves the foreground, the virtual-screen page itself opens, or a system floating preview is shown. The target comes only from the Manager's read-only `targetStatus`; when unavailable it shows "virtual screen active", never guessing from launch records, taking frames or issuing input credentials. The breathing animation follows `UiMotion` and is static when animations are off or motion is reduced.
