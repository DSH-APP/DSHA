# DSHA 0.2.1-rc.5-20261109.2300-dsh0.2.2-rc.1 / build350

- 가상 화면의 창 증거 최소 노출과 다중 창 실행 가능 안내(T98, `33ceab2c7`): `see`의 세분화된 `FRAME_NOT_READY` 응답과 tree / node / editor / anchor의 창 사용 불가 응답은 접근성으로 창을 읽을 수 있을 때 최소 읽기 전용 창 증거(`util/VirtualScreenWindowEvidence`)를 함께 제공합니다. 앱 / 시스템 / 입력기 창 개수, `focusedWindowId` / `activeWindowId`, `windowAmbiguous`, 창이 유일할 때만 대상 창의 displayId / id / type / layer / bounds / focused / active / 제목 / 패키지를 포함합니다. 제목은 제어 문자를 제거하고 공백을 접고 64 코드 포인트로 자르며, 패키지는 패키지 이름 형식을 검증한 뒤에만 유지하고 나머지 부적합 값은 생략합니다. 노드 텍스트, 컨트롤 내용, 스크린샷, 전체 창 목록은 포함하지 않습니다. `NO_UNIQUE_APPLICATION_WINDOW`는 개수로 두 원인을 구분합니다. 앱 창이 여러 개 나란히 있으면(분할 화면 / 플로팅 창) `reason=VSCREEN_WINDOW_AMBIGUOUS`, `nextAction=ASK_USER_TO_CLOSE_SPLIT_SCREEN`; 시스템 / 입력기 창만 있고 앱 창이 없으면 `reason=VSCREEN_NO_WINDOW`, `nextAction=LAUNCH_APP_FIRST`입니다. 증거는 실패와 다음 단계를 설명하는 데만 쓰이며 **권한 부여, 창 선택, 재시도에 전혀 관여하지 않습니다**: 의미 경로는 계속 `VirtualScreenWindowPolicy.selectDetailed`의 유일한 결과만 인정하고, 앵커 경로는 원래 관찰이 전달한 windowId만 인정합니다(같은 id 반복은 여전히 `ANCHOR_WINDOW_AMBIGUOUS`로 거부). "다중 창" 때문에 다른 창으로 자동 전환하지 않습니다.
- 가상 화면 민감 화면 단계와 인계(T119, `dc6f9642e` / `c3a4e3c30` / `241e06159`): 새 `util/SensitiveScreenClassifier`와 `util/SensitiveScreenPolicy`(순수 로직)를 추가해 6.1의 비밀번호 포커스 강제 가드 위에서 화면 전체를 보수적으로 분류합니다(비밀번호 / 일회용 코드 / 결제 / 시스템 보안 / 민감하지만 트리를 읽을 수 없음 `SECURE_UNKNOWN`). 기본값은 모든 범주 `ASK`이며 범주별로 `HANDOFF`를 설정할 수 있습니다. 어떤 입력도 보내기 전에 어시스턴트를 일시 중지하고 진행 중인 요청을 취소하며 관찰을 버린 뒤 `ok:false` / `state=NOT_SENT` / `error=SENSITIVE_SCREEN_HANDOFF` / `sensitivity=<범주>` / `readOnly:true` / `retryable:false` / `nextAction=HANDOFF_TO_USER`를 반환합니다. 사용자가 재개한 뒤에는 반드시 다시 `see`해야 하며 자동 재생하지 않습니다. `OFF`는 화면 전체 단계만 끄고 일반 확인 정책으로 돌아갑니다. 비밀번호 텍스트 읽기/쓰기는 계속 입력 계층의 강제 차단이며 어떤 단계나 확인으로도 해제되지 않습니다. `ALLOW_ALL`과 앱별 `ALLOW`는 일반 확인만 생략하고 민감 범주의 `ASK`를 건너뛸 수 없습니다. 민감 확인은 1회성 인가이며 **"이번 턴에 이 앱 허용"의 5회 기억에 기록되지 않습니다**(일반 앱은 여전히 5회마다 다시 묻습니다). 설정 → 기기 기능 권한 → 화면 인식에 "민감 화면 인계" 독립 행을 추가해 범주별 묻기 / 인계를 선택하고, 강제 인계와 신뢰 앱 두 개의 정확한 패키지 이름 목록(기본 비어 있음, 각 최대 64, 상호 배타, 손상 시 ASK로 복귀)을 관리합니다. 화면 권한의 `policyRevision`은 `screen_confirmation_v1`과 `sensitive_screen_v1` 개정 번호를 합치므로 어느 쪽을 저장해도 이전 확인과 진행 중인 요청이 무효화되고, 프로세스 안에서는 단조 하한을 유지합니다. 입력을 주입하는 엔드포인트는 확인 후, 전송 전에 다시 분류하며 읽을 수 없으면 `SENSITIVE_SCREEN_UNVERIFIED`, 범주가 바뀌면 `SENSITIVE_SCREEN_CHANGED`를 반환합니다. 둘 다 전송되지 않았고 다시 관찰하면 됩니다.
- 아일랜드(알림 캡슐) 수정(PR #12, `ccd4b81d7`, 이미 main에 병합): 펼친 상태에서는 턴 표시를 알림 subText 한 곳에만 두고 본문에서 "제 N 턴"을 반복하지 않으며 실행 중에도 매초 경과 초를 쓰지 않아 내용 서명이 안정되고, 하트비트 알림 재생성이 선택지 버튼 탭을 삼키지 않습니다. 백그라운드 답변 실패는 반드시 보여야 합니다 — HTTP 200이 아니거나, 빈 제출, 만료된 선택지, 만료된 진입점이면 Toast(HTTP 상태와 서버 오류 코드, 예: `HTTP 409 NO_WAITING`)를 띄우고 알림에서 대화로 들어가 답하도록 안내하며, 앱 로그에 `TASK_ANSWER_REJECTED <status> <body>`를 기록합니다. 알림에서 대화로 들어갈 때 판단 기준은 질문 카드에 실제 선택지 행(`Mbwy4a_optionRow`)이 있는지로 바뀌었습니다(선택지 컨테이너 `Mbwy4a_options`는 모든 카드에 렌더링되므로 그것으로 판단하면 항상 참). 선택지가 있으면 포커스를 뺏지 않고 키보드를 닫아 둔 채로 두어 카드 하단의 "제출"이 화면 밖으로 밀리지 않게 합니다. `docs/island-status.md`에 플랫폼 검증 상태표를 추가해 네이티브 Android 16, 16 QPR1+, HyperOS, ColorOS 16, OriginOS 6/7을 "플랫폼 분기 지원 / 코드 지원이나 실기기 미확인 / 기여자 실기기 관찰(미커밋) / 공개 정보이며 실기기 미확인 / 지원 예상이나 실기기 기록 없음"으로 항목별 구분하고, OriginOS 7(Android 17)은 저장소에 실기기 기록이 없음을 명시했습니다.
