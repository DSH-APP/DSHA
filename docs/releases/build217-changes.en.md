# DSHA 0.2.1-rc.3-20261031.0700-dsh0.2.1-rc.5 / build217

- Fixes the plugin list failing on every read after system libraries are installed or upgraded inside the container (for example by apt): when tools such as Playwright install `libsqlite3-0` through apt, `libsqlite3.so.0` becomes a symbolic link to `libsqlite3.so.0.8.6`; the read-only query accepted only regular files and kept reporting that runtime tools or assets were incomplete, while Install & repair used a different check and never rewrote the file.
- The read-only plugin query and the Python shared-library repair now share one guest check: symbolic links are resolved step by step inside the Ubuntu runtime root (relative links, guest-absolute paths, and host paths such as `.l2s` that point back into this runtime root), and only a regular file that finally lands inside the runtime root is accepted; external bindings such as `/system`, `/proc` and `/sdcard`, escaping links and loops are still not ready. The check is the same whether the link was written by the root that proot emulates inside the container or by root granted from outside through su.
- Repair removes only an unresolvable dangling link itself before writing back the bundled library, and a usable link is no longer rewritten; when the plugin readiness verdict changes, diagnostics record the exact file and reason (for example `libsqlite3.so.0:MISSING`) instead of only a generic message.
- Adds the pure-logic `GuestRegularFile` with unit tests; it joins the managed runtime launcher inputs, so the runtime descriptor is regenerated. versionCode is raised to 217; the DSHA revision stays 0.2.1-rc.3 and the bundled DSH is 0.2.1-rc.5; build and acceptance scope follows this CI run and the Release receipt.
