- 화면 인식 모드 전환 2차 확인 (T113, `29c5028b`): 설정 → 기기 권한 → 화면 인식에서 실제 화면/가상 화면을 선택하면 먼저 `DshaDialogBuilder` 2차 확인(읽기 범위와 철회 가능 안내)을 띄우고 확인 후에만 전환한다. 성공·실패·정리 대기·중복 선택 모두 인라인 상태와 toast를 표시하며, "모두 허용" 확인 방식으로도 확인을 건너뛰지 않는다. 새 `ScreenModeFeedback` 이 확인 조건·모드 이름·결과 문구의 유일한 출처가 되며, 전환 중에는 연속 탭을 무시한다. 320dp 짧은 화면과 1.3배 글꼴에서도 중영문 확인 대화상자는 스크롤된다.

- 가상 화면 어시스턴트 텍스트 쓰기 전 비밀번호 포커스 가드 (T97 P1, `8b82e4f7`): `/app/vscreen/type` 의 순수 ASCII 빠른 경로가 Core 에서 `input text` 를 직접 실행해 접근성 비밀번호 검사를 우회했다. 새 `VirtualScreenTextInputPolicy`(비밀번호 포커스 강경 거부, 안전 포커스 허용, 의미 채널은 있으나 포커스 판독 불가 시 fail-closed, 접근성 미연결 시 문서화된 ASCII 능력 유지 + `passwordFocusChecked=false` 표기)와 읽기 전용 `VirtualScreenPasswordProbe`(ACTION_AUTHORITY 로 현재 표시의 단일 앱 창 재확인 후 `FOCUS_INPUT` 판독, 창 변경 시 `SCREEN_TARGET_CHANGED` 로 미전송)를 추가. ASCII 발송 전 사전 점검: 비밀번호는 `PASSWORD_INPUT_UNAVAILABLE`(`state=NOT_SENT`, `nextAction=REPORT_TO_USER`), 판독 불가는 `PASSWORD_FOCUS_UNVERIFIED`(`retryable`, `SEE_AGAIN`). 비ASCII type 과 node `set_text` 의 비밀번호 노드 쓰기도 막았고, 네이티브 패널은 독립 리스로 영향 없음. "그래도 허용"은 제공하지 않는다.
- T97 CI 테스트 시임 수정 (`d16b0c14`, 테스트 기반): `VirtualScreenInput` 에 인스턴스 수준 forced-available 플래그를 추가해 테스트 인스턴스가 호스트의 `/system/bin/input` 탐지에 납치되지 않게 했다(GitHub runner 에 해당 파일이 없어 T97 단위 테스트가 빨강). 프로덕션 인스턴스는 플래그를 설정하지 않으며 실제 missing-command 는 그대로 거부되고 `systemCommandExists` 는 완화되지 않았다.
- 가상 화면 표시 사양 화이트리스트 프리셋 (T99, `c33f358d`): 기본은 1008×1792@320(16:9 / 504×896 dp) 그대로, 호환 기준선 compat-720 = 720×1600@320(20:9 / 360×800 dp) 추가. 알 수 없음/빈 값/예산 초과 사양은 기본으로 복귀하며 임의 크기·dpi 는 받지 않는다. Manager 생성·회전은 preset id 와 방향만 Core 에 전달하고, Core 가 화이트리스트를 해석해 dpi 를 적용하고 preset/density/logical 크기를 되읽는다. `VirtualScreenDisplaySettings` 가 선택을 영속화하고 가상 화면 페이지에 "표시 크기" 라디오를 추가(다음 생성·회전 재구성에만 영향, 현재 프레임 동일성과 입력 게이트는 불변). 관찰 예산은 2장/24 MiB 그대로이며 1440×2560 두 장(약 28.1 MiB)은 화이트리스트에 없다. compat-720 실기기 검증은 미실시.
- 실제 화면 동작 즉 관찰과 이벤트 기반 settle (T105, `c6a2ea84` / `c94df74d` / `00dd7a90`): `/app/ui` 동작 엔드포인트에 선택 `observe=1` 추가. 동작이 `COMPLETED` 된 후 같은 요청에서 settle(첫 접근성 이벤트 ≤800ms, 정적 250ms, 총 상한 2.5s, 작업 취소·요청 기한으로 중단 가능, 바쁜 폴링 없음)하고 트리를 다시 읽어 새 `treeId`/`nodeId`, 텍스트 트리, settle 메타데이터를 회신에 붙인다. 좌표 동작은 여전히 스크린샷을 반환하지 않고 좌표 자격 증명은 별도 스크린샷이 필요하다. 인자를 생략하면 기존 동작 그대로이며, 관찰 실패는 `observationUnavailable` 만 쓰고 동작 상태를 바꾸지 않으며 UNKNOWN 은 재전송하지 않는다. 자격 증명 만료류 거부에는 현재 화면의 새 트리를 붙여 새 자격 증명으로 재시도할 수 있다. 내장 `dsh-computer-use-android` 의 7개 동작 도구에 선택 `observe` 추가(생략 시 MCP 서버가 `observe=1` 주입, `observe:false` 로 끔; 선택 필드만 추가하고 엄격한 인자 검증은 완화하지 않음). 연속 `/app/sense/state` 는 기본으로 델타를 반환(3분의 1 초과 변화, 창/크기/포커스/소스/잘림 상태 변화, 세대 또는 대상 변화, `full=1` 은 전체, 무변화는 `mode=same` 한 줄). 응답에 `mode`/`deltaReason`/`previousSid`/`changedElements` 추가, `format=v4-preview-3`. `k***` 는 여전히 읽기 순서 위치 번호이며 동작은 일회성 `treeId`/`nodeId` 리스를 쓴다. `/app/help` 중영문 동기화 완료.
