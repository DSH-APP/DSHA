# DSHA 0.1.7-rc1 · build 146

本地适配记录。内置 DSH 锁定为 `0.1.7-rc.1`，版本码 146，包名仍为
`com.dsh.client`，Standard/Low 继续使用 E7E3 历史发布证书。

## 上游变化

- Session 日志升级为 V4；rc1 的 JSONL 持久化按 V0→V1→V2→V3→V4 相邻迁移，
  只读旧日志并在校验通过后发布相邻的 V4 successor，旧源字节不改。
- 设置从旧的 `settings.yaml` 导入当前 Profile 插件配置；旧目录式 Agent preset
  不再自动发现，改由 `@deepseek-ai/dsh-agent-preset` 组合包声明。
- 官方 DeepSeek 适配器统一 Messages API；PTC/workflow、Node PTC、Remote、MCP
  资源和插件兼容检查接口均有调整。

## DSHA 迁移保护

覆盖更新在真实 rc1 Web 启动前执行 `rc1-migration.py prepare`，保存 settings、
Profile 的 package/lock/workspace/compatibility 声明、旧 `.agent-presets` 和会话源
文件的摘要。鉴权链接成功后才写入迁移回执。

- 上游 `settings.yaml` 导入若只完成部分 section，下一次启动会把未被销毁的
  `settings.yaml.imported` 原字节放回 `settings.yaml` 重试；没有成功回执就不会把它
  当成已完成迁移。
- 旧 preset、同名插件源码、缺失依赖和无法解析的 bundle 都保留在
  `.dsh/.dsha-rc1-migration` 隔离区，原 profile 声明不删除、不自动启用。
- 旧 preset 会额外生成包含 `package.json`/`cordis.patch.yml` 的 bundle 候选，逐插件兼容检查和实际 roster/resume 验证通过后才能安装。
- 旧 Session 不在宿主侧重写；rc1 自己负责 V4 迁移。预检/启动失败只记录摘要和原因，
  不发布半个 successor。
