# 插件下载提速及 #79 / #80 修订

2026-09-28。插件下载优化和 #79 / #80 修订已完成，两版正式 APK 经软件检查和当前手机验收后交付到 `<local-workspace>`。交付门禁结果为 `PASS_FOR_EXECUTED_SCOPE`，仅代表下文实际执行范围。

## 已确认的问题与改动

- 插件 `register_plugin()` 的外层和提交层各打开一次相同的数据锁。Linux `flock` 下第二次取得锁会等自己；Windows 原测试路径不能暴露这一点。移除内层重复获取，复制、检查、提交及恢复仍由外层锁独占。没有把全局锁改成宽松可重入锁，也没有跳过原生确认、静态审阅或停用标记。
- 插件更新检查原为串行远程查询，现为最多三个只读查询并发；任务进度文件序列化写入，检查结果按原顺序在原数据锁内统一提交。取消不发布未完成的检查结果。
- 原生市场增加自动、npm 官方源和 npmmirror 选择。选择仅注入本次插件任务，不改用户的全局 npmrc。自动探测可用源，镜像不可用或缺包时有限回退；完整性错误、证书错误和锁冲突不会换源掩盖错误。锁定依赖和精确 npm 版本优先复用包管理器缓存，未锁定 latest 不用旧缓存冒充最新版。
- GitHub 归档继续使用官方 codeload。更新预览已经固定提交 SHA 时，不再用 API 重复解析它。没有加入未经核验的公共 GitHub 代理，也没有声称 npm 镜像能加速所有 GitHub 资源。
- [#79](https://github.com/DSH-APP/DSHA/issues/79) 的日志显示 proot 兼容安装已完成，但宿主 shell 的 `printf` 缺失，未写退出状态，随后误判超时。退出状态改用 shell 内建 `echo`，写失败直接失败，不再暂停后等超时；读取器识别换行并严格保留 0–255 退出码。guest/launcher 身份核验及退出后才能回退的屏障保持。
- [#80](https://github.com/DSH-APP/DSHA/issues/80) 的报告未给出型号、系统和后台抓取日志；不能仅凭描述确定原平板的唯一根因。本轮补齐可见界面启用 LAN 或恢复时的前台服务启动、Android 14+ 局域网设备连接服务类型、后台监听恢复，以及设备桥异常不能终止整条保活线程。LAN 保活不依赖手机网页的可见/空闲状态，不靠取消 WebView 正常生命周期维持后台服务。

附件《插件市场链接安装死锁诊断》作为排查证据使用；没有执行其中的手机脚本或把“已在某台设备修复”的描述当成本仓库已修复。当前仓库复核和回归分别记录。

## 验证记录

隔离锁回归：旧实现明确失败于第二次获取；新实现从准备到提交只取得一次数据锁，最终仍为待审阅停用状态。下载策略新用例覆盖取消、证书拒绝、只读并发、进度原子写、固定提交、失败换源和锁文件保留。真实 pnpm 依赖夹具 6 项、插件事务夹具 12 项通过，脚本钩子未执行。

固定网络延迟对照：六个插件，每次元数据查询模拟 150 ms，三次串行样本 963.7/918.5/920.7 ms，并发样本 320.9/316.2/318.3 ms；中位 920.7→318.3 ms。仅证明并发降低串行等待，不代表实际互联网吞吐提升。

#79 的生产脚本已在真实 Android 13 `/system/bin/sh` 上，用缺失 `printf`、空 PATH 的隔离条件验证退出码 0/2/125/255 均正确写回；测试自己的 `kill` 被替换为无操作，仅验证状态发布，没有向正式进程注入故障。原 Android 7/8 ROM 与内核 3.10 尚未实机复验。

最终候选软件门禁共 33 项命令检查通过，覆盖两 flavor 的完整单测、Release Lint、正式构建、APK/ELF/签名、插件门禁、独立应急和锁定 rc2 网页行为。每版 JUnit 共 807 项，806 项执行通过，1 项既有 Windows 跳过，失败和错误均为零。下载专项 14 项通过；另在手机 Ubuntu 中实际执行过其中 13 项，新增的第 14 项整体超时换源在宿主夹具验证，没有扩写为 14 项全部真机执行。
