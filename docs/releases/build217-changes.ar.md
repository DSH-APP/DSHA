# DSHA 0.2.1-rc.3-20261031.0700-dsh0.2.1-rc.5 / build217

- إصلاح فشل قراءة قائمة الإضافات في كل مرة بعد تثبيت مكتبات النظام أو ترقيتها داخل الحاوية (مثلاً عبر apt): عندما تثبّت أدوات مثل Playwright الحزمة `libsqlite3-0` عبر apt يصبح `libsqlite3.so.0` رابطاً رمزياً إلى `libsqlite3.so.0.8.6`؛ وكان الاستعلام للقراءة فقط يقبل الملفات العادية وحدها فيظل يُبلغ بأن أدوات التشغيل أو الأصول غير مكتملة، بينما يستخدم «التثبيت والإصلاح» معياراً مختلفاً فلا يعيد كتابة الملف.
- يتشارك الآن استعلام الإضافات للقراءة فقط وإصلاح مكتبات Python المشتركة معياراً واحداً للضيف: تُحلّ الروابط الرمزية خطوة بخطوة داخل جذر تشغيل Ubuntu (الروابط النسبية، والمسارات المطلقة للضيف، ومسارات المضيف مثل `.l2s` التي تشير إلى هذا الجذر)، ولا يُقبل إلا ملف عادي ينتهي داخل جذر التشغيل؛ وتبقى الارتباطات الخارجية مثل `/system` و`/proc` و`/sdcard` والروابط التي تخرج عن الجذر والحلقات غير جاهزة. والمعيار نفسه سواء كتب الرابطَ root الذي يحاكيه proot داخل الحاوية أو root ممنوح من الخارج عبر su.
- يحذف الإصلاح الرابط المعلّق غير القابل للحل نفسه فقط قبل إعادة كتابة المكتبة المضمّنة، ولم يعد يعيد كتابة الرابط الصالح؛ وعندما يتغيّر حكم جاهزية الإضافات يسجّل التشخيص الملف والسبب بدقة (مثل `libsqlite3.so.0:MISSING`) بدلاً من رسالة عامة فقط.
- أُضيف المنطق الخالص `GuestRegularFile` مع اختبارات الوحدة؛ وهو من مدخلات تشغيل وقت التشغيل المُدار، لذا أُعيد توليد وصف وقت التشغيل. رُفع versionCode إلى 217؛ وتبقى مراجعة DSHA عند 0.2.1-rc.3 وDSH المدمج 0.2.1-rc.5؛ ويتبع نطاق البناء والقبول تشغيل CI هذا ووصل Release.
