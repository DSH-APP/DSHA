# DSHA 0.2.1-rc.3-20261101.1430-dsh0.2.1-rc.5 / build245

- Recuperar manutenção interrompida agora distingue transações pendentes de registros ilegíveis. Quando um registro não pode ser lido, informa o tipo, o motivo e o próximo passo, em vez de mostrar só um código de erro bruto, e não repete mais uma verificação fadada a falhar.
- Quando os registros de transações de plug-ins não podem ser lidos, a página de manutenção oferece Isolar registros de plug-ins ilegíveis. Após a confirmação nativa dos registros listados, eles são movidos sem alteração para `plugin-install-quarantine` com um inventário; nada é excluído ou reexecutado, e a ação é recusada se os registros mudarem após a confirmação. Sessões e configurações não são afetadas; os plug-ins relacionados podem precisar ser reinstalados. A página de reparo de emergência oferece a mesma ação.
- Transações de dados do host, do ambiente de execução e de reconstrução do ambiente podem estar aplicadas pela metade; por isso, quando não podem ser lidas, não são isoladas automaticamente: o motivo exato é informado e sugere-se exportar o diagnóstico para o suporte, em vez de pular uma reversão e deixar os dados pessoais inconsistentes.
- Corrige um impasse quando os diretórios de dados antigo e novo existem ao mesmo tempo: todas as verificações falhavam na leitura e Selecionar diretório de dados era recusado por isso. Agora a seleção do diretório de dados não é bloqueada por esse estado; outras transações pendentes continuam vindo primeiro.
- Escopo da verificação: testes unitários locais e regressões Python de transações de plug-ins passaram; sem verificação em aparelhos. versionCode sobe para 245. A revisão DSHA continua 0.2.1-rc.3 e o DSH incluído continua 0.2.1-rc.5.
