# DSHA 0.2.1-rc.5-20261107.1900-dsh0.2.2-rc.1 / build337

- Correction du 409 de l’interface des tâches téléphone (T115, `a9c718e2`) : la fenêtre des tâches sur l’écran physique ne pouvait pas être créée dans le paquet de production build336 — le `dsh-status-overlay` intégré appelait encore `SessionController.inspect`, supprimé en 0.2.2-rc.1 ; `sessions.status` levait donc une TypeError, le pont répondait 409 et Java ne voyait que `ASSISTANT_TASK_CHANGED`. Il lit désormais `controller.state` et une page bornée de `controller.events` (les 16 derniers événements de message sont réduits aux 8 entrées visibles ; turnId / turnActive privilégient la projection `turnBoundary` de l’hôte) et conserve les champs de réponse lus par Java ; le test hôte passe 11/11. **La validation sur appareil du paquet de production reste à faire après installation de build337 par l’utilisateur.**
- Correction de `pty.fork` du terminal Web (T116, `adab1698`) : lorsque `sharp` se charge avant `node-pty` dans le même processus Node, les exports de `pty.node` sont enregistrés sous des clés sharp/libvips et l’ouverture du terminal Web échoue avec `pty.fork is not a function` (réessayer ne sert à rien). Le préchargement `startup-observer.cjs` exige désormais node-pty avant le chargement des plugins ; les échecs restent silencieux et n’affectent pas le démarrage. Voir l’[audit T116](../design/t116-pty-fork-20261107.md).
