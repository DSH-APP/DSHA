# DSHA 0.2.1-rc.5-20261109.0900-dsh0.2.2-rc.1 / build347

- La sélection de dossier SAF cible désormais explicitement le sélecteur de fichiers système (`479302313`) : le nouveau `ui/SystemDocumentPicker` pointe l’intent d’arborescence vers `com.android.documentsui` / `com.google.android.documentsui`, avec repli sur la résolution par défaut s’il n’est pas exporté, désactivé ou absent. Si un OEM a remplacé le gestionnaire par défaut, l’application explique d’abord que les cartes SD / clés USB peuvent être invisibles, puis propose trois entrées : sélecteur système / informations de l’application qui a pris la main (effacer son « par défaut ») / continuer avec le défaut. Les trois emplacements de sélection d’arborescence (page d’autorisation, dossier de sauvegarde en un geste de l’espace de travail, source de sauvegarde de projet des données natives) sont unifiés ; le manifeste ajoute les `<queries>` des deux paquets système et `OPEN_DOCUMENT_TREE` ; `SystemDocumentPickerTest` couvre en 7 cas l’entrée système forcée, la détection de reprise OEM et le repli.
- Les pastilles d’état des canaux d’appareil ne chassent plus les boutons et interrupteurs (`cfad29009`) : les quatre lignes Root / Shizuku / ADB / appareil externe deviennent « colonne de titre + pastille d’état » avec répartition par poids ; les boutons de vérification / appairage et les interrupteurs sont mesurés d’abord, et un état long se replie dans la colonne de gauche ; nouvelle `ShellChannelStatusPill` (6 lignes maximum, sans ellipse, interligne 2 dp), l’état de l’appareil externe rejoint la colonne de gauche ; `DeviceGrantsLayoutTest` ajoute des régressions état long / chinois-anglais / police 1,3× où les actions gardent leur largeur et restent à l’écran.
- « Masquer des applications récentes » reçoit une garde de contenu et un mode strict expérimental (`76b3a44a6`) : sur Android 13+, RecentTasks conserve la « tâche visible la plus récente », donc un glissement depuis l’application vers les applications récentes laisse la carte courante au système, et l’API publique ne peut pas retirer seulement cette carte sans terminer l’UI. Le nouveau `ui/RecentsPrivacyGuard` (cycle de vie au niveau Application), interrupteur activé, tous les écrans désactivent le contenu de la capture dans les récents (API 33+) ; le mode strict expérimental (désactivé par défaut) termine la tâche UI 700 ms après que toute l’application est passée en arrière-plan, mais pas pendant un sélecteur à résultat en cours (SAF), en picture-in-picture, en multi-fenêtres ou pendant une rotation ; les échecs sont journalisés sans plantage ni rejeu ; `BrowserTasks` relit la liste des tâches et les drapeaux du root Intent après application : liste vide ou drapeau incohérent est désormais un échec (`RECENTS_HIDE_APPLY` / `RECENTS_HIDE_VERIFY`), plus un faux succès ; les Réglages ajoutent la sous-ligne du mode strict (masquée quand l’interrupteur parent est désactivé) et les chaînes en dix langues `m9500`–`m9502`.
- Mise à jour de l’environnement géré : les changements de `DshaApp` / `ConfigStore` recalculent `runtimeId` en `28dc573a` ; les entrées fixes restent figées sur 20261105e ; le `dsh-web-mobile` intégré reste sur l’upstream 3.3.1 et activé par défaut.
- Version et périmètre : versionCode porté à 347 (base build346 publié / `86f91ba0a`) ; la révision DSHA reste `0.2.1-rc.5` avec DSH intégré `0.2.2-rc.1`. Cette fournée ne change pas la liste blanche du shell de l’appareil et n’assouplit pas les gardes d’exécution.
- **Non vérifié / non accepté** : sur OnePlus C16, le contenu de la carte courante est-il vide lors d’un glissement depuis l’application vers les récents, la carte disparaît-elle après Home, le mode strict la retire-t-il alors que le keep-alive dsh Web / terminal / ADB fonctionne encore ; l’entrée du sélecteur système et l’autorisation d’arborescence réelle en cas de reprise OEM ; l’acceptation visuelle des quatre lignes de canaux en jour-nuit / écran court / police 1,3× / RTL ; le résultat réel de la relecture `BrowserTasks` sur un nouveau ROM. **build347 n’est pas encore validé sur appareil** : l’acceptation est une première installation 346→347 réussie, des données intactes, READY, la mise à jour de l’environnement géré et le comportement des trois fonctions ci-dessus ; l’acceptation sur appareil des paquets officiels build344–build347 attend l’utilisateur.
