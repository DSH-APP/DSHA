# DSHA 0.2.1-rc.3-20261101.1430-dsh0.2.1-rc.5 / build245

- 「中断したメンテナンスを復旧」は、復旧待ちのトランザクションと読み取れない記録を区別するようになりました。記録を読み取れない場合は、種類・原因・次の手順を示し、生のエラーコードだけを出すことはなくなりました。失敗が確実なスキャンも繰り返しません。
- プラグイントランザクションログを読み取れない場合、メンテナンス画面に「読み取れないプラグインログを隔離」が表示されます。一覧の記録をネイティブで確認すると、そのまま `plugin-install-quarantine` へ移して一覧を残します。削除も再実行もせず、確認後に記録が変わった場合は実行を拒否します。セッションと設定には影響しません。関連プラグインは後で再インストールが必要になる場合があります。緊急修復画面でも同じ操作ができます。
- ホストデータ、ランタイム、環境再構築のトランザクションは途中まで適用されている可能性があるため、読み取れなくても自動隔離はしません。正確な原因を示し、診断を書き出してサポートに連絡するよう案内します。ロールバックを飛ばして個人データを不整合にしないためです。
- 新旧のデータディレクトリが両方ある場合のデッドロックを修正しました。以前はすべての検査が読み取りに失敗し、そのせいで「データディレクトリを選択」も拒否されていました。現在はこの状態でデータディレクトリを選択できます。他の復旧待ちトランザクションは引き続き先に処理が必要です。
- 検証範囲：ローカル単体テストとプラグイントランザクションの Python 回帰テストに合格。端末での検証はしていません。versionCode を 245 に引き上げ。DSHA リビジョンは 0.2.1-rc.3、同梱 DSH は 0.2.1-rc.5 のまま。
