# DSHA 0.2.1-rc.5-20261108.0300-dsh0.2.2-rc.1 / build339

- تأكيد ثانٍ عند تبديل إعداد التعرّف على الشاشة (T113، `29c5028b`): عند اختيار الشاشة الفعلية أو الافتراضية في الإعدادات → أذونات الجهاز → التعرّف على الشاشة، يُعرض أولًا تأكيد `DshaDialogBuilder` (يوضح نطاق القراءة وإمكانية السحب)، ولا يتم التبديل إلا بعد التأكيد. النجاح والفشل وانتظار التنظيف والتحديد المتكرر تحصل على حالة داخل السطر وtoast، ولا يُتخطّى التأكيد بسبب نمط «السماح للكل». الوحدة الجديدة `ScreenModeFeedback` هي المصدر الوحيد لقاعدة التأكيد وأسماء الأوضاع ونصوص النتائج؛ تُتجاهل النقرات المتكررة أثناء التبديل؛ حوار التأكيد بالصينية/الإنجليزية قابل للتمرير على شاشة 320dp وخط 1.3×.
- تبسيط صفحة بدء DSH الطارئ وتوحيد مستوى تدفّق التأكيد (T92، `da0b9b71`): يُختصر شرح الشاشة الأولى إلى سطر استنتاج + ⓘ؛ وتُدمج الحالة وأزرار البدء/الدخول/الإيقاف الثلاثة في بطاقة واحدة؛ ويُطوى مفتاح API المؤقت افتراضيًا، وتنتقل التشخيصات/السجلات/النسخ الاحتياطي/العودة إلى الاستعادة إلى «المزيد»؛ وتظهر الحالة ونتائج الإجراءات بتلاشٍ عبر UiMotion. يُضاف `RecoveryRepairSheet` إلى تدفّق التأكيد: الاختيار والمعاينة يتبدّلان داخل الحوار نفسه، والرجوع يعلو مستوى واحدًا فقط، وتُعطَّل النقرات المتكررة أثناء توليد المعاينة، ويبقى التنفيذ/الرفض داخل المحتوى القابل للتمرير (الشاشات القصيرة والخطوط الكبيرة)، ولا يظهر مدخل تنفيذ عندما يكون معرّف الاقتراح فارغًا؛ ويصبح ترويسة Web الطارئ عنوانًا من سطر واحد + إجراء قصير «اقتراح إصلاح» + أيقونة إعادة تحميل + فاصل.
- حارس تركيز كلمة المرور قبل كتابة المساعد للنص على الشاشة الافتراضية (T97 P1، `8b82e4f7`): كان مسار ASCII السريع في `/app/vscreen/type` ينفّذ `input text` مباشرة في Core ويتجاوز فحوص كلمة المرور في إمكانية الوصول. تُضاف `VirtualScreenTextInputPolicy` (رفض صارم لتركيز كلمة المرور، السماح بالتركيز الآمن، fail-closed عند وجود قناة دلالية لكن التركيز غير قابل للقراءة، والحفاظ على قدرة ASCII الموثقة مع `passwordFocusChecked=false` عند عدم اتصال إمكانية الوصول) و`VirtualScreenPasswordProbe` للقراءة فقط (يعيد التحقق من نافذة التطبيق الوحيدة للشاشة الحالية عبر ACTION_AUTHORITY ويقرأ `FOCUS_INPUT`، ويعيد `SCREEN_TARGET_CHANGED` دون إرسال إذا تغيّرت النافذة). يُفحص قبل إرسال ASCII: كلمة المرور تعيد `PASSWORD_INPUT_UNAVAILABLE` (`state=NOT_SENT`، `nextAction=REPORT_TO_USER`)، والتركيز غير المقروء يعيد `PASSWORD_FOCUS_UNVERIFIED` (`retryable`، `SEE_AGAIN`)؛ كما تُغلق كتابة غير ASCII وكتابة عقد كلمة المرور عبر node `set_text`؛ ولوحة أصلية تعمل بعقد مستقل ولا تتأثر. لا يوجد «السماح رغم ذلك».
- إصلاح وصلة اختبار CI الخاصة بـ T97 (`d16b0c14`، بنية اختبار): يضيف `VirtualScreenInput` علامة forced-available على مستوى النسخة كي لا تختطف فحوص المضيف `/system/bin/input` نسخ الاختبار (ملف غائب على GitHub runner تسبب في فشل اختبارات T97)؛ نسخ الإنتاج لا تضع العلامة، وغياب الأمر الحقيقي لا يزال يُرفض، و`systemCommandExists` لم يُخفَّف.
- إعدادات مسبقة بيضاء لمواصفات عرض الشاشة الافتراضية (T99، `c33f358d`): يبقى الافتراضي 1008×1792@320 (16:9 / 504×896 dp)، وتُضاف قاعدة توافق compat-720 = 720×1600@320 (20:9 / 360×800 dp)؛ المواصفات المجهولة/الفارغة/المتجاوزة للميزانية تعود إلى الافتراضي، ولا تُقبل أحجام أو dpi عشوائية. إنشاء Manager ودورانه يمرران إلى Core معرّف preset والاتجاه فقط، ويحل Core القائمة البيضاء ويطبّق dpi ويعيد قراءة preset/density/الأحجام المنطقية؛ يحفظ `VirtualScreenDisplaySettings` الاختيار، وتضيف صفحة الشاشة الافتراضية زر راديو «حجم العرض» يؤثر فقط في الإنشاء التالي أو إعادة البناء بالدوران، دون تغيير هوية الإطار الحالي أو بوابة الإدخال. تبقى ميزانية المراقبة 2 إطارًا / 24 MiB، وإطارا 1440×2560 (~28.1 MiB) ليسا في القائمة البيضاء؛ ولم يُجرَّ اختبار compat-720 على جهاز.
- «الإجراء كمراقبة» وsettle المدفوع بالأحداث للشاشة الفعلية (T105، `c6a2ea84` / `c94df74d` / `00dd7a90`): تقبل نقاط إجراء `/app/ui` وسيطًا اختياريًا `observe=1` — بعد `COMPLETED` يُجري الطلب نفسه settle (أول حدث إمكانية وصول ≤800ms، هدوء 250ms، سقف كلي 2.5s؛ قابل للمقاطعة بإلغاء المهمة والموعد النهائي، دون استعلام مشغول) ويعيد قراءة الشجرة، ويضيف في الإيصال `treeId`/`nodeId` جديدين والشجرة النصية وبيانات settle؛ إجراءات الإحداثيات لا تعيد لقطة شاشة، وما زالت بيانات الإحداثيات تتطلب لقطة منفصلة. حذف الوسيط يبقي السلوك القديم؛ فشل المراقبة يكتب `observationUnavailable` فقط ولا يغيّر حالة الإجراء؛ لا يُعاد تشغيل UNKNOWN؛ رفض انتهاء البيانات يرفق شجرة الشاشة الحالية الجديدة لإعادة المحاولة ببيانات جديدة. تضيف `dsh-computer-use-android` المدمجة `observe` اختياريًا في أدواتها السبع (عند الحذف يحقن خادم MCP `observe=1`، و`observe:false` يعطّله؛ تُضاف حقول اختيارية فقط ولا يُخفَّف التحقق الصارم من الوسائط). نداءات `/app/sense/state` المتتالية تعيد افتراضيًا فرقًا: تغيّر أكثر من الثلث، أو تغيّر النافذة/الحجم/التركيز/المصدر/حالة الاقتطاع، أو تغيّر الجيل أو الهدف، أو `full=1` تعيد لقطة كاملة، وعدم التغيّر يعيد `mode=same` بسطر واحد؛ تُضاف `mode`/`deltaReason`/`previousSid`/`changedElements` و`format=v4-preview-3`. يبقى `k***` رقم موضع في ترتيب القراءة، والإجراءات تستمر في استخدام عقود `treeId`/`nodeId` لمرة واحدة. تمت مزامنة `/app/help` بالصينية والإنجليزية.
- إرشاد عدم تطابق إصدار إضافات المستخدم بعد ترقية وقت التشغيل (T93، `bebc01b4`، وثائق): تحديثات APK/DSH فوق السابقة لا تعيد كتابة قائمة الإضافات الخارجية في ملف تعريف المستخدم أو `node_modules`؛ وفحص التوافق المسبق في DSH يتخطى الحزم غير المتوافقة ويعطّل الإدخالات المطابقة حسب `engines.dsh` ونطاقات peer `@deepseek-ai/dsh*` (fail-safe، دون حذف أو إعادة كتابة تلقائية). تتم المعالجة بإعادة التثبيت من إدارة الإضافات واستثناءات الإصدار الدقيقة في `compatibility.json`، وليس بتحرير الملف يدويًا؛ كما يوضح أن أسطر البدء المتكررة من مداخل cordis متعددة للحزمة نفسها ليست استيرادًا مزدوجًا (وStartupTrace يزيل الأسطر المتطابقة المتجاورة).
- تقييم تصميم مساري المراقبة للشاشة الفعلية (T107، `ee5adfde`، وثائق): يوصي بالاتجاه C (قراءة مرآة بامتياز + كشف إدخال المستخدم الفيزيائي عبر evdev)؛ كشف نشاط المستخدم لا يعتمد على الإطارات، وإطارات المرآة لا تصدر أبدًا بيانات إحداثيات/إجراء، ويبقى النهج الخفيف A كاحتياطي بلا امتياز مع `userActivity=UNKNOWN`؛ الأذونات مغلقة افتراضيًا وتُفعَّل لكل مهمة وقابلة للسحب وfail-closed عند الفشل. هذا الإصدار تقييم فقط: لا كود منتج، ولا تحقق على جهاز من التقاط الإطارات/evdev/أذونات القنوات.
