# DSHA 0.2.1-rc.5-20261106.0230-dsh0.2.2-rc.1 / build330

- Виртуальный экран больше не принимает сам хост в качестве цели запуска (T76): `/app/vscreen/launch` не позволяет запускать сам DSHA на виртуальный экран. Система не создаёт отдельный экземпляр для дополнительного дисплея, а повторно использует тот же работающий процесс; WebView, уже привязанный к основному display, на дополнительном дисплее падает с нулевой ссылкой в `libmonochrome` (доказательство с устройства relay: display 4, цикл Looper главного потока входит в WebView, повторно использован процесс 14715). bridge отказывает до запроса авторизации, Manager — до claim, Core — до отправки `am start`; все три уровня используют одну проверку и возвращают `VSCREEN_SELF_LAUNCH_REFUSED` (`state=NOT_SENT`, команда запуска не отправляется, падения нет); встроенный плагин относит этот код к pre-dispatch, нативный выбор приложений больше не показывает хост, а страница результата выводит причину на китайском и английском. Это защитный отказ, а не поддержка self-launch на дополнительном дисплее; для поддержки позже нужен `createDisplayContext` с отдельным экземпляром WebView. runtime-descriptor перегенерирован (runtimeId `35e3f499`); фиксированные входы не пересобираются.
- Исправление управляемого актива gh в APK (T79, вывод B из T78): официальные APK build328/329 содержат только `assets/gh-cli.tar` (38 727 680 B, STORED), без `gh-cli.tar.gz` — слияние активов AGP 9.1.1 автоматически распаковывает `.gz` и убирает расширение, поэтому управляемая установка, открывающая `gh-cli.tar.gz`, обязательно завершается ошибкой (самозагрузка обёртки может восстановить). Имя исходного фиксированного входа и pin `runtime-descriptor.json` не меняются, фиксированные входы не пересобираются; имя упаковки в APK становится `gh-cli.bin`, `RuntimeTools` открывает упакованное имя и откатывается к исходному, а новый релизный гейт `tools/verify-apk-managed-assets.py` проверяет фактические имена членов, побайтовые дайджесты и закреплённый член gh в цепочках сборки официального и тестового пакета, чтобы тихое переименование не повторилось. runtimeId обновляется вслед за изменением управляемого генератора до `35e3f499` (фиксированные входы не пересобираются).
- Объём проверки: полная группа contracts хоста, проверка форматирования всего дерева (JDK 17) и целевые модульные тесты (VirtualScreenPolicy, VirtualScreenManager ownership, страница обновления); локальная проверка на устройстве не выполнялась. Код версии повышен до 330 (на базе build329); редакция DSHA остаётся 0.2.1-rc.5, встроенный DSH — 0.2.2-rc.1.
