# DSHA 0.1.6-alpha2 · build 136

本地 Release 交付记录，日期：2026-09-18。应用版本名为 `0.1.6-alpha2`，兼容版为 `0.1.6-alpha2low`，版本码 136；包名仍为 `com.dsh.client`。内置 DSH 为 `0.1.6-alpha.2`，Ubuntu 基础环境仍为 10，受管运行时身份为 `2e042447828c6a56c46994091021f8cc71e037f0aa7a836d8834c1aae83eaa98`。

## 变更

- 同步 alpha.2 的插件管理、Session 多实例、InputHub、文件改动卡片、Office 预览、浏览器模式、Subagent 侧栏和新版 PTC 入口。
- 适配新版客户端脚本拼接器、Agent 预设、模型设置入口、Session 导航和图片草稿接口。图片草稿改用实际 Session binding，不枚举已移除的旧 `Map`。
- 插件安装、删除和第三方启用增加 DSHA 原生审阅门禁；网页入口导航到原生预览/管理页，Host 侧再按真实安装锚点、依赖和事务记录核验。内置/受管插件仍可按原流程启用。
- 插件刷新、启用、停用和删除在同一容器任务中返回最终列表；原生任务快照和“后台任务”页面显示阶段、耗时及对应入口。
- Office 转 PDF 使用随包 LibreOffice WASM；Android 默认加入只读 `/system/fonts`，不复制系统字体，保留缺失字体列表。
- 更新应用图标为用户提供的 DSHA 图片（原图按比例保留并生成各密度/自适应图标资源）；悬浮条采用 32ms 合并渲染、稳定行数和窗口尺寸更新；画中画按实际窗口比例重排逻辑视口。
- 修复通知栏正文点击无响应：前台运行、ADB 状态/错误、Agent 确认、安全确认、数据维护和更新下载通知均带有回到 DSHA `MainActivity` 的 `PendingIntent`；通知中的允许/拒绝、停止等操作按钮仍保持各自独立的接收器动作，不会被正文入口替代。静态门禁脚本 `tools/test-notification-actions.py` 已覆盖这些通知来源。
- Web UI 顶部移动端会话栏拆分为状态/标题行与预设、文件、更多操作行，避免窄屏控件互相覆盖；Web 返回箭头只回 DSHA 启动页，画中画只由“小窗”按钮显式进入，返回桌面不再隐式缩成小窗。
- 修复 issue #22 的离线备份凭据链：备份开关明确允许时注入 `.dsh/.dsha-apikey`，旧归档恢复会回填 Android Keystore；未包含或回填失败会如实提示，并在空环境提供旧 Download/DSHA 备份的预检/手动选择入口。
- 修复受管运行时隔离试运行把可选插件 loader 输出误判为 `TRIAL_PLUGIN_FAILED`：只有 DSHA 自有检查插件导入或应用失败才立即拦截，其他插件输出交由网页、鉴权、存储、会话和渲染检查判定；真实失败会显示脱敏原因。
- 「安装与环境」和运行时维护页均提供“格式化并全新开始”。两级确认后会停止 Web、终端和写任务，并逐阶段显示旧公开数据、运行环境、会话、插件、本机备份、缓存、设置与 API Key 的清理进度。完成后不结束应用，直接清空任务栈进入欢迎页；手动导出的备份和其他个人目录保留。

隔离 Windows/Node 24 环境执行了 alpha.1 → alpha.2 → alpha.2 重启对照：同一 Session ID、凭据配置、嵌套工作区文件摘要均保持；实际模型请求由本机确定性 HTTP fixture 驱动，未访问付费模型。`write`、`read`、`edit`、`glob`、`grep`、`skill`、`bash`、`pwsh`、`job_list`、`present` 和 `run_code` 均完成并复读结果。

Android 13 Redmi 使用原 APK 数据目录做非破坏性覆盖安装。更新前 7 个会话文件与 `settings.yaml` / `.credentials.yaml` 摘要保存，更新后逐项 SHA-256 一致；随后使用隔离目录执行 alpha2 的升级、重启和新 profile 回归。最终真机又完成一次真实受管运行时更新，隔离试运行、切换和旧健康副本核验均成功，没有再出现 `TRIAL_PLUGIN_FAILED`；`settings.yaml`、`.credentials.yaml` 和工作区索引更新前后摘要一致。没有卸载、清空数据或修改用户插件。

Office 隔离回归中 DOCX、XLSX、PPTX 均生成有效 `%PDF-` 输出；Android 字体补丁在最终构建中已打包。桌面群反馈中的数据/工具异常未在 DSHA 隔离回归中重现；桌面端安装形态与数据目录不属于本机 Android 验收范围。

## 界面与设备验证

- 两种网页内核的浏览器 smoke、中文多行输入、图文草稿刷新恢复、文件侧栏和返回入口通过；顶部会话栏在窄屏实机重新排版后无遮挡。
- Agent 预设保留完整服务端选项，自定义预设通过 Host 返回值核验；Subagent 触摸在 393px 与 920px 视口通过。
- Android Computer Use 六个工具的 schema、发现和取消回归通过；没有在测试中执行破坏性设备命令。
- 插件刷新基线约 3–8 秒；合并路径在当前真机空闲状态约 5–6 秒，重复启动扫描已删除。后台任务按钮可打开只读进度页。
- 真机 `dumpsys notification` 已确认 DSHA 前台通知存在有效 `contentIntent`（目标为 `com.dsh.client` 的启动 Activity）；在 DSHA 切到后台后实际下拉通知并点击正文，已回到 DSHA 启动界面，通知按钮仍保持独立动作，会话及 Web 状态未报错。
- 真机确认格式化入口在「安装与环境」常驻显示，第一次确认列出删除与保留范围，第二次确认明确不可撤销、展示清理过程并在完成后直接返回欢迎页。验收没有点击最终“删除全部并格式化”，正式数据保持原位；目录删除、任务状态消费和欢迎页门禁由隔离单测与构建检查覆盖。
- 已知设备运行时：该手机的 proroot 触发 glibc `pthread_stack_min` 崩溃，因此本轮真机验收切换到稳定 proot；不能把 proroot 声称为通过。用户原有运行偏好及权限状态在结束时恢复。
