# DSHA 0.2.1-rc.5-20261106.1830-dsh0.2.2-rc.1 / build333

- Доступ к файлам между приложениями (SAF, PR #3, review `5797594537` APPROVE, merge `9cc91f5e`): в разделе «Настройки → Разрешения возможностей устройства → Системные разрешения» появился пункт «Доступ к файлам между приложениями». После того как пользователь выдаёт каталог через системный выбор документов, DSHA сохраняет доступ на чтение и запись (до 8 деревьев); страница разрешений управляет ими и предлагает просмотр только для чтения с текстовым предпросмотром. Добавлены конечные точки моста `/app/saf/*` (trees / ls / stat / read / write / push / pull / mkdir / rm; read 256 КиБ за вызов, write 16 КиБ, push/pull 32 МиБ, списки 500 записей; `rm` использует двухэтапный одноразовый токен), протокол моста остаётся версии 3 (только аддитивные изменения). Границы безопасности: принимаются только короткие id из реестра разрешений, запись и удаление требуют, чтобы дерево было доступно для записи, пути контейнера используют `BridgePathPolicy` (области учётных данных недоступны для чтения и записи), а локальные файлы открываются с `O_NOFOLLOW` + dev/ino + проверкой реального пути через `/proc/self/fd`, жёсткие ссылки и сущности `.l2s` отклоняются. Встроенная подсказка `dsh-device-shell-guide` и `/app/help` получают по одному предложению о входе. Управляемые входы пересчитывают runtime descriptor в этом PR (runtimeId `04b24571`); фиксированные входы не пересобираются.
- «Настройки → Опыт»: добавлен переключатель «Скрыть в фоне» (`73896284`, вспомогательное средство для keep-alive через ADB): по умолчанию выключен, это локальная настройка устройства, не входящая в список резервного копирования. При включении все действительные задачи приложения убираются из недавних; при выключении они восстанавливаются и переклассифицируются по существующему правилу «только одна основная карточка». После перезапуска приложения или повторного открытия после завершения процесса настройка перечитывается и применяется; при неудаче пишется `RECENTS_HIDE_APPLY` и выполняется повторная попытка при следующем запуске. Влияет только на видимость в недавних: не меняет `DeviceBridgeService`, постоянное уведомление, foreground-сервис и семантику остановки; это не обещание keep-alive (без защиты от Doze, экономии энергии производителя или принудительной остановки).
- Исправление согласованности интерфейса страницы разрешений (`8509ae0a`): статусные пилюли теперь адаптируются внутри `PluginFlowRow` (`wrap_content` с минимальной шириной 56dp; переносятся на новую строку вместо сжатия в четверти), строка статуса теряет отступ 12dp и может занимать две строки, а размеры заголовка и статуса перенесены в `device_grants.xml` (12sp). Слово состояния «выключено» в остальных 9 языках теперь использует существующий перевод «закрыто» (китайский сохраняет 关闭 / 關閉) для статуса сводки, распознавания экрана и уровней буфера обмена, не затрагивая строку «кнопка закрытия». Панель сводки уплощена до `shell_bg` + нижняя `shell_line` 1dp, убраны нижние углы 16dp, сильная обводка и тень 2dp; на коротких экранах (`screenHeightDp ≤ 480`) панель переходит в область прокрутки, а при обычной высоте остаётся закреплённой со ссылками перехода.
- Объём проверки: полная группа contracts хоста, проверка форматирования всего дерева (JDK 17), `generate-changelog --check`, проверки ссылок документации и чистоты исходников, шлюзы `test-release-*` и целевые модульные тесты (страница обновления, пять классов SAF плюс маршрутизация, `TaskNavigationPolicy`, `BrowserTasks`, `ConfigStore` скрытие в фоне, вёрстка разрешений). **Ни одна из двух новых функций не проверена на устройстве**: в наборе `androidTest` есть существующая ошибка компиляции (`RecoveryInstrumentation` вызывает `HarnessService.refreshPowerMode()` без `Context`), а реальное поведение в недавних задачах и пиксельное обрезание на странице разрешений (шрифт 1,3×, короткие экраны, RTL) ещё требуют проверки на устройстве. Код версии повышен до 333 (на базе build332); редакция DSHA остаётся 0.2.1-rc.5, встроенный DSH — 0.2.2-rc.1, runtimeId остаётся `04b24571` (изменения версии и документации не меняют управляемые входы).
