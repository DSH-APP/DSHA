# DSHA 0.2.1-rc.5-20261108.0900-dsh0.2.2-rc.1 / build342

- Three press-feedback variants (`PressFeedback`, A1 / C1 / C2, `99c971d6c`): tappable rows gain only a state layer (content and layout unchanged), primary buttons scale to 0.985 while pressed, and large cards morph their corner radius from 18 to 22 dp; with system animations off everything degrades statically, and disabled buttons never enter the scale gesture. `UiMotion` gains rolling numbers, corner morphs and region cross-fades. Twenty-five pages are wired in: shared buttons and rows in `OnboardingKit` / `CardPage`, the `CardSheet` footer, and `attachButtons` on 25 page root views (launch / settings / device grants / data backup / install and maintenance / update / diagnostics / plugins / virtual screen / emergency / recovery / files and more; the terminal's custom touch area and WebView are excluded).
- Inline loading buttons `LoadingAction` (A2, `2d261ff4f`): a real 16 dp spinner appears on the button's left, the measured width locks while busy, taps are disabled and `stateDescription` is written; finishing restores the original label and width. Repeated `start` is refused, the synchronous `run()` restores even on exceptions, and a static arc is shown when system animations are off. One-tap backup shows the inline spinner and locks width when the real task starts; deploy / maintenance buttons are already hidden while busy with a separate progress area, so no fake loading state is stacked on them.
- Rolling numbers and status cross-fades (E5 / G4, `3bbae9e68`): `RollingNumber` remembers the previous value and rolls to the new one, keeping the unit with the formatter and landing directly when animations are off; `FadeSwap` writes the value first and fades it in, and region content fades out for 90 ms, rebuilds and fades in for 150 ms, keeping only the last of consecutive refreshes. The storage page rolls its total from the previous value; the workspace status, automatic-backup status and maintenance-page header switch via FadeSwap text.
- Card tiers and status badges (H1 / H2, `055b400c4`): three tiers — elevated primary (surface + hairline + 1 dp lift), filled group (raised solid, no stroke) and outlined secondary; groups unify on filled, and `CardPage.card(Tier)` lets pages choose explicitly. Badges (>99 shows 99+) and status dots use only `shell_*` tokens and can be recolored on the same View; the workspace status card is elevated, the automatic-backup dot recolors with the switch, and the multi-select bar uses a count badge.
- Selectable cards and multi-select bar (D1 / D2 / H3, `708206da3`): `SelectableCard` renders single-select as a 2 dp stroke + tint + check, and multi-select as a check box; compact cells hide the check to avoid truncation, and screen readers report `radio` / `checkbox` checked. `SelectionActionBar` shows a selected-count badge and actions, collapsing the count at zero items without shifting the action bar. Wired into the language cells, virtual-screen preview tier (in-card single select replacing the single-choice dialog) and export-scope cards; retained copies and old environments move to a multi-select bottom action bar (selected count + check + refresh / cancel).
