## 自动清理旧环境

- 覆盖更新后，在当前环境健康、DSH 与终端停止、没有数据作业时清理。普通再次打开应用不会重复做整树清理。
- 受管组件保留最近两份健康且内容未变化的前代。是否能读取新数据决定能否回退，不再导致不兼容的旧组件永久堆积。
- 新的环境重建在数据逐文件恢复和运行试验通过后，为旧树建立绑定 inode、树摘要、数据归档和映射的证明，再清理旧 Ubuntu 系统；个人数据验证副本和事务记录保留。
- 旧树被后来修改、含额外文件、证明缺失或数据副本损坏时，保持原件。此前版本没有清理证明的历史重建副本不会被猜测性删除。
- 新重建清理路径使用真实临时目录测试，覆盖成功、未提交、旧树新增文件、归档损坏和空根路径拒绝。未在用户正式数据上做破坏性重建或故障注入。

## 自动备份的范围

正常完成的自动副本保留最近 **3 份**；手动副本与无法核验的记录不自动删除。默认备份对话、附件、设置和插件，不复制 Ubuntu，个人项目使用手动选择目录。原生 API Key 默认排除，设备权限不从备份生效。

自动副本保存在应用私有目录，采用本机保管的随机密码加密。它用于本机恢复；**卸载应用会清除本机副本**。需要换机或卸载时，应导出副本并保存界面提供的解密密码。导出仍重新核对密文摘要。

真机完成实际加密备份及完整恢复预检，预检后取消，未覆盖正式数据。该设备的部分第三方插件依赖存在待核对关系，因此显示“插件依赖待核对”，没有伪报插件完整可恢复。

## 权限与运行验证

- 短信：开关打开时通过 Root 执行 `where 1=0` 的空结果查询成功；关闭后同一查询被策略拒绝，没有读取实际短信内容。
- 传感器：开启后获得传感器列表和光线读数；撤销后接口立即返回关闭状态。
- 定位：本机系统权限已被拒绝。关闭路径确认不返回位置；打开时给出系统权限设置入口并保持关闭，没有伪称定位可用，也没有读取坐标。
- 读屏：允许一次后，超过 **11 分钟**仍能读取本应用界面；撤销后出现新的确认，拒绝后未返回界面内容。临时启用的无障碍服务已按原状态恢复。
- 后台：锁屏前后核对同一 Node PID 与出生时间；本机 HTTP 仍返回正常的未鉴权拒绝。该检查不等同于厂商长期深度休眠或所有网络环境验证。
- 本机首选 proroot 出现明确退出时，按既有策略兼容切换到 proot，界面如实显示实际运行方式。
