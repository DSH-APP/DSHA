# DSHA 0.2.1-rc.5-20261109.0700-dsh0.2.2-rc.1 / build346

- Écran toujours allumé et économie d’énergie désormais exclusifs (`d540dfe9d`) : nouvelle logique pure `util/PowerModePolicy` ; les deux sont désactivés par défaut, en activer un force la désactivation de l’autre et synchronise la persistance, le service et l’indicateur de fenêtre, tandis que désactiver l’un ou réactiver le même n’affecte jamais l’autre ; la page Réglages utilise un garde de synchronisation pour empêcher la récursion du `setChecked` programmatique et affiche un toast bilingue lorsqu’elle force la désactivation de l’autre côté ; au démarrage, un ancien état « les deux activés » est normalisé en écran allumé et économie d’énergie désactivée, silencieusement, puis réécrit. `PowerModePolicyTest` / `ConfigStorePowerModeTest` couvrent les valeurs par défaut, la non-interférence et la branche de démarrage.
- Historique d’activité de l’écran physique M1 (`19d928f3c`) : ajout de `ScreenActivityFeed` (anneau mémoire d’environ 120 s / 64 événements), `ScreenActivityEvent` / `ScreenActivityPolicy` / `ScreenActivityQuery` et `ScreenActivityRecorder` ; il n’enregistre que pendant une tâche téléphone les changements de cible, appuis / défilements de l’utilisateur, changements de contenu et actions de l’assistant ; fin de tâche, pause, déconnexion ou reconnexion du service d’accessibilité effacent immédiatement l’historique ; rien n’est écrit sur disque, dans les sauvegardes ou les diagnostics ; les applications sensibles ne gardent que le changement de cible, les champs de mot de passe seulement « déjà saisi », et les événements IME / propres superpositions sont écartés.
- Réponses et outil : chaque réponse JSON `/app/ui/*` porte désormais `recentActivity` (au plus 3 événements depuis la réponse précédente) ; un nouveau `GET /app/ui/history?since=<séquence>&limit=20` sert la lecture incrémentale (20 par défaut, 100 maximum, `since` se poursuit avec `nextSince` ; M1 ne renvoie pas d’images, `frames` est un tableau vide) ; le plugin intégré `dsh-computer-use-android` ajoute l’outil `android_history` et `/app/help` est synchronisé. La configuration d’accessibilité ajoute `typeViewClicked|typeViewScrolled` ; l’exécuteur d’actions enregistre explicitement `ASSISTANT_ACTION` et sépare user / assistant par une fenêtre de dispatch de 1,5 s ; la sémantique des gardes d’exécution (comparaison de cible, TTL des identifiants, politique de confirmation) est inchangée.
- Mise à jour de l’environnement géré : les changements de `DshaAccessibilityService` / `HttpShellService` / `screen/ScreenActionExecutor` / du nouveau `screen/ScreenActivityRecorder` / de la configuration d’accessibilité et du plugin intégré `server.cjs` recalculent `runtime-descriptor` en `7b1ca97d` ; les entrées fixes restent figées sur 20261105e ; le `dsh-web-mobile` intégré reste sur l’upstream 3.3.1 et activé par défaut.
