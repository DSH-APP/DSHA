# DSHA 0.2.1-rc.5-20261108.0030-dsh0.2.2-rc.1 / build338

- Page keep-alive K0–K2 (T110, `ba13ed5f` / `02e187e0`): when the Web host page switches to the native settings / terminal / plugin page inside the same task, the WebView document is no longer destroyed; returning takes over the same page with the same generation / instance and does not `loadUrl` again. The new `BrowserPageKeeper` raises page ownership to application scope, and `onDestroy` handles three branches: configuration change, normal finish and system reclaim. Stop, maintenance, Web process replacement, renderer exit, origin-restore, task removal and low-memory trim retire explicitly, so a real stop is never hidden by keep-alive. K0 adds redacted diagnostics `WEB_ENGINE` / `WEB_PAGE_DESTROY` / `WEB_KEEPALIVE_ATTACH|DETACH|RETIRE` (reason-code allowlist; URLs, cookies and page titles are never recorded).
- In-app round trips no longer reconnect or re-render the whole page (T110 / K5 scenario 1, `b80d8225` / `7f13f06f`): on returning to the Web UI the host dispatches `dsha-browser-resume`, and the managed `app-integration/client.js` first probes the current carrier with one read-only `session.control` stream. Any returned frame keeps the Connection and skips rebuilding the Remote baseline, so long pages no longer re-render wholesale or stall on loading; if the probe times out while the Connection is still `connected`, it is not reset either (a truly dead carrier is left to the server heartbeat / socket close); a disconnected Connection or missing probe capability falls back to the previous behaviour. A new redacted `WEB_PAGE_RESUME` diagnostic records impl / trigger / state / probe / reset / hiddenMs / inApp for later regression analysis.
- K5 device receipt: scenario 1 (streaming long page, in-app round trip) passed on a LENOVO TB321FU / Android 16 / WebView 140 by user testing — the yellow → green reconnect is gone, streaming output no longer reloads the whole page or stalls on loading, and the draft is preserved. It was validated with the second-round diagnostic test package `3d3866f7` (same fix content as this merge; package `io.github.sunsetrne.dsha.test`). The remaining scenarios (2–13: Home / app switch, system reclaim, process death, rotation and dark mode / language / font, PiP, stop / maintenance / backup, origin-restore, renderer, multi-window, upload/download/microphone, log redaction) and a second device / second WebView were not executed; per the user's decision they are declared experimental and do not block the merge.
- Physical-screen occlusion fix (`bfe82527`): `MainScreenWindowPolicy` now first collects the display-0 covers that sit above the target and intersect it, then computes every edge from the largest crop amount, so the result no longer depends on window-list order or layer. System decoration and IME edge tests gain a 2 px tolerance and an "edge coverage ≥ 80%" rule, and edge strips / small overlays that do not cover enough but extend inward by at most 1/4 of the target's vertical extent are cropped on that edge. Interior coverage still rejects the whole window for coordinates, no partial-occlusion state is introduced, and zero-area / reversed / null bounds are skipped as geometrically non-covering (P2). The ZUI device shape (centered taskbar plus an edge game overlay) moves from whole-window rejection to cropping; floating IME / split screen / PiP and ZUI/vivo device revalidation are not done.
- Virtual-screen status next step (T88, `850875bf`): the standalone `/app/vscreen/status` now adds a machine-readable `nextAction=CREATE_FIRST` and `retryable` when no Core exists (still `ASK_USER_TO_CLOSE` while cleanup is pending) alongside `ok:false` + `VSCREEN_NOT_RUNNING`, keeping the existing error / state / lifecycle fields; `HttpShellService` and `VirtualScreenManager` are managed launcher sources, so the descriptor is recomputed on the merge tree (runtimeId `a77aa93f…`).
- Second UI batch (T114 remainder + error and composite states ⑬, `61245640`): on the startup-recovery page the action row keeps only the action title, the effect description moves into a trailing ⓘ, the unavailable reason stays inline, group descriptions move into an ⓘ next to the title, rebuilt lists restore scroll position and fade in, and result banners transition on appearance / text change. The install page fades its conclusion / status / progress, the stopwatch changes digits without flicker, six-stage transitions are highlighted, and maintenance errors are reduced to a short conclusion + ⓘ per UI baseline ⑬ while keeping the error semantic colour. The diagnostics page cross-fades conclusion / status / buttons and highlights icon steps; the maintenance stage bar is rebuilt only when the stage shape changes; device-grant root-relax warnings and overview capsules fade in and colour dots highlight; data-page state cards fade their conclusion and move paths / native-task details into ⓘ; the transfers page slides back into the list in 160 ms; WebPreview / WebCrashPanel fade the top progress bar and reveal the error state in 180 ms. `UiMotion` gains `crossFadeTimerText` / `flash` / `reveal`, `InfoHint` gains `bindOnSurface`, `StartupRecoveryLayoutTest` is added and the UiMotion / InfoHint suites are extended; the new string "View details:" enters messages-extra with eight translations.
