# DSHA 0.1.7-rc2.1 · build 148

本地修复版，基于已发布的 0.1.7-rc2 / 147；内置 DSH 仍为 `0.1.7-rc.2`，Ubuntu 基础环境版本仍为 10。包名 `com.dsh.client`，Standard 最低 Android 11，Low 最低 Android 6，均仅支持 arm64-v8a。正式 APK 沿用历史 E7E3 签名，可覆盖 rc2 并保留应用数据。本页不表示 GitHub Release 或官网已更新。

## 原因与修复

旧版原生安装器把下载好的第三方插件写成 `DSHA_REVIEW_REQUIRED`，停用并等待人工审阅；直接启用入口也拒绝第三方插件，网页管理器又把安装和启用导向原生审阅。审阅入口不可用时，安装变成无法完成的死路。此外，上游网页管理器安装时传 `enabled: false`，仅移除审阅拦截也不会让插件可用。

rc2.1 将链接、本地包和更新的“解析 → 冻结依赖 → 事务提交”自动串接，提交时默认启用插件。正在运行的正式 Web 会在提交后自动重启，以加载新插件；未运行时在下一次启动加载。网页管理器可直接安装和启用第三方插件，并以 `enabled: true` 安装。旧版精确匹配 `DSHA_REVIEW_REQUIRED` 的安装在升级启动时启用；用户主动禁用和安全模式标记保持不变。同名冲突、缺失依赖和损坏原件仍报告错误，不覆盖当前插件。

真机首次安装还发现：Web 可到达鉴权页面，但浏览器尚未握手时，如果再次启动，旧加载记录会把插件错误地转为“未确认”并停用。现在新一轮启动先复核同一插件内容与依赖，再继续加载；只有实际加载失败或内容变化才停用。用户直接从插件管理页重新启用时，也会重新登记本次加载确认对象。

插件管理搜索框原先未消费硬键盘回车，Android 可能尝试把焦点交给不可聚焦控件并使应用崩溃；本版将搜索完成作为搜索框内的动作处理并收起键盘。

插件包格式、路径越界、压缩包大小、来源摘要和依赖快照继续检查；依赖安装仍禁用生命周期脚本与 pnpmfile。插件代码与 DSHA 共用 Android 应用权限，自动启用意味着安装第三方插件后其代码会在 Web 启动时运行。
