## 本轮修复

### proroot 更新试运行的数据重开失败

alpha.2 的 JSON `per-record` 存储使用 `readdir(..., {withFileTypes:true})` 判断表目录。在本次真机的 proroot 环境中，部分目录项会返回未知类型；记录文件实际已经写入，但重开时整张表被跳过，受管运行时试运行因此报告 `Trial KV reopen mismatch` 并安全回滚。

打包阶段现在为锁定的 `@deepseek-ai/dsh-storage-json` 加入受管兼容补丁：已明确为普通文件或软链接的目录项保持原逻辑，仅对类型未知的目录项使用 `lstat` 核对是否为目录。磁盘格式、记录内容和用户目录均不迁移。补丁带固定标记并纳入 APK 运行时验证；新增回归脚本会把目录项强制模拟为未知类型，验证写入、关闭和重开仍可读回同一记录。

### 插件与社区预设兼容

- Web 插件页的待审阅入口只对“已安装、未启用、确属原生审阅”的插件恢复操作；清单损坏等真实错误继续禁用并显示原因。
- 为旧社区预设引用的 `@deepseek-ai/dsh-workflow-worker-thread` 提供两个受管只读链接，统一指向 alpha.2 的 `@deepseek-ai/dsh-workflow-ptc`；不改写第三方插件源码。
- Low 版只在 API 26–30 使用旧的 `onUserLeaveHint` 画中画入口，避免 Android 6/7 触发不存在的 API 26 调用。
