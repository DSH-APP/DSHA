# DSHA 0.2.1-rc.5-20261106.0400-dsh0.2.2-rc.1 / build331

- Le plantage des grands diffs git sous proroot devient fail-loud (T82) : avec build330 (proroot v1.2.8), `git show --stat`, `git diff --stat` / `--numstat` plantent de façon déterministe pour certains commits ou une combinaison d'au moins 8 chemins en une fois — exit 139, stdout de 0 octet, et seulement `[proroot] SIGSEGV pc=… lr=…` sur stderr. Lorsque la commande est enchaînée à `| head` ou `;`, le rc final est avalé à 0, si bien que la revue ou la fusion peut recevoir silencieusement des données vides. Le nouvel encapsulateur partagé `tools/git_guard.py` lève `GitSigsegvError` (`GIT_PROROOT_SIGSEGV`) dès qu'il voit rc=139 / -11 ou le marqueur sur stderr ; il ne réessaie pas, ne rétrograde pas et ne renvoie pas de sortie partielle, et son message propose des alternatives sûres (`--name-status`, `--dirstat`, fractionnement en ≤7 chemins). Tous les outils du dépôt qui appellent git passent désormais par `git_output`, le nouveau `tools/test-git-guard.py` est enregistré dans le manifeste host-tests, et AGENTS ainsi que la documentation du moteur d'exécution consignent le piège local et les usages sûrs de revue/fusion.
