# DSHA 0.1.5-rc2 · 构建 124

本次合入三项用户反馈：3080 端口占用导致启动失败、按参考图重做原生启动恢复页、恢复 1.1.10 的旧 WebView 提前补齐接口策略。版本码 **124**，dsh 仍为 **0.1.5-rc.2**，Ubuntu 基础环境仍为 **10**。

## 启动端口冲突

用户提供的 vivo Android 16 日志中，实际错误是 `dsh-host-webserver` 监听 `127.0.0.1:3080` 时出现 `EADDRINUSE`，普通和安全启动都失败；日志不能确定具体占用者。

现在优先使用配置端口；占用时先尝试本机曾成功使用的备用端口，否则通过锁定上游支持的 `--port 0` 由系统在真正监听时分配。原首选端口保留，成功备用端口仅保存在本机。实际鉴权地址、保活和 LAN 代理均使用本轮真实端口。动态端口只接受本轮进程完整、唯一的官方 loopback 启动行。探测只尝试绑定，不向占用者连接或发送凭据，也不按端口猜测 PID。

端口冲突会显示为 Web 端口问题，保留原始堆栈。现有 PID 身份核验和停止门禁继续生效，不能绕过已知本应用 Web 尚未退出的状态。

3090 是独立的设备桥端口，不随 Web 自动迁移；若持续被其他实例占用，设备工具仍需等待该端口释放，Web 可独立启动。界面与日志明确提示，不再暗示普通 Web 重启一定能释放它。

测试还发现 proroot 执行安全配置 Python 脚本时可能触发 glibc 辅助向量断言；安全配置和快照脚本现在与插件管理一样，预先选择 proot 执行。Web 本身仍遵循所选运行方式，不在写入结果未知后改通道重放。

## 旧 WebView 兼容

对照本仓库 `v1.1.10` 标签的 `webui-polyfill.sh`，恢复在网页应用脚本执行前补齐 `AbortSignal.any`、`AbortSignal.timeout` 和缺失的 `crypto.randomUUID`。

- 保留已存在的原生实现；合并取消信号时传递源 reason、校验成员并清理监听，避免旧实现丢失取消原因。
- 超时异步触发，长时间等待分段调度，避免普通计时器整数溢出；UUID 使用安全随机数。
- 同一兼容代码覆盖文档起始和 Worker，并在受管 HTML 的应用脚本前插入有界、幂等入口，保留早期 UTF-8 声明。厂商 WebView 不支持原生文档起始接口时，收到的 HTML 本身仍有补丁。
- 页面加载后的能力检查先幂等补齐再检查。仍保留真实能力检测，不通过隐藏错误来假装兼容。
