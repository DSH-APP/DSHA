# DSHA build 151：tar.gz 备份与前后台输出恢复

版本名 `0.2.2-20261001.2046-dsh0.2.0-rc.2`，Low 加 `low`；版本码 151。
内置 DSH 0.2.0-rc.2、Ubuntu 10、包名 com.dsh.client 保持。

## 备份

外部文件统一为 `DSHA-data-v5-<UUID>.tar.gz`，MIME 为 application/gzip。
这是可由标准 gzip/tar 工具打开的封装，包含原已验证的 `portable.dshbak` 和 README.txt。
内层继续使用可选密码 AEAD 或无密码 DSHADATA 完整性校验；原密码、实际范围、部分备份与插件警告等级保留。
手动导出和私有副本重新导出使用相同封装，自动副本内部格式保持。

导入先完整检查外层 gzip CRC、tar 头和尾部、唯一载荷、普通文件类型、路径和大小，
再执行既有内层认证、实际清单预检及原生确认。旧裸 dshbak 与历史 tar/gzip 继续可读，文件名不授予全量恢复资格。
保存位置选择期间进程被回收后，丢失的导出请求要求重新发起，不猜测密码选项。
目录记录分别保存外层文件摘要与内层载荷摘要。

封装与读回验证会临时增加磁盘占用，峰值可接近三份备份体积；空间不足会失败并保留已验证副本。

## 前后台输出

代码中确认的缺口：原生恢复浏览器绘制后没有请求重建 DSH 官方 Connection。
后台传输已失效但仍标为 OPEN、或浏览器暂停期间漏掉 online 回调时，客户端可能持续停在等待状态。
保活服务的 TCP 探测无法判断网页订阅的这种失效。

WebView / Gecko 恢复到当前已鉴权页面后触发合并的连接恢复，官方连接同时替换物理 WebSocket、
重新同步 journal/snapshot 中的已产生输出；不重新提交 prompt，不重启 Node，不刷新整个页面。
恢复信号早于网页可见时先保留意图，隐藏期间不重连；页面销毁撤销定时器与监听。
Native 入口核对页面/会话、源、鉴权和运行代次，手动停止及旧页面不触发恢复。
既有草稿和附件缓存继续使用原恢复链。

可见页面同时为已启动的本机 Web 补齐前台服务，覆盖 LAN 未开启的情况；
复用服务前核对保活线程实际存活状态，迟到的 ACTION_START 再检查手动停止和既有运行状态。
客户端断流使用连接恢复，保留原有 PID 出生身份和停止屏障。
