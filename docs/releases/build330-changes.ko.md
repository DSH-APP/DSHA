# DSHA 0.2.1-rc.5-20261106.0230-dsh0.2.2-rc.1 / build330

- 가상 화면에서 호스트 자체를 실행 대상으로 거부(T76): `/app/vscreen/launch`는 DSHA 자신을 가상 화면으로 실행하는 요청을 더 이상 받지 않습니다. 시스템은 보조 디스플레이용 별도 인스턴스를 만들지 않고 실행 중인 같은 프로세스를 재사용합니다. 기본 display에 이미 바인딩된 WebView는 보조 디스플레이에서 `libmonochrome` 널 포인터로 충돌합니다(relay 실기기 증거: display 4, 메인 스레드 Looper가 WebView로 진입, 실행 중 프로세스 14715 재사용). bridge는 승인 질문 전에, Manager는 claim 전에, Core는 `am start` 발행 전에 같은 판정으로 거부하며 `VSCREEN_SELF_LAUNCH_REFUSED`(`state=NOT_SENT`, 실행 명령을 보내지 않고 충돌하지 않음)를 반환합니다. 내장 플러그인은 이 코드를 pre-dispatch로 분류하고, 네이티브 앱 선택기는 호스트를 나열하지 않으며, 결과 페이지는 중국어/영어 사유를 보여 줍니다. 이는 안전 거부이며 보조 디스플레이 self-launch 지원이 아닙니다. 나중에 지원하려면 `createDisplayContext`와 별도 WebView 인스턴스가 필요합니다. runtime-descriptor는 재생성(runtimeId `35e3f499`), 고정 입력은 재구성하지 않습니다.
- APK 관리 gh 자산 수정(T79, T78 결론 B): 공식 build328/329 APK에는 `assets/gh-cli.tar`(38,727,680 B, STORED)만 있고 `gh-cli.tar.gz`가 없습니다. AGP 9.1.1 자산 병합이 `.gz`를 자동으로 gunzip하고 확장자를 떼기 때문에 `gh-cli.tar.gz`를 여는 관리 설치가 반드시 실패합니다(래퍼 부트스트랩이 복구 가능). 소스 고정 입력 이름과 `runtime-descriptor.json` pin은 그대로 두고 고정 입력도 재구성하지 않습니다. APK 패키징 이름을 `gh-cli.bin`으로 바꾸고 `RuntimeTools`는 패키징 이름으로 열고 소스 이름으로 폴백합니다. 새 `tools/verify-apk-managed-assets.py` 릴리스 게이트가 정식 패키지와 테스트 패키지 빌드 체인에서 실제 멤버 이름, 바이트 다이제스트, gh 고정 멤버를 확인하여 다시 조용히 이름이 바뀌지 않도록 합니다. runtimeId는 관리 생성기 변경에 따라 `35e3f499`로 갱신됩니다(고정 입력은 재구성하지 않습니다).
- 검증 범위: 호스트 contracts 전체 그룹, 전체 트리 포맷 검사(JDK 17), 대상 지정 단위 테스트(VirtualScreenPolicy, VirtualScreenManager ownership, 업데이트 페이지). 이 기기에서 실제 기기 검증은 하지 않았습니다. 버전 코드를 330으로 올립니다(build329 기준). DSHA 개정 번호는 0.2.1-rc.5, 내장 DSH는 0.2.2-rc.1입니다.
