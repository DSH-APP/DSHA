# DSHA 0.2.1-rc.5-20261109.1100-dsh0.2.2-rc.1 / build348

- Первый экран нижнего ящика действий теперь ограничен 0,72× доступной высоты (`450952c1e`): списки входов `BottomSheetCard`, например «Другие действия» плагина, при подстройке под содержимое уходили в верхнюю половину экрана; новый `SheetGeometry.bottomDrawerMaxHeight(heightDp, liftDp)` считает предел от доступной высоты (высота экрана − подъём плавающей капсулы), `BottomSheetCard` использует его, и лишнее прокручивается внутри ящика, а нижний колонтитул остаётся на месте. Режим BOTTOM у `CardSheet` сохраняет 0,9 и не разделяет константу: описания / выбор / длинные формы встречаются широко, а длинным формам нужна высота тела. `SheetGeometryTest` / `BottomSheetCardLayoutTest` / `CardSheetGeometryTest` покрывают новую пропорцию и неизменное поведение коротких экранов (<480dp); компромисс записан в §9 базовой линии UI.
- Доказательства выполнения плагинов пропускают проверку равенства версий для совместимой оболочки Auto review (`4a25d2562`): запись профиля по умолчанию — подписанная оболочка `dsh-auto-review@0.1.0`, patch которой вставляет официальный пакет `@deepseek-ai/dsh-experimental-auto-review@0.2.2-rc.1`; снимок выполнения содержит только запись профиля (оболочка 0.1.0), а версия карточки берётся из официального пакета 0.2.2-rc.1. `PluginIdentity.legacyShim(cardName, observedName)` принимает только исторический путь «canonical-карточка + alias-строка выполнения», `PluginRuntimeProjection.apply()` пропускает равенство версий для оболочки и подтверждает по состоянию загрузки, поэтому карточка больше не показывает постоянно «состояние загрузки не подтверждено / перезапустите Web». Несовпадение версий без alias по-прежнему даёт unknown + ожидание перезапуска, защита «старый модуль выдаёт себя за новый» не меняется; `PluginRuntimeProjectionTest` добавляет случай реального направления с разными версиями и закрепляет защиту canonical-строки.
- Состояния карточки плагина теперь показаны семантическими цветными бейджами (`df4fe653d`): источник / версия / конфигурация / текущий Web получают отдельные пилюли, фон и текст берутся из семантических токенов `shell_*`; сопоставление тонов конфигурации и текущего Web вынесено в чистую логику `PluginCardState.configTone` / `runtimeTone` с модульными тестами, меняется только отображение, решения о состоянии не затрагиваются. Напоминание о перезапуске стало предупреждающим бейджем (`item_plugin_state_chip`) и отличается от строк «доступно обновление / последнее сообщение операции»; бейджи лежат в `PluginFlowRow` и переносятся целиком на узких экранах и при шрифте 1,3×, не опуская ключевые слова состояния; точка состояния объединена с бейджем конфигурации как compound drawable и больше не становится отдельным фокусом TalkBack.
