# DSHA 0.2.1-rc.3-20261031.0700-dsh0.2.1-rc.5 / build217

- 컨테이너 안에서 apt 등으로 시스템 라이브러리를 설치하거나 업그레이드한 뒤 플러그인 목록 읽기가 매번 실패하던 문제를 수정했습니다. Playwright 같은 도구가 apt로 `libsqlite3-0`을 설치하면 `libsqlite3.so.0`이 `libsqlite3.so.0.8.6`을 가리키는 심볼릭 링크로 바뀝니다. 읽기 전용 조회는 일반 파일만 인정해 '실행 도구 또는 자산이 불완전합니다'를 계속 표시했고, '설치 및 복구'는 판정 기준이 달라 이 파일을 다시 쓰지 않았습니다.
- 읽기 전용 플러그인 조회와 Python 공유 라이브러리 복구가 이제 같은 guest 판정을 공유합니다. Ubuntu 실행 루트 안에서 심볼릭 링크를 단계별로 해석하고(상대 링크, guest 절대 경로, `.l2s`처럼 이 실행 루트를 가리키는 호스트 경로) 최종적으로 실행 루트 안에 있는 일반 파일만 인정합니다. `/system`, `/proc`, `/sdcard` 같은 외부 바인딩, 범위를 벗어나는 링크와 순환 링크는 여전히 준비되지 않은 것으로 판정합니다. 링크를 컨테이너 안에서 proot가 흉내 내는 root가 썼든 외부 su로 부여된 root가 썼든 판정 방식은 같습니다.
- 복구 과정은 해석할 수 없는 끊어진 링크 자체만 삭제한 뒤 번들 라이브러리를 다시 쓰며, 사용 가능한 링크는 더 이상 덮어쓰지 않습니다. 플러그인 준비 판정이 바뀌면 진단 기록에 구체적인 파일과 원인(예: `libsqlite3.so.0:MISSING`)을 남겨 막연한 안내만 남지 않습니다.
- 순수 로직 `GuestRegularFile`과 단위 테스트를 추가했습니다. 이 클래스는 관리 런타임 시작 입력에 포함되어 런타임 디스크립터를 다시 생성했습니다. versionCode를 217로 올렸습니다. DSHA 리비전은 0.2.1-rc.3, 내장 DSH는 0.2.1-rc.5이며 빌드와 검수 범위는 이번 CI run과 Release 기록을 따릅니다.
