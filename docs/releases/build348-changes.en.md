# DSHA 0.2.1-rc.5-20261109.1100-dsh0.2.2-rc.1 / build348

- The BOTTOM action drawer now caps its first screen at 0.72× available height (`450952c1e`): plugin "More actions" and similar `BottomSheetCard` entry lists used to grow into the upper half of the screen when content-sized; the new `SheetGeometry.bottomDrawerMaxHeight(heightDp, liftDp)` computes the cap from available height (screen height − floating-capsule lift), `BottomSheetCard` uses it, and overflow scrolls inside the drawer while the footer stays fixed. `CardSheet`'s BOTTOM mode keeps 0.9 and does not share the constant: descriptions / pickers / long forms are wide-reaching and long forms need body height. `SheetGeometryTest` / `BottomSheetCardLayoutTest` / `CardSheetGeometryTest` cover the new ratio and unchanged short-screen (<480dp) behaviour; design baseline §9 records the trade-off.
- Plugin runtime evidence now skips the version-equality check for the Auto review compatibility shim (`4a25d2562`): the default profile entry is the signed shim `dsh-auto-review@0.1.0`, whose patch inserts the official `@deepseek-ai/dsh-experimental-auto-review@0.2.2-rc.1`; the runtime snapshot only records the profile entry (shim 0.1.0) while the card version comes from the official package 0.2.2-rc.1. `PluginIdentity.legacyShim(cardName, observedName)` accepts only the historical "canonical card + alias runtime row" path; `PluginRuntimeProjection.apply()` skips version equality for the shim and confirms by load state, so the card no longer keeps reporting "load state unconfirmed / restart Web to apply". Non-alias version mismatches still become unknown + restart required, so the old-module-masquerading-as-new guard is unchanged; `PluginRuntimeProjectionTest` adds the real-direction unequal-version case and locks the canonical-row protection.
- Plugin card state now uses semantic-color badges (`df4fe653d`): source / version / config / current Web each get their own pill, with background and text taken from `shell_*` semantic tokens; config and current-Web tone mapping moves to `PluginCardState.configTone` / `runtimeTone` pure logic with unit tests, display only, state decisions untouched. The restart todo becomes a warning chip (`item_plugin_state_chip`) and is visually distinct from the update / last-operation notes; badges live in `PluginFlowRow`, wrap whole on narrow screens and at 1.3× font, and never drop key state words; the status dot is folded into the config badge as a compound drawable and no longer becomes a separate TalkBack focus.
- Managed-runtime update: `PluginIdentity` / `PluginRuntimeProjection` are `runtime-descriptor` launcher sources, so `runtimeId` is recomputed to `5fec6de5`; fixed inputs stay frozen at the locked 20261105e; the bundled `dsh-web-mobile` stays upstream 3.3.1 and default-enabled.
- Version and scope: versionCode raised to 348 (based on the released build347 / `2121f27c0`); the DSHA revision stays `0.2.1-rc.5` with bundled DSH `0.2.2-rc.1`.
