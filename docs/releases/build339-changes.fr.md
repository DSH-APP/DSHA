# DSHA 0.2.1-rc.5-20261108.0300-dsh0.2.2-rc.1 / build339

- Double confirmation lors du changement de réglage de reconnaissance d’écran (T113, `29c5028b`) : au choix physique ou virtuel dans Réglages → Autorisations d’appareil → Reconnaissance d’écran, une confirmation `DshaDialogBuilder` explique d’abord la portée de lecture et la révocabilité ; le changement n’a lieu qu’après confirmation. Succès, échec, attente de nettoyage et sélection répétée affichent un état en ligne et un toast ; la confirmation n’est pas contournée par le mode « tout autoriser ». Le nouveau `ScreenModeFeedback` est l’unique source de la règle de confirmation, des noms de mode et des textes de résultat ; les appuis répétés sont ignorés pendant le changement ; le dialogue chinois/anglais défile sur un écran court 320 dp avec police 1,3×.
- Page de démarrage du DSH d’urgence allégée et flux de confirmation à un seul niveau (T92, `da0b9b71`) : l’explication du premier écran devient une ligne de conclusion + ⓘ ; l’état et les trois actions démarrer / entrer / arrêter fusionnent en une carte ; la clé API temporaire est repliée par défaut, diagnostics / journaux / sauvegarde / retour à la récupération passent sous « Plus » ; états et résultats apparaissent en fondu UiMotion. Le flux de confirmation gagne `RecoveryRepairSheet` : sélection et aperçu basculent dans le même dialogue, Retour remonte exactement d’un niveau, les appuis répétés sont désactivés pendant la génération de l’aperçu, exécuter / refuser restent dans le contenu défilant (écrans courts et grandes polices), et aucune entrée d’exécution n’apparaît pour un ID de proposition vide ; l’en-tête Web d’urgence devient titre sur une ligne + action courte « Proposition de réparation » + icône de rechargement + séparateur.
- Garde de focus mot de passe avant l’écriture de texte par l’assistant sur l’écran virtuel (T97 P1, `8b82e4f7`) : le chemin rapide ASCII pur de `/app/vscreen/type` exécutait `input text` directement dans le Core et contournait les contrôles de mot de passe de l’accessibilité. Le nouveau `VirtualScreenTextInputPolicy` refuse le focus mot de passe, autorise un focus sûr, échoue fermé quand un canal sémantique existe mais que le focus est illisible, et conserve la capacité ASCII documentée avec `passwordFocusChecked=false` quand l’accessibilité n’est pas connectée ; le `VirtualScreenPasswordProbe` en lecture seule revérifie la fenêtre applicative unique de l’écran courant via ACTION_AUTHORITY et lit `FOCUS_INPUT`, en renvoyant `SCREEN_TARGET_CHANGED` sans envoi si la fenêtre change. La pré-vérification avant envoi ASCII renvoie `PASSWORD_INPUT_UNAVAILABLE` (`state=NOT_SENT`, `nextAction=REPORT_TO_USER`) pour un mot de passe, `PASSWORD_FOCUS_UNVERIFIED` (`retryable`, `SEE_AGAIN`) pour un focus illisible ; le type non-ASCII et l’écriture de nœuds mot de passe via node `set_text` sont aussi bloqués ; le panneau natif garde sa location indépendante. Aucun « autoriser quand même ».
- Correction du joint de test CI T97 (`d16b0c14`, infrastructure de test) : `VirtualScreenInput` reçoit un drapeau forced-available au niveau de l’instance pour que les instances de test ne soient plus détournées par la sonde hôte `/system/bin/input` (le runner GitHub n’a pas ce fichier, ce qui faisait échouer les tests unitaires T97) ; les instances de production ne posent pas le drapeau, une vraie commande manquante est toujours refusée et `systemCommandExists` n’est pas assoupli.
- Réglages de spécification d’affichage de l’écran virtuel en liste blanche (T99, `c33f358d`) : la valeur par défaut reste 1008×1792@320 (16:9 / 504×896 dp) et une base de compatibilité compat-720 = 720×1600@320 (20:9 / 360×800 dp) est ajoutée ; les spécifications inconnues / vides / hors budget reviennent au défaut, aucune taille ni dpi arbitraire n’est acceptée. La création et la rotation du Manager ne transmettent au Core qu’un preset id et une orientation ; le Core résout la liste blanche, applique le dpi et relit preset / density / tailles logiques ; `VirtualScreenDisplaySettings` persiste le choix et la page de l’écran virtuel gagne un bouton radio « Taille d’affichage » qui n’agit que sur la prochaine création ou reconstruction par rotation, sans changer l’identité de la frame ni la porte d’entrée. Le budget d’observation reste 2 frames / 24 MiB : deux frames 1440×2560 (~28,1 MiB) ne sont pas dans la liste blanche ; la validation compat-720 sur appareil n’est pas faite.
- Action-comme-observation et settle piloté par événements pour l’écran physique (T105, `c6a2ea84` / `c94df74d` / `00dd7a90`) : les points d’action `/app/ui` acceptent un `observe=1` optionnel — après `COMPLETED`, la même requête fait un settle (premier événement d’accessibilité ≤800 ms, silence 250 ms, plafond total 2,5 s ; interruption possible par annulation de tâche et échéance, sans interrogation active) puis relit l’arbre et renvoie dans le reçu de nouveaux `treeId` / `nodeId`, l’arbre textuel et les métadonnées de settle ; les actions de coordonnées ne renvoient toujours pas de capture et leurs identifiants exigent toujours une capture séparée. Sans paramètre, le comportement est inchangé ; un échec d’observation n’écrit que `observationUnavailable` et ne modifie pas le statut de l’action ; UNKNOWN n’est jamais rejoué ; les refus pour identifiants expirés joignent le nouvel arbre de l’écran courant pour réessayer avec de nouveaux identifiants. Le `dsh-computer-use-android` intégré gagne un `observe` optionnel sur ses sept outils d’action (omis → le serveur MCP injecte `observe=1`, `observe:false` le désactive ; seuls des champs optionnels sont ajoutés, la validation stricte des arguments n’est pas assouplie). Les appels consécutifs à `/app/sense/state` renvoient par défaut un delta : plus d’un tiers de changement, changement de fenêtre / taille / focus / source / troncature, de génération ou de cible et `full=1` donnent un instantané complet, l’absence de changement donne `mode=same` sur une ligne ; les réponses ajoutent `mode` / `deltaReason` / `previousSid` / `changedElements`, `format=v4-preview-3`. `k***` reste un numéro de position dans l’ordre de lecture et les actions utilisent toujours des locations `treeId` / `nodeId` à usage unique. `/app/help` est mis à jour en chinois et en anglais.
- Guide pour les plugins utilisateur dont la version ne correspond plus après une mise à niveau du runtime (T93, `bebc01b4`, documentation) : les mises à jour APK / DSH par-dessus ne réécrivent pas la liste de plugins tiers du profil utilisateur ni `node_modules` ; le pré-contrôle de compatibilité DSH ignore les bundles incompatibles et désactive les entrées concernées selon `engines.dsh` / les plages peer `@deepseek-ai/dsh*` (fail-safe, sans suppression ni réécriture). Le traitement passe par une réinstallation via la gestion des plugins et des exemptions de version exacte dans `compatibility.json`, jamais par une édition manuelle du profil ; il est aussi expliqué que les lignes de démarrage répétées de plusieurs entrées cordis d’un même bundle ne sont pas des imports de modules en double (StartupTrace déduplique en plus les lignes identiques adjacentes).
