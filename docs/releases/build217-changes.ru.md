# DSHA 0.2.1-rc.3-20261031.0700-dsh0.2.1-rc.5 / build217

- Исправлено чтение списка плагинов, которое после установки или обновления системных библиотек в контейнере (например, через apt) каждый раз завершалось ошибкой: когда инструменты вроде Playwright ставят `libsqlite3-0` через apt, `libsqlite3.so.0` становится символической ссылкой на `libsqlite3.so.0.8.6`; запрос только для чтения принимал лишь обычные файлы и постоянно сообщал о неполных инструментах или ресурсах среды, а «Установка и восстановление» использовали другой критерий и не перезаписывали файл.
- Запрос плагинов только для чтения и восстановление общих библиотек Python теперь используют один guest-критерий: символические ссылки разрешаются пошагово внутри корня среды Ubuntu (относительные ссылки, абсолютные guest-пути и пути хоста вроде `.l2s`, указывающие обратно в этот корень), и принимается только обычный файл, который в итоге находится внутри корня среды; внешние привязки вроде `/system`, `/proc` и `/sdcard`, выходящие за пределы ссылки и циклы по-прежнему считаются неготовыми. Критерий одинаков, записал ли ссылку root, эмулируемый proot внутри контейнера, или root, выданный извне через su.
- Восстановление удаляет только саму неразрешимую висячую ссылку перед записью встроенной библиотеки, а пригодная ссылка больше не перезаписывается; при изменении вывода о готовности плагинов диагностика фиксирует точный файл и причину (например, `libsqlite3.so.0:MISSING`), а не только общее сообщение.
- Добавлена чистая логика `GuestRegularFile` с модульными тестами; она входит во входные данные запуска управляемой среды, поэтому дескриптор среды выполнения сгенерирован заново. versionCode повышен до 217; ревизия DSHA остаётся 0.2.1-rc.3, встроенная DSH — 0.2.1-rc.5; объём сборки и приёмки определяется этим запуском CI и квитанцией Release.
