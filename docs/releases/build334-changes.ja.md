# DSHA 0.2.1-rc.5-20261106.2228-dsh0.2.2-rc.1 / build334

- P0 上書き更新の修正（T91、`a70232fc`）：build333 の実機上書き更新後、proroot ランチャーが試用 guest の終了後も遅れて終了したり残留することがあった（OnePlus PJD110 / Android 16 / WebView 156 で実測。バックグラウンドに他の Web がなくても再現）。`RuntimeTrial` の終了処理が「ランチャーオブジェクトがまだ生きている」ことを試用失敗 `TRIAL_PROCESS_UNCONFIRMED` と誤判定し、ランタイム更新トランザクションが半コミット（`files-committed` / `settings-committed`）のまま残り、起動がメンテナンスバリアで止まり、再起動しても直らなかった。現在は試用の終了判定をこの記録の guest 終了証拠だけで行い、ランチャー残留は結論を変えない。`RuntimeTrial` は今回保持する `Process` ハンドルに対して1回だけ有界な後片付けを行い、タイムアウトや失敗時は `TRIAL_LAUNCHER_RETENTION` 診断を書くだけにする。`launched` だが `.dsha-web.pid` / `.stale` 証拠がない記録では、`TrialRecovery` はその記録 id から導かれる試用 profile に該当プロセスがないことをプラットフォームに確認させる（同一 UID、2回一致する出生識別）。存在し続ける・読めない・識別が変わる場合は引き続き fail-closed とし、自癒できない証拠欠落を無条件に残さない。
- メンテナンス失敗の診断と古い失敗の消去：メンテナンスタスクの開始 / 失敗がエクスポート可能な操作記録（`MAINTENANCE_TASK_START` / `MAINTENANCE_TASK_FAILED`）を書き込み、失敗状態でも緊急 DSH、メンテナンス記録、エクスポート可能な可読コピー、「制限付きメイン UI へ」を押せるままにする。外部復旧が完了し、環境が実行可能でメンテナンス進行中 / 復旧待ちがない場合、ページは古い失敗スナップショット（`RuntimeUpgradeState.clearStaleFailure`）を破棄し、「前回ランタイムの更新待ち」という標準状態に戻して更新入口を出し、ユーザーに再試行を再度押させない。起動記録は「認証リンクは取得したが最終 ready / failed 未書き込み」を「準備完了 · 入場待ち」と表示し、「中断 · 結果なし」は表示しない。
- 上書き更新で旧版を退役（I10）：インストール済み APK の身元と記録上のセッション身元が異なる場合に限り、メンテナンス / 強制停止の経路で記録済みの出生識別（boot、PID、出生時刻、コマンドライン、UID、世代/インスタンス/nonce）を2回検証したうえで、まず記録上の guest を終了し、次に対応する旧 proot ランチャーを終了する（SIGTERM → 短い待機 → 再確認 → SIGKILL）。guest の終了が確認できなければランチャーには触れず、検証失敗 / 読めない / PID 再利用 / 他者 UID / 2回の観測間の変化があれば一切シグナルを送らず元の環境を保つ。通常停止、現在のインスタンス、ターミナル、仮想画面、隔離試用の経路は不変（I9）。強制停止ダイアログは「前の Web を放棄して強制終了」と guest → 旧ランチャーの順序を明記する。
