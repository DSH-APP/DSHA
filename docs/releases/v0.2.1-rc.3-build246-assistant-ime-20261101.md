## 2. 问题（源码核对，build245 仍存在）

- 现象：打开悬浮助手（收起态，底部右侧）后，在其他应用的输入框唤起键盘，悬浮助手随键盘整体上弹。
- 调用链：`AssistantService` → `new AssistantWindow(...).show()` → `WindowManager.addView`，参数为 `TYPE_APPLICATION_OVERLAY`、`FLAG_NOT_FOCUSABLE | FLAG_NOT_TOUCH_MODAL`、`gravity = BOTTOM | END`、`height = WRAP_CONTENT`、`softInputMode = SOFT_INPUT_ADJUST_RESIZE`。
- API 30+ 中，窗口未显式设置 fit-insets 时，`ViewRootImpl.adjustLayoutParamsForCompatibility` 把 `ADJUST_RESIZE` 换算为 `fitInsetsTypes |= ime()`，窗口框架按当前输入法区域避让；`FLAG_NOT_FOCUSABLE` 不改变这一点。
- 连带：窗口移动触发 layout 监听 `publish()`，`OwnedScreenOverlay` 登记的排除区几何随输入法开合变化。
- 来源：build195（`a5cfca0`）随悬浮助手引入；后续编辑改由 `AssistantActivity` 承担，第 239 行注释已写明“never an IME target”，该设置未随之移除。
- 同类窗口排查：`OverlayController`、`AssistantConfirmationWindow`（顶部对齐）、`VirtualScreenOverlayController`（左上对齐）均未声明调整模式，不受影响；Web 画中画已按 `ownsKeyboard()` 与 `Insets.NONE` 隔离。

## 3. 改动

- `AssistantWindow.show()`：`softInputMode` 改为 `SOFT_INPUT_ADJUST_NOTHING`，并显式 `setFitInsetsTypes(WindowInsets.Type.systemBars())`；显式设置后系统不再按兼容规则补 `ime()`。`render()` / `restoreStopControls()` 复用同一 `params`，展开与停止控件恢复同样生效。
- `AssistantInputAndroidTest`：断言 `getFitInsetsTypes()` 不含 `ime()`，且调整模式不是 `ADJUST_RESIZE`。

## 5. 未验证与限制（需后续反馈）

- **未在实机测试，存在变更失效的问题**：修复依据 AOSP `ViewRootImpl` 的兼容换算推断，部分厂商 ROM 的窗口管理器可能另行对悬浮层做输入法避让，届时悬浮助手仍会上弹。请用户反馈：机型 / ROM 与 Android 版本、悬浮助手收起或展开状态、键盘弹出时是否仍上移（可附 `dumpsys window` 中该窗口的 frame）。
- 没有设备验证：其他应用弹键盘时悬浮助手的实际位置、`dumpsys window` 帧对比、展开态与停止控件恢复态均未在真机上看过。
- Robolectric 只验证窗口参数，不模拟系统窗口管理器的输入法避让；修复是否在各 ROM 上生效须以设备验收为准。
- ROM 自带“小窗 / 自由窗口”模式下的输入法行为不在本次改动范围内。
