# DSHA 0.2.1-rc.5-20261106.1830-dsh0.2.2-rc.1 / build333

- 跨应用文件访问（SAF，PR #3，review `5797594537` APPROVE，merge `9cc91f5e`）：设置 → 设备能力授权 → 系统权限新增「跨应用文件访问」。用户经系统文档选择器授权目录后，DSHA 持久化读/写权限（最多 8 棵树），授权页可管理并只读浏览目录与文本预览。新增 `/app/saf/*` 桥端点（trees / ls / stat / read / write / push / pull / mkdir / rm；read 每次 256 KiB、write 16 KiB、push/pull 32 MiB、列表 500 项；`rm` 为两段式一次性 token），桥协议保持版本 3（纯加法）。安全边界：只认授权簿短 id，写/删要求该树可写；容器路径复用 `BridgePathPolicy`（凭据区不可读写）；本地文件用 `O_NOFOLLOW` + dev/ino + `/proc/self/fd` 真实路径复核，拒绝硬链接与 `.l2s` 实体。内置 `dsh-device-shell-guide` 提示词与 `/app/help` 各加一条入口说明。受管输入随该 PR 重算 runtime-descriptor（runtimeId `04b24571`），固定输入不重建。
- 设置 → 体验新增「隐藏后台」开关（`73896284`，ADB 保活辅助项）：默认关闭、本机偏好、不进入备份白名单。打开后把本应用全部有效任务移出最近任务，关闭后恢复并按现有「只留一张主卡」规则重新分类；App 重启或进程被杀后重开会重新读取偏好并应用，失败写 `DiagnosticLog` 并提示、下次打开重试。只影响最近任务可见性，不改 `DeviceBridgeService`、常驻通知、前台服务与停止语义，也不承诺保活（不防 Doze、厂商省电或强行停止）。
- 设备能力授权页 UI 一致性修复（`8509ae0a`）：状态胶囊改为在 `PluginFlowRow` 内自适应（`wrap_content` + 最小 56dp 宽，放不下换行，不再四等分压缩），状态去掉 12dp 缩进、允许两行，标题/状态字号收进 `device_grants.xml`（12sp）；其余 9 个语种的「关闭」状态词改用现成的「已关闭」译条（中文保留「关闭 / 關閉」），覆盖概览状态、识屏与剪贴板档位三处，不改「关闭按钮」词条。概览条压平为 `shell_bg` + 底部 1dp `shell_line`，去掉 16dp 下圆角、强描边与 2dp 阴影；短屏（`screenHeightDp ≤ 480`）把概览条并入滚动区，常规高度仍吸顶并保留跳转。
- 验证范围：宿主 contracts 整组、全树格式检查（JDK17）、`generate-changelog --check`、文档链接与源码整洁检查、`test-release-*` 相关门禁，以及定向单测（更新页、SAF 五类 + 路由、`TaskNavigationPolicy`、`BrowserTasks`、`ConfigStore` 隐藏后台、设备授权页布局）。**两项新功能未做真机验收**：`androidTest` 源集存在既有编译错误（`RecoveryInstrumentation` 调用 `HarnessService.refreshPowerMode()` 少传 `Context`），隐藏后台的最近任务实际行为与授权页像素级截断（1.3 倍字体、短屏、RTL）待真机核对。版本码提升为 333（基于 build332）；DSHA 修订号保持 0.2.1-rc.5，内置 DSH 为 0.2.2-rc.1；runtimeId 保持 `04b24571`（版本与文档改动不改变受管输入）。
