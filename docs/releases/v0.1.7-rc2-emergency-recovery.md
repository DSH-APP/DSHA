## 实现边界

- 普通安全 Profile 仍属于正式环境；应急入口使用 `RecoveryController` / `RecoveryRuntime` 自有状态和目录，不进入正式迁移、用户数据绑定或正式启动锁。
- 启动只装载官方基础界面和五个受控工具；正式插件与设备桥不进入应急 Profile。真实工具表、唯一预设、固定应急工作区、进程出生身份和鉴权分别核验。
- `/proc` 身份读取被拒绝时，仅对本次已经完成资产、工具、鉴权检查的存活进程提供 `READY_READ_ONLY`。这种状态不取得正式维护豁免，不能确认写入。无效身份、坏资产和鉴权失败仍拒绝就绪。
- 原生修复支持中断事务恢复、签名运行时修复、当前 schema 的普通 Profile 设置、基础 Web Profile 和全局补丁重建。设置变更仍由现有 `ProfileSettingsTransaction` 预检、宿主事务及真实服务读回执行。原件与回切日志保留，未知或变化的源拒绝写入。
- 网络工具只能诊断、读取、提案和查结果；确认只在原生页面。已确认的修复持有独立 lease，停止应急聊天不撤掉正在运行的原生修复的前台保护。关闭的候选过期，已运行事务保留实际结果。
- 应急停止先通过本次私有哨兵让 Node 正常退出，再核验 guest 和 launcher；不能确认时保留现场和阻断状态。未按裸 PID 或名称强杀进程，未把拒绝访问当作已退出。
- 原生错误日志包含应急代次、阶段和结果。应急 Web 使用独立的 localhost 鉴权流程；rc2 的 Cookie 绑定 authority，不能将 127.0.0.1 Cookie 直接搬过去。
- 这属于运行状态隔离，同 UID 的 proot 不视为系统安全沙箱。它用于受支持的环境/配置修复，不能代替新的签名 APK 修复原生程序自身的代码错误。

## 真机发现并修正

1. 打包时 strip 改写标准 proot/loader 的字节，会令正确启动器被精确校验拒绝。保留这两份 ELF 原始字节，实际 APK 校验通过；应用仍是非调试正式包。
2. Linux 的默认 Documents 探测不能保证空白工作区可用。现在在 READY 前用 rc2 真正的 WorkspaceRegistry 创建并读回本次 HOME/workspace，前端选中 `DSHA Recovery`。
3. 旧预览把代次哈希当作修改前内容，维护提案没有可读的修改后说明。现在列出实际任务/事务状态和执行步骤；没有待恢复事务时明确只核验状态。
4. 长预览的三行对话框按钮会挤出屏幕。决议按钮移入同一滚动内容，保留固定返回按钮；最终 Low 包真机确认两项决议都可到达。
5. 应急浏览器工具栏收为一行，为短横屏保留输入区空间；保留网页会话，旋转不重新启动 DSH。

## 未验证与使用限制

- 当前手机没有可用模型凭据：没有发起真实模型请求，也没有证明所有模型服务可用。
- 没有在正式设备上制造损坏配置、磁盘满或权限拒绝。新 Broker 到 Android 宿主事务的损坏数据端到端故障注入未覆盖；对应源变化/确认/事务故障由隔离逻辑测试覆盖。
- 当前普通工作台没有可用于比对的历史长会话；首次安装时间保持不等于完整用户数据前后摘要验证。本轮不能宣称全部历史覆盖升级、会话恢复与续写真机矩阵完成。
- Android 6/7、真实 16 KiB 内核、其它厂商 ROM、真实读屏及完整手机长会话 p50/p95/内存/FD 矩阵未覆盖。宿主布局/渲染结果不能替代这些实测。
- 应急仍依赖 Android 能运行应用、执行签名启动器以及足够存储。不可用时保留原生日志/数据入口，不能承诺所有系统故障下都能启动 Web。
