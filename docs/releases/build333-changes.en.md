# DSHA 0.2.1-rc.5-20261106.1830-dsh0.2.2-rc.1 / build333

- Cross-app file access (SAF, PR #3, review `5797594537` APPROVE, merge `9cc91f5e`): Settings → Device capability grants → System permissions gains "Cross-app file access". After the user grants a directory through the system document picker, DSHA persists read/write access (up to 8 trees); the grants page manages them and offers read-only browsing with text preview. New `/app/saf/*` bridge endpoints (trees / ls / stat / read / write / push / pull / mkdir / rm; read 256 KiB per call, write 16 KiB, push/pull 32 MiB, listings 500 entries; `rm` uses a two-step one-time token), and the bridge protocol stays version 3 (additive only). Security boundaries: only short grant-book ids are accepted, writes and deletes require that tree to be writable, container paths reuse `BridgePathPolicy` (credential areas stay unreadable and unwritable), and local files are opened with `O_NOFOLLOW` + dev/ino + `/proc/self/fd` real-path verification, rejecting hard links and `.l2s` entities. The built-in `dsh-device-shell-guide` prompt and `/app/help` each gain one entry sentence. Managed inputs recompute the runtime descriptor in that PR (runtimeId `04b24571`); fixed inputs are not rebuilt.
- Settings → Experience adds a "Hide in background" switch (`73896284`, an ADB keep-alive aid): off by default, a device-local preference that stays out of the backup allowlist. Turning it on removes all valid tasks of this app from Recents; turning it off restores them and re-classifies with the existing "one main card" rule. After an app restart or a process kill it re-reads and applies the preference, logging `RECENTS_HIDE_APPLY` and retrying on the next launch if applying fails. It only affects Recents visibility: it does not change `DeviceBridgeService`, the ongoing notification, the foreground service or stop semantics, and it is not a keep-alive promise (no Doze, OEM power-saving or force-stop protection).
- Device capability grants UI consistency fix (`8509ae0a`): status pills now adapt inside `PluginFlowRow` (`wrap_content` with a 56dp minimum width; they wrap instead of being squeezed into quarters), the status line loses its 12dp indent and may use two lines, and title/status sizes move into `device_grants.xml` (12sp). The "off" state word in the other 9 languages now reuses the existing "closed" translation (Chinese keeps 关闭 / 關閉) across the summary status, screen sensing and clipboard tiers, without touching the "close button" string. The summary bar is flattened to `shell_bg` + a 1dp bottom `shell_line`, dropping the 16dp bottom corners, heavy border and 2dp shadow; on short screens (`screenHeightDp ≤ 480`) the bar moves into the scroll area, while normal heights keep it pinned with the jump links.
- Verification scope: the full host contracts group, the whole-tree format check (JDK 17), `generate-changelog --check`, document-link and source-hygiene checks, the `test-release-*` gates, and targeted unit tests (update page, five SAF classes plus routing, `TaskNavigationPolicy`, `BrowserTasks`, `ConfigStore` hide-from-recents, grants layout). **Neither new feature was validated on a device**: the `androidTest` source set has a pre-existing compilation error (`RecoveryInstrumentation` calls `HarnessService.refreshPowerMode()` without a `Context`), and the actual Recents behavior plus pixel-level truncation on the grants page (1.3× font, short screens, RTL) still need a device check. Raises versionCode to 333 (based on build332); the DSHA revision stays 0.2.1-rc.5, the bundled DSH is 0.2.2-rc.1, and runtimeId stays `04b24571` (version and documentation changes do not change managed inputs).
