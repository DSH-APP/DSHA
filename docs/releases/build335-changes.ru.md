# DSHA 0.2.1-rc.5-20261107.0140-dsh0.2.2-rc.1 / build335

- Результат build334 на реальных устройствах (P0, не пройдено): первая установка 333→334 поверх не удалась — на двух устройствах завершение trial остановилось на `TRIAL_PROCESS_UNCONFIRMED` (транзакции вида `c4299668…`), транзакция обновления среды осталась наполовину зафиксированной, запуск упёрся в барьер обслуживания. Повторное обслуживание со страницы обслуживания дало 334/READY с целыми данными. build334 записан как «первая попытка неудачна, вторая рабочая», а не как пройденный. Эта сборка исправляет путь первой неудачи и состояние после восстановления по этим полевым данным.
- Ограниченное принудительное завершение не вышедшего гостя при завершении trial (T103, `a5168f99`): непустой `manager.stop()` больше не приводит к немедленному `TRIAL_PROCESS_UNCONFIRMED`. Сначала ограниченно ждём лаунчер этого раунда 3 секунды, затем `WebProcessManager.forceStopTrialGuest` последовательным чтением перепроверяет запись этого раунда, единственный profile и сохранённую идентичность рождения и посылает SIGKILL только гостю этого раунда, после чего повторно выполняет записанную остановку и глобальную проверку отсутствия Web. Только если подтвердить всё равно нельзя, шаг завершается ошибкой и пишет обезличенные подробности в экспортируемые записи операций и каталог записей (сбой завершения после успешного trial — `failure.json`, путь восстановления — `recovery-stop.json`, существующие подробности ошибки не перезаписываются). `TrialRecovery` идёт в том же порядке, поэтому один `recover-maintenance` закрывает старый trial, застрявший на не вышедшем госте. Принудительный путь fail-closed при отсутствии идентичности рождения, несовпадении записи PID или изменении между двумя наблюдениями; поиск по голому PID или имени не выполняется. Страница обслуживания убирает 2-секундный кэш `pendingTrial` и в `onResume` сбрасывает UI-кэш `BackupTask`, поэтому после внешнего восстановления сразу возвращается к «предыдущая среда ожидает обновления».
- Восстановление перепроверяется по идентичности рождения и дописывает доказательство идентичности (T100, `903974db`): восстановление при запуске и перепроверки при переходе переднего/фонового плана используют общий `observeRecoveredSession`. Если строгая проверка PID / файла идентичности даёт UNKNOWN, выполняется переход к полному доказательству рождения (boot / PID / время рождения / командная строка / UID / generation+instance+nonce); при строгом LIVE / EXITED перехода нет, а нечитаемое доказательство остаётся fail-closed. После успешного переподключения дописываются `/root/.dsha-web.pid` и `.dsha-web.identity` по проверенной идентичности рождения (запись pid на другой номер сохраняется как есть), что закрывает разрыв, когда устаревший или устаревший после выхода файл идентичности заставлял каждый запуск возвращаться к `IDENTITY_UNKNOWN`. Финальный UNKNOWN пишет экспортируемую диагностику `WEB_SESSION_RESTORE_FAILURE` (stage / reason / attempts), а текст `IDENTITY_UNKNOWN` даёт следующий шаг: остановить → если обычная остановка не подтверждается, принудительно завершить по проверке идентичности → перезапустить и перепроверить.
- Переработка предпросмотра виртуального экрана (T96, `71010565`): по умолчанию 172dp-панель внутри страницы больше не раскрывается автоматически; вместо неё — синяя «дышащая» полоса вверху страницы-хоста (3dp линия + текст целевого приложения «имя приложения · имя пакета», визуально 27dp, область касания 40dp); нажатие открывает страницу виртуального экрана, × сворачивает. Добавлены три уровня «полоса (по умолчанию) / полный предпросмотр (старая панель в странице) / выключено»: Настройки → Разрешения возможностей устройства → Предпросмотр виртуального экрана; выбор уровня сбрасывает намерение свернуть. Состояние сворачивания хранится в приватных настройках приложения, переживает поколения виртуального экрана и перезапуск App и больше не запоминается по generation; удаляется при остановке/отзыве виртуального экрана, уходе хоста из переднего плана, показе самой страницы виртуального экрана и системного плавающего предпросмотра. Цель берётся только из доступного только для чтения `targetStatus` Manager; если её нет, показывается «виртуальный экран работает», без догадок по записям запуска, без кадров и без выдачи учётных данных ввода. Анимация дыхания подчиняется `UiMotion` и статична при отключённых анимациях или уменьшении движения.
