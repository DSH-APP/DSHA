# DSHA 0.2.1-rc.3-20261031.0700-dsh0.2.1-rc.5 / build217

- Corrige a lista de plugins que falhava em toda leitura depois de instalar ou atualizar bibliotecas do sistema dentro do contêiner (por exemplo via apt): quando ferramentas como o Playwright instalam `libsqlite3-0` pelo apt, `libsqlite3.so.0` vira um link simbólico para `libsqlite3.so.0.8.6`; a consulta somente leitura aceitava apenas arquivos comuns e continuava informando ferramentas ou recursos de execução incompletos, enquanto "Instalação e reparo" usava outro critério e nunca reescrevia o arquivo.
- A consulta de plugins somente leitura e o reparo das bibliotecas compartilhadas do Python agora usam o mesmo critério guest: links simbólicos são resolvidos passo a passo dentro da raiz de execução do Ubuntu (links relativos, caminhos absolutos do guest e caminhos do host como `.l2s` que apontam para esta raiz), e só um arquivo comum que termina dentro da raiz de execução é aceito; vínculos externos como `/system`, `/proc` e `/sdcard`, links que escapam e laços continuam não prontos. O critério é o mesmo quer o link tenha sido escrito pelo root emulado pelo proot dentro do contêiner, quer por um root concedido de fora via su.
- O reparo remove apenas o próprio link pendente que não pode ser resolvido antes de regravar a biblioteca empacotada, e um link utilizável não é mais reescrito; quando o veredito de prontidão dos plugins muda, o diagnóstico registra o arquivo e o motivo exatos (por exemplo `libsqlite3.so.0:MISSING`) em vez de apenas uma mensagem genérica.
- Adiciona a lógica pura `GuestRegularFile` com testes unitários; ela entra nas entradas de inicialização do runtime gerenciado, por isso o descritor de runtime foi regenerado. O versionCode sobe para 217; a revisão DSHA permanece 0.2.1-rc.3 e o DSH embutido é 0.2.1-rc.5; o escopo de build e aceitação segue esta execução de CI e o recibo da Release.
