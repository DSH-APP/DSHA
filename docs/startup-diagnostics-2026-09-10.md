# 启动诊断、兼容恢复与附件图标修订

适用于标准版和 low，仍为版本码 115、dsh 0.1.5-alpha.2、Ubuntu 基础环境 10。内置移动界面仅增加本地 CSS 修订，版本为 2.4.0-dsha.2。

## 处理的问题

启动页此前只显示“等待鉴权”，没有接收插件注册及真实进程输出。Cordis 的插件导入/初始化异常可能留在内部错误缓冲中，整个进程继续等待，既没有鉴权地址也没有退出。本次观察实际 Entry.init 的返回/拒绝，显示插件名称、版本、加载结果和错误原因；可选依赖路径探测不作为插件故障。网页侧同时观察模块工厂、插件 apply 和官方启动失败屏。

启动时间线由进程级协作者保存，页面重建不会丢失，并限制长度、清理控制字符及脱敏。停止旧进程、运行工具、恢复事务、注册插件、加载 DSH、服务就绪等阶段均显示耗时。错误日志下载附带本轮时间线和上次失败记录。

原“安全启动”在已启动中的状态会直接返回，而且只停用第三方插件，无法绕过损坏的原配置。本次支持先停止当前任务，再创建独立的官方基础 profile；保留原插件开关、配置、会话和文件。普通重启返回原配置。安全界面不包含移动界面等可选扩展。

用户提供的 vivo V2463A / Android 16 日志来自 alpha.1low（114）：三轮鉴权前退出，后续成功输出覆盖了失败记录。该日志没有崩溃原因，不能据此断言具体厂商故障已复现。本次记录实际退出码，并在 proroot 确认退出、鉴权前且未定位到插件故障时尝试一次 proot；不改保存的运行方式。等待时间长、用户停止、明确插件故障都不能触发此重试。

运行时依赖链接缓存检查其父目录和受管入口状态。新增、删除、替换链接会重新检查；冷环境仍完整修复。插件注册复用 RuntimeTools 安装的脚本，避免同内容重写造成后续工具缓存失效。

实际点击重启还暴露出停止检查的竞态：第一次读到活进程 stat 后，进程退出并清空 cmdline，而 `kill(pid, 0)` 在僵尸态仍成功。此前会错误报告“进程命令行暂不可读”。现先复核内核退出状态，并对短暂读取失败作有限重读；长期不可读的活进程仍保持保护，不给未知 PID 发信号。新增真实直接重启回归，测试结束的停止失败也计为测试失败。

附件按钮偏移来自旧 CSS 的 `:nth-child(2)`：新版该位置是附件按钮，其 SVG 被错误设置为最小宽度 34px。改为匹配实际 `_modes` 容器。真实 WebView 中图标从 34px 恢复为 14px，280/320/350px 工具栏下按钮与图标中心偏差均小于 0.001px。
