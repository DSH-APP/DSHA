## Changes

- Plugin discovery filters genuine bundles before checking managed content. Proof metadata is authenticated once per query, and canonical aliases are deduplicated within that query. Full file content, mode, symlink and before/after directory stability checks remain. A later query or commit verifies the content again.
- Node plugin provenance uses bounded asynchronous file reads. Read-only listing does not hold the profile writer lock; removal fully rechecks the actual target at commit. Native enable/disable acknowledges the exact name, Boolean value and persisted readback before a separate refresh. Persisted intent does not prove that running components have reloaded.
- Native plugin queries coalesce refreshes, retain the last confirmed list and support cancellation. Queueing, preparation checkpoints and command execution share the remaining deadline. A single system IO call, monitor or Binder operation cannot be preempted; unknown process exit retains the existing barrier. Error reporting no longer launches a second synchronous full scan.
- After strictly adopting the existing live Web process, LAN publication reuses its verified cookie only after the second kernel identity check and current-generation checks. The actual port and verified authentication result are reused. Recovery does not repeat authentication or replay startup, migration or business operations.
- If that same generation later loses process-identity proof, pending LAN publication is rejected and its existing LAN authentication, listener and connections are retired. A newer generation is preserved. No signal is sent to an unidentified Web process, and the stop barrier remains.
- Notice persistence separately checks lost responses, background completion and revision conflicts. Only confirmed durable Host state can close the notice. Unsaved or unknown outcomes cannot be reported as saved.
- Chinese distribution targets and the maintained English documentation are included. Original historical evidence and newly created navigation copies retain distinct provenance. See the [English index](../index.md) and [Chinese release record](../../releases/v0.2.1-rc.2-build190-fix12-20261021.md).

## Automatic Web port investigation

The native plugin helper uses guest commands, not a Web port. Web plugin management uses the current Connection. In the controlled Host test, actual enable and disable of the official voice plugin retained the same HTTP instance and port. Evidence demonstrates that expensive synchronous scanning blocked the Node event loop; it does not establish one unique cause for every reported phone symptom.

Automatic mode first reuses the last successful port on this device when it is still available, otherwise the kernel assigns one. Recovery and LAN publication bind the current generation, actual URL and actual port. A changed port changes the Web origin. Retained browser data, the temporary OAuth callback route and the LAN proxy have separate rules. The OAuth route belongs to the current WebServer; it does not open a separate temporary listening port. See [ports](../ports-and-networking.md), [LAN](../lan.md) and [startup diagnostics](../startup-and-diagnostics.md).
