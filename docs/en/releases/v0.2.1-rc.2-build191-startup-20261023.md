## Implementation scope

### Lightweight CAS entry, FD traversal and timing

Ordinary startup invokes `python3 -u /root/.dsh/materialize-cas-links.py`, still under fixed proot. Selecting proroot for the main Web does not change the migration's execution domain. The dedicated entry retains registry checks, both shared locks, transaction recovery and the V1 unique final-line `PLUGIN_RESULT` contract, while removing the general manager's SSL/download/archive initialization.

POSIX scanning anchors actual open directory FDs with NOFOLLOW. Each child checks its current directory edge; entry/return checks the upper edge. Every directory retains fstat stability checks and a second names enumeration, with final full-path identity validation by reader.parent. Windows fallback retains recursive per-child ancestor validation. Persistent directory/link substitutions are rejected; detection of every transient move-away/return above the root is not promised, but FD reads cannot be redirected to the replacement tree. Actual CAS materialization uses the original proot transaction, O_PATH pinning, original preservation, full-chain identity/time rechecks before publication and existing batch/recovery semantics.

**Every ordinary startup still scans the relevant complete physical profile dependency tree.** No root-mtime, manifest or past-success shortcut was added. Disabling a plugin does not necessarily remove its dependency scan. This reduces repeated ancestor checks and unused imports, without pretending arbitrary nested terminal/pnpm modifications can be detected without scanning. Host Java scanning, generation indexes, Node compile caches, core prebundling and lazy activation were not enabled merely because the external report suggested them.

| Diagnostic | Boundary |
|---|---|
| `CAS_HOST_TIMING` | Native-file preparation, launcher preparation, process creation, collection and exit finalization using monotonic time; failures have a separate stage |
| `CAS_TIMING` | Python entry/imports, data/profile lock waits, transaction checks, scan, copy/commit and entry total; counts include entries/directories/maximum component depth/candidates and copied bytes/batches |
| Output budget | At most24 CAS timing lines, each at most4096 characters, retained by Java; no user-file contents |
| Success | Non-timeout, zero exit, untruncated output and guest/launcher finalization precede unique typed receipt validation; timing lines never substitute for success |

Python success is printed after locks are released. Host/Python spans have different, overlapping boundaries and must not be added indiscriminately. `changed=false` means no CAS contents were copied, not no scan, lock wait or maintenance work. Existing preloads/environment and uncertain-exit/non-replay barriers remain.

### Shared account-profile requests and HTTP diagnostics

Profile and gift-notification identity readers share only a still-pending profile/users-current request with the same credential detailsLifetime, issuer/token and actual request headers. Completion removes the in-flight entry; failures are not cached and no HTTP retry is added. Different credentials or request contexts cannot share an old identity result.

HTTP403 logs explicitly use `http-error` / `forbidden`, retaining `network` only for the existing thrown UI/schema contract. That compatibility field does not establish offline/DNS/TLS failure.403 neither clears credentials nor automatically means an expired token.401 and successful-HTTP business code40003 retain upstream expiration behavior. Backend account errors and frontend read-failed logs use one JSON string with fixed non-sensitive fields, avoiding `[object Object]` for those messages.

This reduces duplicate concurrent GETs and diagnostic ambiguity; it does not change server rejection rules. Model-catalog success does not establish profile403 recovery. Remove runtime configuration's full-access/workspace-write/read-only selector and its explanatory text. Production Web launch fixes `DSH_PERMISSION_MODE='danger-full-access'` and no longer accepts a mode parameter. Upgrade clears historical `permission_mode`; portable backup/system-preference migration no longer exports or imports it. Old interrupted-recovery transactions accept but ignore that field while restoring other fields normally. Existing DSH session permissions, plugin configuration and the independent recovery runtime's read-only policy are not rewritten here.

Screen-operation manual/per-app/allow-all confirmation is a separate native policy and remains. Android accessibility, ADB, Root, Shizuku, microphone, SAF and virtual-screen capabilities retain system grants and target/generation/latest-frame validation. Removing this DSH mode selector does not strongly sandbox terminals or third-party plugin execution.
