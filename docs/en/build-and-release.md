## Where identities come from

| Identity | Source of truth | Maintenance rule |
|---|---|---|
| APK code / name / filename version | `versionCode/versionName/dshaApkNameVersion` in [app/build.gradle](../../app/build.gradle) | They mean different things. A filename may keep the regular version; a tag does not determine code |
| DSH content | [package.json](../../tools/dsh-runtime/package.json) and [lockfile](../../tools/dsh-runtime/package-lock.json) | Pin actual content; do not infer data format from the APK version |
| Ubuntu base identity | Split-package recipe, fixed inputs, and managed descriptor | UI changes do not increment base automatically; an ordinary DSH update is not an Ubuntu rebuild |
| runtimeId / contract | Actual content proofs generated by [prepare-runtime-descriptor.py](../../tools/prepare-runtime-descriptor.py) | Separate content digest from launcher/bridge/data contracts; do not edit a proof into a desired string |
| Release tag / source commit | Actual Git commit and Release | Commit is not APK SHA. Freeze source before generating attachments and external receipts |
| Package / release certificate | [ci/release-identity.json](../../ci/release-identity.json) | `io.github.sunsetrne.dsha`, the Mod-owned certificate `a4b0413c…5d5d` (full SHA-256 in that file), v1/v2/v3; no historical E7E3, debug or temporary substitute |

Not every version field should become the same number. Check callers, locks, and generators for the layer being changed, then bind source, inputs, APK, and Release. Put the source ZIP's own SHA in an external Release/receipt rather than a file inside that ZIP, avoiding self-reference.

## Git and complete source ZIP

Git stores application source, resources, locks, recipes, checkers, and necessary notice/lock-covered small binary inputs. Large generated rootfs, DSH, and recovery archives stay out of Git. A source-only checkout supports source-only checks, not a “release slim package” with missing large archives.

Fixed original inputs no longer depend on a private source ZIP. They ship as a public pre-release Release asset and are pinned file-by-file by [ci/sunset-inputs.lock.json](../../ci/sunset-inputs.lock.json); the restore command, rollover flow and integrity requirements are in [fixed build inputs](../fixed-build-inputs.md). Builds still need JDK 17, Android SDK/NDK, Python, Node and the other toolchain inputs. Transformed layers in an APK cannot recover all original build inputs; do not guess missing inputs from arbitrary latest versions or old caches.

The maintained source location is whatever clone you are working in; historical worktrees are not the current build source. Other machines use the current commit/tag. [CONTRIBUTING](../../CONTRIBUTING.en.md) defines LF rules, managed bytepins, small binaries, historical originals, and the nine explicit audit-JSON exceptions. Do not rewrite line endings repository-wide or upload raw user/device material.

## Validation stages

These are responsibility groups, not a claim that any one script proves a whole group. Record associated commands and real results in the current receipt, retain failed originals, and record reruns separately.

| Stage | Entry points | Results to retain |
|---|---|---|
| Source and navigation | `check-source-hygiene.py`, `check-document-links.py`, host-manifest check | Exact file set, broken current links, historical local-evidence classification; no ignoring current broken links to pass |
| Fixed inputs and descriptor | `ci-assets.py`, `verify-runtime-descriptor-source.py`, generator check modes | Actual input SHAs, missing inputs, and which bytes reuse older exact-equality proofs |
| Host / browser | Each `run-host-tests.py` stage, real locked-runtime fixtures | Environment, selection, platform skips, expected negative controls; not phone acceptance |
| Standard JUnit / Release Lint | Corresponding Gradle tasks | Selected classes/XML tests/failures/errors/skipped, cache/incremental reuse, Lint errors and warnings |
| Exact APK content | `audit-standard-apk.py`, `verify-dsh-upgrade-apk.py` | APK identity, managed assets/DSH, manifest/DEX, matching source and SHA |
| Emergency / plugins / licensing | `verify-recovery-apk.py`, `verify-plugin-upgrade-gate.py`, `verify-third-party-apk.py` | Independent emergency lock/asset locations, plugin policy, notices, and actual APK contents |
| Signing and delivery | Android `apksigner verify --verbose --print-certs`, release owner's inventory | Package/code, `debuggable=false`, certificate, ABI/API, APK/ZIP sizes and SHAs, remote attachment status |

[check-release-prerequisites.py](../../tools/check-release-prerequisites.py) checks release-identity JSON format, package, and certificate fields without keys. It cannot replace actual APK signature verification, software receipts, or phone acceptance. `verifyPublishCertificate` checks the actual keystore certificate and applicationId against `ci/release-identity.json`; historical E7E3, A3 and debug certificates must not sign a Mod release. Keep private keys, passwords and credentials out of command echoes and source.

The actual “seven APK gates” wording belongs to a particular delivery's selection/logs; it does not mean each row above is one tool invocation. Consult that receipt for composition/results rather than deriving a pass count here. Use current `--help` and entry-point arguments so an old audit tool's defaults do not point at a new delivery.

## Reading test counts

F10's 124 classes / 785 tests per variant, fix1's 511 tests each, and build170's 45 related checks each belong to their own selections and execution times. They are not static Java-file counts or text counts of `@Test`. Dynamic/parameterized tests, variant conditions, skips, setup failures, and reruns change the metric. A test's presence in source does not mean it ran, and cache-based passes must be explicit.

Retain matching source/inputs, task names and selected classes, XML set, tests/failures/errors/skipped, first failures, rerun reasons, incremental/cache reuse, and unrun scope. Mark raw local receipts as local when absent from the source package; mentioning their names in Markdown does not make them independently downloadable or reproducible. Do not transfer historical release summaries into current source conclusions or vice versa. See the [documentation gap map](documentation-gap-matrix.md).

## Local delivery, publication, and device acceptance are separate conclusions

After local APK verification, place regular APKs and `.apk.sha256` files in `release/<filename-version>/` under the user's rules. Move older same-version artifacts to `history/`. Source and receipts belong in `artifacts/source/` and `artifacts/deliveries/`. Intermediate `app/build` output is not delivery, and checking a directory does not prove GitHub upload.

Only within authorized publication scope, verify the actual repository, commit/tag, APK/complete source ZIP, and remote attachment digests. Filling documentation does not automatically publish, alter the website, or modify the original repository. New APK software passes do not inherit old phone results. Device/ADB/conversation and continuous four/eight-hour acceptance remain paused.

If future release-upgrade acceptance is authorized, first verify the same package, the Mod release certificate hash recorded in `ci/release-identity.json`, non-debuggable state and version, then normally stop and prove exit. Do not uninstall, clear data, or inject force-kill/broken-plugin faults into production data. [Updates](update.md) describes the current installer boundary; historical build173 managed-install records do not apply to the maintained build170 base. Full cold-network builds, Android 11+ ROM and external-model matrices require their own real evidence; Android 10 and below are no longer supported.
