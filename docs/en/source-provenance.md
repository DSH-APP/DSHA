# Provenance review of the current implementation

An old header in Shizuku's `ShellService` mentions CFR 0.152. That comment alone does not establish which external object was decompiled, who originally authored it, or whether its license is incompatible. The verifiable repository provenance is that path at commit `5f984e4029a5223bcb37dc7d6d290268d2449609`. No materials reviewed during this work establish its earlier external origin, so no legal characterization is made.

For build156, the locally available Git history was read as original blobs revision by revision. Ten records of the path were found; the earliest visible commit was `a3a0b00321402f20fc4efc91d3f9c83d3ecd01d4`. Original-byte digests and whether the CFR header was present in each revision are recorded in the [historical provenance review](../audits/build156/shellservice-source-provenance.json). This evidence extends traceability within the repository. It does not establish a missing external original or authorization. The current source bytes and annotation were retained during that review.

The current execution path uses the public `IShellService` protocol, Android ProcessBuilder, the repository's DeviceShellExecutor/DeviceShellPolicy, and BoundedProcessRunner. Binding capabilities, the 30-second total deadline, bounded output, privileged-process-only exit and process ownership remain subject to actual regression validation. Removing an old comment has not been treated as provenance proof, and infringement has not been alleged without evidence.

Third-party versions, actual asset digests, upstream sources and bundled licenses are described in [THIRD_PARTY_NOTICES.md](../../THIRD_PARTY_NOTICES.md) and the historical build154 audit. Optional components for other platforms in a lockfile are not automatically part of the distribution. Source auditing of proprietary proroot and byte-for-byte reproducibility across platforms remain separate limitations. Any unverifiable provenance must remain explicitly unknown rather than being guessed.
