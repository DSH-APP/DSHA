# Interface language, system-language capture, and browser synchronization

Verification date: 2026-10-21. Source: the corresponding Chinese maintenance guide and current working-tree implementation, using published F10 `087724c` as a reference baseline. This implementation guide adds no device language-switching validation.

## User choice and effective timing

**Settings → Interface language** offers **Follow system / Simplified Chinese / English**. The default saved intent is `system`. Explicit `zh/en` choices from older versions remain. The settings summary also shows the effective language. [UiLanguagePreference](../../app/src/main/java/com/deepseekharness/app/util/UiLanguagePreference.java) accepts exactly these three values; other historical values normalize to Follow system.

| Preference | Effective interface language |
|---|---|
| `zh` | Simplified Chinese, independent of system changes |
| `en` | English, independent of system changes |
| `system` | Chinese system tags map to Chinese; other valid languages map to English; an unrecognized source falls back to Chinese. |

After the selection dialog closes, [SettingsFragment](../../app/src/main/java/com/deepseekharness/app/ui/SettingsFragment.java) calls [LanguageController.select](../../app/src/main/java/com/deepseekharness/app/ui/LanguageController.java), saves the preference, and updates resources immediately. Activities may be recreated for a language change. Terminals, the Web service, and application-level business tasks remain with their owners. Changing language must not replay commands or restart DSH.

## Why the system language is captured at process startup

[DshaApp](../../app/src/main/java/com/deepseekharness/app/DshaApp.java) calls `SystemLanguage.initialize(this)` before applying the interface language. The app calls `Locale.setDefault`. Reading that default later as the system language could make Follow system read the just-applied app language and become self-locked.

[SystemLanguage](../../app/src/main/java/com/deepseekharness/app/util/SystemLanguage.java) therefore captures the real system-preferred language at the earliest point in the process. Later `Locale.setDefault` changes do not alter it. Android13+ first reads `LocaleManager.getSystemLocales()` to avoid resource contamination from a persistent app language. When unavailable, it falls back through the system resource LocaleList, legacy `Configuration.locale`, and the JVM default. Initialization publishes only once; the earliest formal initialization can replace a temporary value obtained before it.

This is a process-level capture. The implementation does not promise immediate resampling when the system language changes inside an already long-lived app process. A new app process resolves the new system source; the current process's Follow system mode uses its captured value. Stopping DSH, clearing app data, or rebuilding the environment is not a language-refresh procedure.

[AppLocaleDispatch](../../app/src/main/java/com/deepseekharness/app/util/AppLocaleDispatch.java) uses platform application locales on API33+ and AppCompat on earlier versions. Application resources are also updated for notifications, overlays, and background tasks. Build resources must cover both Chinese and English; changing XML alone does not cover every dynamic string.

## Dynamic state and the browser

[UiStateText](../../app/src/main/java/com/deepseekharness/app/util/UiStateText.java) retranslates registered complete messages or templates only at the display boundary. Parameters remain verbatim. It does not replace arbitrary substrings in user messages, commands, or logs. Original state and business data must not be rewritten by an interface-language change. The dynamic translation source is [messages.json](../../tools/i18n/messages.json).

[WebPageScripts](../../app/src/main/java/com/deepseekharness/app/ui/WebPageScripts.java) injects `window.__DSHA_LANGUAGE__` and dispatches `dsha-language`. The WebView language listener accepts only the current local, same-origin top-level page. An explicit browser selection of `zh/en` can update the host preference through that restricted message bridge. Ordinary external sites have no such authority. Low Gecko synchronizes through its own extension message channel. The recovery page receives language and compatibility scripts without the formal device/plugin bridge. Synchronization does not imply that model replies, user-plugin content, or external pages are translated.
