# rc1.4 原生 UI 排版调整计划

用户选择“紧凑但不要过于紧凑”。本轮采用适度紧凑的工具型界面，保留右上角日夜切换，不重新加入主题设置卡片，版本名与版本码保持 rc1.4 / 113。

## 目前问题

- 返回按钮和标题分成两行，返回与日夜按钮外观过重。
- 更新、诊断、备份页面把大量主/次/低频操作都铺成相同宽度和颜色的按钮，阅读顺序不明确。
- 设置页模块与其他条目的字号、内边距和图标结构不同；省电说明过长。
- 插件页的介绍和帮助文字占据较大空间，实际安装入口不够集中。
- 部分按钮紧贴、部分区域间距过大；配置/数据页存在重复说明、技术路径直接占据主界面的问题。
- 启动页使用固定顶部操作区和剩余高度日志，窄屏、大字体或短屏下需要检查主操作与日志的分配。

## 统一规则

- 页面边距 16dp，卡片内边距 14–16dp；使用 8/12/16/24dp 间距，分组清楚，组内适度紧凑。
- 顶部一行安排返回与页面标题；日夜切换为轻量操作，主导航保持稳定。
- 主按钮最小 48dp，工具按钮至少 44dp；均允许大字体自动增高，不能靠缩小文字塞进固定高度。
- 正文 15sp、说明 13sp、辅助信息至少 12sp；保留当前日夜对比度修复。
- 每个任务区只突出当前主操作；次操作并排或采用轻量按钮，低频/危险操作放在独立下方分组。
- 按任务组织：更新分为版本/状态/操作/说明，诊断分为检查与修复/反馈/报告，数据页分为备份/文件共享/环境维护。
- 保留原控件 ID、权限确认和操作语义，避免排版调整改变已有功能。

## 验证要求

使用原生控件渲染和截图检查 320/360/392dp、日夜模式、1.0/1.3 字体，以及忙碌、错误和空状态；确认文字不裁切、按钮不重叠、首要操作可达、长内容可滚动。发布包另核对签名、版本、完整摘要和环境版本。旧交付保留到 release/history。
