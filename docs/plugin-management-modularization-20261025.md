## 已核实事实（源码调用链，B 级证据）

- 原生插件管理是 `PluginFragment`；DSH Web 插件管理有独立 list/management 协议与运行插件，不把两页当同一 UI。
- `DshaApp` 已持有应用级 `PluginRepository`，已有单线程 IO 和内存列表，没有本轮新增的持久目录缓存。
- `GuestScriptQueue` 已串行调度底层脚本；用户第二个 mutation 仍因 `working` CAS 被拒绝，两者不是同一个队列。
- 启停已有严格意图回执检查、目标更新和合并刷新；列表已有纯进度不重算优化，但仍用全量 adapter 通知。
- Fragment 本地刷新修订号随重建丢失；导出/能力查询成功也会追加全量刷新；提交前获取环境凭据、进度读文件、取消写文件和完成清理存在主线程 I/O。
- 旧 PluginListAudit/PluginSortAudit/PluginUiInstrumentation 仍取 Activity 仓储，与生产不一致。列表 position 0 是页头。旧“只解析”设备审计实际可能自动提交安装，不能按只读执行。
- 实际数据位置须经 Android authority、UserDataLayout 与 NOFOLLOW 路径解析；Web generation 只表示 Web 意图代次，不能替代数据树出生身份。

## 设计与阶段

使用现有 Android 工程内的 `plugins` 包：当前协作者依赖 Android 生命周期和已有执行后端，暂不增加 Gradle module。

1. **目录与入口**：`PluginManagementEngine` 统一前台/READY 预取及按过期状态核对；`PluginRegistry` 保存不可变、带版本、来源身份和失效序号的展示投影；`PluginBackendAdapter` 解析真实宿主数据位置与源身份。`PluginRepository` 保留 guest 兼容接口和现有事务实现。
2. **列表渲染**：保留页头、条目、页脚布局与入口；条目采用明确稳定身份及内容版本，DiffUtil/payload 发出增加、变更和移除。保存搜索、过滤、排序、展开与滚动锚点，合法重排按现有排序规则执行。
3. **变更检测**：FileObserver 只标记可能变化，经有截止时间和最小扫描间隔的合并器调度；扫描期间的新失效保留。恢复前台、环境重绑、原生完成及加载核验事件补偿。文件通知不作为成功或健康证明。动态运行心跳不每两秒触发全量扫描。
4. **用户任务队列**：有界单消费者，任务有 operationId、目标身份、desired、来源和前提、阶段及结果。等待不持环境/运行凭据，队首后台复核后获取。只合并未开始的同目标启停；安装/删除/更新/回退不覆盖。进度、取消文件和清理均在后台；回执成功与后续扫描失败分别记录。

## 状态与兼容边界

observed 是最近完整查询或有效执行回执确认的安装/配置事实；desired 是队列中的用户意图；operation 是排队/执行/提交/成功/失败/待核验；runtime 依据实际代次内加载证据，不能从 enabled 或文件事件推断。

持久条目使用 installed/profile/scope/明确规范名；原生后端当前读 web profile，各发现源已按原 guest 合同归并，source/location/origin 保留为展示及操作前提，不能随来源显示变化制造新条目。会话临时插件保留完整 generation/sessionId/pluginId。仅沿用现有明确官方 alias 归并规则。Registry 不写 profile、禁用标记或事务日志，不成为新权威。

保留 EnvironmentTaskGate → RuntimeTasks → 维护屏障顺序、NOFOLLOW、原件保留、提交前完整校验、取消边界及 UNKNOWN 不重放。预取与列表刷新不初始化环境，不启动/重启 Web。安装后原有恢复 Web 行为需额外核对用户停止意图/代次。

首版目录和用户队列为进程内状态，不承诺跨进程自动执行；进程死亡后重新核验事实，已有 guest 事务/恢复门禁保持，不自动重放未知安装、删除或更新。SAF 输入执行时重新打开验证可读性；不保存凭据或敏感源正文。

## 验证与回滚计划

按阶段运行确定性单测/真实 Repository 生命周期测试及相关 guest 事务/恢复回归。Standard Android 编译、JUnit、Lint 和实际 APK 范围绑定本轮提交与 CI 产物，旧 artifacts 仅作历史。记录失败原件与修正后的结果，不能把 source-only 或宿主测试写成真机验证。

性能只记录实际扫描/guest 调用/列表重绑与主线程工作证据；区分首次可见、缓存展示、扫描完成、提交核验、实际加载，不编提升比例。

回滚以本轮分阶段提交的逆序 revert 为单位，保留原基线和用户文件；本轮不迁移真实插件数据格式，不自动写入新的持久缓存或恢复队列。

## 实施记录

- 基础协作者与身份模型提交：`267f5b2`。实际接线顺序按依赖调整为基础模型 → 管理入口/执行器/检测 → 页面与夹具 → CI 历史发布；可逆序 revert，不改用户插件数据格式。
- 管理入口由 Application 懒持有；本地 Activity 首帧空闲后建立，只读 READY 探测在后台。缓存 TTL 为 60 秒。显式刷新与目录失效进入单扫描合并器；窗口为 200ms 防抖、首事件最多 2000ms 发起、两次扫描开始至少间隔 750ms，实际查询另受原有总预算限制。失败保留旧快照，冷却期间页面重建不会无限重查。
- 文件观察按真实 UserDataLayout 绑定：根及标记观察不等于内容证明；目录遍历有 1024 观察目录、32768 枚举成员、48 层、单轮 1000ms 的上限。受限覆盖明确记录，由前台/环境事件和低频核对补偿。退后台释放观察器并取消未被页面或显式刷新接管的预取；正在执行的用户任务继续。
- 用户队列等待上限 32、单 active、完成历史 64；只有同目标、同来源、同必要版本的未开始启停可以合并。每个请求都有 operationId；未解析安装输入只记录摘要，候选预览/confirmation 与真实提交保持同一逻辑操作。等待不占 EnvironmentTaskGate/RuntimeTasks；进度文件、取消文件、清理、诊断写入已移出主线程。
- 安装页按保存的 operationId 读自己的结果；关闭页面不清理其他任务候选。进程死亡后历史缺失明确提示核对，不自动再发安装。SAF 在执行时重新打开，失权则明确失败。
- 删除沿用原有事务与原件保留，只新增删除后入口读回回执。原 `delete-list` 和完整 list 合同保留；原生使用独立回执更新目标再核对，导出与能力查询不再追加无关全量扫描。
- 布局资源未修改。保持搜索、过滤、排序、展开与两个标签的滚动锚；合法重排按已核验配置排序，相同排序值用稳定键打破平局。DiffUtil通知显式偏移页头；进度和展开复用既有行次序。五处列表/语言/重建审计不再错误注入 Activity 仓储；旧会自动安装的“只读下载”审计已改成真实只读观察范围。

## 性能解释与剩余限制

- **首次可见/缓存展示**：通过应用内状态复用减少重复查询请求；没有设备端首次可见、缓存展示毫秒实测。
- **后台扫描完成**：仍执行既有 guest 完整校验。预取会改变等待发生的时间，不宣称它降低单次扫描工作量或带来某个提速比例。
- **操作提交确认**：启停/删除严格回执后发布结果，完整目录核对独立；安装解析与提交仍走原检查与维护事务。
- **实际加载生效**：动态条目使用 10 秒内、同 Web generation 的真实活动摘要；持久条目的旧 activation `loadState` 仅作历史事实，缺乏当前 Loader 证据时显示“未核验”。未新增认证 Web 推送、未把 enabled 或文件事件当成热加载成功。
- 目录和任务都为进程内状态，没有持久快照/自动重放队列。重启后重新核验，真实未完成事务仍由原有恢复门禁处理。
- 队首若遇到维护、来源变化或失效输入，会明确拒绝/失效；不会持有执行凭据无限等待或自动重放未知结果。
- 本轮尚无实际设备安装、旋转/底栏/滚动像素验证、OEM事件风暴、外部终端/Web并发真实负载数据；相关合同由受控测试和后续 Standard CI 分别验证，范围不互相替代。

最终 Standard CI、提交、标签、APK 摘要和发布链接将在完成后补入本节。

## 2026-10-25 启动与更新后的状态修订

本节修订上面的首版边界：持久插件新增当前 Web 的实际 Loader 投影，目录缓存仍为进程内状态，不引入跨进程任务重放。

- 同一用户数据根仅运行时标记、运行根或 Web 代次变化时，保留上次完整目录，明确标记陈旧并重新核对。执行前提仍比较完整来源身份；真正用户数据根变化不串用旧目录。
- READY/来源核对在探测、扫描期间到达时保留一次待办；旧票继续拒绝，结束后补一次当前来源读取。普通失败仍冷却，后台不保留周期扫描。
- Web 代次变化通过内存身份立即撤销旧运行结论，不等待环境可读。有效心跳绑定 generation、实例、profile 和版本；过期或暂不可读时同代上次状态显示为待核验，旧实例不能确认新实例。
- 启停和删除的严格执行回执先以精确目标更新 Registry；后置来源读取失败不撤销已确认的配置事实。真正来源替换时保留操作回执，不能污染新目录。
- 启动观察器只读解析 bundle 插入入口，冻结启动时版本与模块身份摘要；两秒活动采样只遍历实际 Cordis Loader，不重读全目录、不重复执行插件。一个 bundle 的多个入口整体核对；等待服务、初始化中、加载失败和已加载分别呈现。修改既有入口、无法明确归属的 include/表达式、缺席或歧义保持未知，不把 enabled 或旧 activation ledger 当作当前成功。
- 原生运行摘要新增 `instance` 和 `installedPlugins: [{name, version, profile, state}]`；保留原动态 `plugins` 协议。完整目录查询保留同版同代运行证据，真实新摘要再替换；过期补偿只重投影一次，不触发完整扫描。历史激活记录仍单独展示。

新增回归覆盖真实生产目录协议、官方三类 bundle 的入口映射、实际锁定 Cordis 的加载/失败/等待/卸载、多入口与错误归属、刷新暂不可读、实例/版本/代次错配、在途 READY 补偿、回执后的读取失败，以及真实 Fragment 的状态文案。Standard CI 增加实际 Loader 宿主测试入口；宿主逻辑、Android 编译和设备验收分别记录。未新增手机安装或真实 OEM 文件事件验收。
