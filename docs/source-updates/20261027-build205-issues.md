# build205 issue investigation and software validation

Based on build204, `0.2.1-rc.3-20261027.1312-dsh0.2.1-rc.3` / 205 retains the standard application ID and release certificate. Device acceptance was explicitly paused.

- #193: The Termux 0.118.0 emulator is vendored with provenance and license notices. Terminal-to-process writes use a bounded FIFO; paste is enqueued as one unit. Saturation pauses input and requires an explicit user decision to resume after outstanding writes drain. A cancelled or partially written input is not automatically replayed. Tests exercise simulated backpressure, ordering, paste and cancellation; actual Android PTY/JNI behavior and the pre-existing descriptor-close boundary remain unverified on a device.
- #194: A virtual-screen start with an unknown result can expose a filtered, fixed-set diagnostic stage and type. This preserves the unknown-result fence and does not establish that the HyperOS or Shizuku failure is resolved. No device root-cause claim is made.
- #198: A resolver configuration matching the bundled legacy two-line template exactly is migrated to valid Android-provided DNS addresses; modified files and a missing device DNS are retained. A manually written identical file cannot be distinguished from the template. Concurrent guest edits and parent symlink handling have existing limitations. Direct resolvers do not inherit Android Private DNS transport semantics; VPN, network transition and Private DNS require device verification.
- #202: Screen operations are bound to the latest successful observation's display, window and package; observation requests use an ordering fence. This reduces wrong-target actions but does not prove the reason the external app returned to DSHA or prevent Android from changing the foreground app.
- #203: Current rc3 already reconnects and re-establishes streams. The new host fixture checks foreground recovery and stream baselines without replaying an operation. It does not prove actual server restart, authentication or UI selection recovery.
- PR #200: The existing build194 host compression integration already handles the reported middleware case. Tests now exercise the real rc3 host with small 405 and large responses under gzip and br negotiation. The proposed unconditional suppression of repeated `writeHead` is not adopted because it could hide unrelated errors.

Standard Debug targeted JUnit: 67 tests in 10 classes, no failures/errors/skips. Release lint: 0 errors, 320 warnings; Standard Release assembled successfully. The first incremental compile and a subsequent run with two stale changelog assertions failed; after a full task rerun and updated assertions, the stated final test run passed. Host stream and compression fixtures passed 7 and 2 cases respectively. No Low build, APK installation, phone testing or real-world network/DNS measurement was performed.
