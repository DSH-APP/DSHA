## 原始失败和调整过程

1. 首次浏览器工具安装后提示缺少系统库；补齐容器中的 Chromium 运行依赖后启动正常。项目依赖锁和 Android 文件未修改。
2. 首轮 `file://` 导航 30秒超时，未进入核心交互断言：[首次原始记录](<validation-first-attempt.json>)。随后一个只读诊断任务同样卡在导航，被主动取消，不能将其记为成功打开。
3. 尝试由 Playwright route 在内存履约的文档导航也超时：[第二次原始记录](<validation-navigation-attempt.json>)。没有启动本地服务器，也没有更换当前 DSH GUI。
4. 改为 `page.setContent` 注入原文件完整文本，浏览器成功解析、执行和截图。首轮交互检查通过104条；增加极简菜单返回/再进断言并修正右上菜单与长行内容的避让后，最终通过116条。
5. 用户提出改为悬浮球后，先保留[改版前116条结果](<validation-before-floating-ball.json>)；在不改Android生产代码的前提下新增拖动、吸边、取消、焦点、避让与位置保留逻辑，复跑原回归及17条新检查，133条全部通过。该轮未新增工具安装或启动服务器。
6. 最终结果绑定上面的 HTML SHA。没有将早先导航失败抹掉或描述成“一次全绿”。导航超时根因未充分定位，不能断言来自 HTML 或容器中的某个具体组件。

### 验证工具副作用说明

为做真实浏览器渲染，本轮在容器临时目录安装了 Playwright，在浏览器缓存目录下载 Chromium，并补齐其 Ubuntu 运行依赖；**没有改仓库 package lock、没有操作 Android 设备文件/系统设置，也没有启动替代 Web 服务**。后续不需要这些依赖也可以阅读报告；交互 HTML 自身无第三方依赖。浏览器测试结束后已关闭浏览器实例。

## 本轮没有验证的内容

- Android `TerminalActivity`（尚未实现）、真实 Main task栈、预测返回、单最近任务卡片。
- Termux TerminalView/JNI/PTY 输入、ANSI/TUI、真实中文组合输入、软键盘高度动画、硬键盘和系统复制粘贴。
- FGS可见准入、通知拒绝、运行中服务丢失、息屏/Doze/OEM限制与系统杀进程。
- 真正的异步关闭失败/UNKNOWN、guest退出核验与维护屏障；HTML确认删除是模拟对象删除。
- APK、运行资产、Standard/Low 构建或设备兼容矩阵。
- 所有用户浏览器的 `file://`/文件预览打开方式。应下载 HTML 用支持 JavaScript 和原生 dialog 的现代浏览器打开；若某个文件卡片预览禁用脚本，它只能展示静态内容，不表示业务代码故障。

## 复现

先在独立工具目录安装 Playwright 与 Chromium（不加入项目生产依赖），然后在仓库根目录执行：

```bash
PLAYWRIGHT_HOME=/path/to/tooling/node_modules \
  node docs/design/terminal-20261025/check-preview.cjs
```

脚本会重生成同目录截图和机器验证结果。它只读取本地 HTML并通过浏览器交互断言，不启动服务器或连接任何实际终端。执行前若需保留旧结果，应先另存旧证据；已有失败记录与最终结果分别命名。
