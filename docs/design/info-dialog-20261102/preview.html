ⓘ 说明弹窗适配 · 交互原型

对象：配置页「模型和 API Key 在 Web UI 中配置。ⓘ」点开的弹窗，代码入口 InfoHint.show() → DshaDialogBuilder（全 App 共 17 处 InfoHint 调用同一弹窗）。 设备里点任意 ⓘ 打开；可切换设备、方案、主题、1.3 倍字体与语言，或拖动尺寸滑块模拟分屏。Esc 关闭，底部面板可下滑关闭。

推荐：方案 B，按窗口与锚点选形态只作用于 InfoHint

说明弹窗是「看一眼就走」的轻信息，不该打断操作。宽屏让说明贴着 ⓘ 出现，手机竖屏放到拇指区，矮窗只保证不被挤爆。全局 DshaDialogBuilder 的 560dp 规则保持不变，避免影响确认类弹窗。

窗口条件（dp）形态尺寸位置关闭典型设备
宽 ≥ 600 且 高 ≥ 480，有锚点锚定气泡，无遮罩宽 min(360, 屏宽 − 24)；高 ≤ min(420, 锚点一侧可用高度)，超出滚动正文ⓘ 下方 8dp；下方放不下且上方更宽裕时翻到上方。水平以图标为中心，夹在左右 12dp 内，小三角始终指向 ⓘ点外部 / 返回 / ✕平板竖横屏、折叠内屏
高 < 480紧凑居中弹窗宽 min(屏宽 − 48, 560)；高 ≤ 屏高 − 32居中；「知道了」与标题同一行，只滚正文知道了 / 点外部 / 返回手机横屏、上下分屏
其余（宽 < 600）底部说明面板全宽；高 ≤ 60% 屏高贴底，含 20dp 手势区留白；盖住底部胶囊（模态期间导航不可用）知道了 / 下滑 / 点外部 / 返回手机竖屏、左右窄分屏
无锚点（程序直接调用）方案 A 弹窗宽 min(屏宽 − 2m, 400 | 440)，m = 16 | 24居中知道了 / 点外部 / 返回—

共用排版

  • 标题 18sp / 600（气泡 16sp），正文 15sp、行高 1.55；文字左右边距 24dp（气泡 18dp）。
  • 中文每行控制在约 20–28 字；平板现状 512dp 宽约 32 字，偏长。
  • 按钮与 ✕ 触控区 ≥ 48dp（✕ 视觉 40dp，Android 侧用 TouchDelegate 或 minHeight 补足）。
  • 所有形态正文都可滚动，标题与关闭入口固定；1.3 倍字体下也能完整读到。
  • 打开时焦点落到弹层，TalkBack 先读标题；关闭后焦点回到触发的 ⓘ 行。

落地到代码（已实现：util/InfoSurfacePolicy、ui/InfoSurface；待真机核对）

  1. 新增纯逻辑 util/InfoSurfacePolicy 并配单测：输入 screenWidthDp、screenHeightDp、是否有锚点；输出形态、宽度、最大高度。边界用例 599/600、479/480、无锚点、1.3 倍字体不改变形态。
  2. InfoHint.bind() 把触发的 TextView 作为锚点传给新重载 show(context, anchor, title, full)；旧的 show(context, title, full) 保留并走无锚点分支，现有 17 处调用不用改。
  3. 气泡沿用 DshaDialogBuilder 自定义 view：窗口 gravity = TOP|START，x/y 由 anchor.getLocationInWindow() 与测得高度计算，dimAmount = 0，setCanceledOnTouchOutside(true)。不用 PopupWindow，保留 Dialog 的返回键与 TalkBack 焦点行为。
  4. 底部面板复用 CardSheet 的贴底动效与滚动测量；说明面板不需要抬到胶囊上方（CardSheet 的 lp.y 偏移只留给需要导航可见的场景）。
  5. 紧凑弹窗用 BoundedDialogLayout 承载自定义布局，避开 MDC 默认上下 80dp 背景内边距（数值依 MDC 默认推算，未真机测量）对横屏高度的挤占。
  6. 旋转：MainActivity 未声明 configChanges，旋转会重建并关闭弹窗。若要旋转后保留，改为 DialogFragment 保存提示键，按新窗口重新判定形态（可选项）。
  7. 验收：LayoutAuditInstrumentation 中英文、日夜、短屏、1.3 倍字体；真机手机竖/横、平板竖/横各截一张，核对气泡不出界、底部面板不被手势条遮挡。

其他方案取舍

A 收紧弹窗

只改 InfoHint 的弹窗：阅读宽度 ≤ 440dp（手机 ≤ 400dp），标题 18sp，收紧按钮区，最大高度 = 屏高 − 48。改动最小、风险最低；但平板上仍在正中，离右上角的 ⓘ 远，且遮住正在看的设置项。可作为 B 的第一步先上。

C 行内展开

点 ⓘ 在原位展开其余句子，无弹层、无遮罩，最轻。缺点是推动下方布局，长文在手机上把行撑得很高，也与 v5 方案 A「行内只留一句、详情收进 ⓘ」的初衷相反。只适合极短补充。

本原型只用于评审，不参与 Android 构建。设备内 1px = 1dp；平板竖屏 640×1024dp 由截图 1600px 宽 ÷ 2.5 推算，现状 512dp 宽与截图一致。英文为原有已翻译文案，长文压力样本为真实文案拼接。
