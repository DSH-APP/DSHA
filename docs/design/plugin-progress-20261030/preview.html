现状评估

按源码与 v5 token 静态还原，未抓取真机动态帧

现状不是“丑”，而是三件事混在一条 3dp 线上：是否在处理、处理到哪、结束得是否正常。 动效方案应该先决定这条线主要负责哪一件事，而不是先加装饰。

落点 · plugin_list_header.xml:65

平台横向 ProgressBar，通栏、3dp 高；只设了 indeterminateTint，轨道、圆角、端点均走平台默认。

驱动 · PluginFragment.java:651

busy 时显示；percent < 0 转不确定；percent ≥ 0 调 setProgress；忙碌结束立即 GONE。

数据 · PluginRepository.java:1296

percent = current * 100 / total，无总量时为 -1。排队、校验、安装阶段通常拿不到百分比。

容器 · RecyclerView 头部

插件市场 / 插件管理切换、列表滚动回收都会重新绑定；任何自绘动画都必须可附着、可离开、可幂等重放。

  • 中
    3dp 太细，缺少轨道对比

    下方是 46dp 的下载源按钮和 12sp 说明，3dp 蓝线在浅色底上存在感很低，容易被当成分隔线。

  • 低
    下载源说明常驻两行

    “自动选择可用的 npm 源…”是技术细节，约占 40dp，把进度条推远；按钮标签已经表达默认行为。删掉，或移入下载源弹窗，都合理。

  • 中
    确定态是硬跳变

    一参 setProgress 不做过渡，5% → 37% 会直接跳；平台自带的 animate 参数过渡也偏短，仍接近跳变。

  • 中
    不确定态是系统默认滑块

    与启动页 ShellActivityTrack 已建立的 2dp / 34% 光带语言不一致；同一条产品线出现两种“正在处理”。

  • 中
    没有百分比，也没有收束

    数字只存在于状态文案里；100% 后整条立即消失，看不到“完成”的确认，也分不清是成功还是被截断。

  • 中
    失败 / 取消没有视觉终点

    同样直接隐藏，只剩下方文字。用户滚到列表下方时，抬头只看到“没有进度条”，无法判断刚才是完成还是失败。

  • 中
    TalkBack 语义缺失

    进度条没有 contentDescription；setProgress 不保证播报，状态文字也不是 live region。

  • 低
    显示 / 隐藏会顶动下方内容

    GONE ↔ VISIBLE 带来约 13dp 的头部高度变化，状态文字和取消按钮会跟着跳；这与动效无关，但会放大“闪一下”的感觉。

02

六个动效方案

同一条模拟任务，六种表现；下方可暂停逐帧看

三条底线：不确定态不暗示百分比；确定态只跟随真实 percent；系统关闭动画时回退静态。 六个方案的高度都在 4–6dp，不改变页面结构（D 需要一行数字位）。

快速看：

静态首帧里 A / E / F 都是 37% 的填充，差别在不确定态与换挡；切到「校验」或播放完整流程，才能看到横扫、光点与呼吸的差异。 卡片里的“下载源：自动选择（推荐）”只是位置参照。真实顺序是：下载源按钮 → 4dp 说明 → 10dp 进度条；按钮上方另有 8dp 间距。

04

共通细节

动效之外，决定体感的四件事

条高与落位

同一方案在 2 / 3 / 4 / 6dp 下的可读性。当前是 3dp，建议 4dp。

2dp
只适合启动页那种“状态轨迹”，不做主进度。
3dp
现状高度；不圆角、无轨道时几乎只剩一条线。
4dp
推荐：拇指不挡、视觉可辨、不抢卡片标题。
6dp
仅 D 方案：为数字留一行时的胶囊高度。

完成 / 失败收束

当前两者都是直接 GONE；建议给一个短终点，再隐藏。

完成100% → .7s → .24s
点“重播”查看
失败停在 64% → .9s
点“重播”查看

建议：完成用 shell_good 填满并停 700ms；失败用 shell_bad 停在当前 percent 并停 900ms，再淡出。两者都不要“瞬间消失”。

参数与回退

可直接交给自绘 View 的初始参数；真机亮度 / 刷新率下再微调。

  • 横扫2.6s linear，带宽 34%，两端渐变透明
  • 填充240ms cubic-bezier(.22,1,.36,1)，只跟随真实 percent
  • 呼吸2.0s ease-in-out，透明度 .32 → .92
  • 收束完成停 700ms / 失败停 900ms，淡出 240ms
  • 减少动效无逐帧动画；不确定态保留静态 34% 光带，确定态直接落位

现有 ShellActivityTrack 已经用 postInvalidateOnAnimation + 时间相位，并在系统关闭动画时保持静态；新控件应沿用这套边界。

无障碍与回收

进度条是“状态”，不是装饰；TalkBack 与列表回收都要有确定行为。

progress.setContentDescription("插件任务进度：" + percent + "%");
if (percent >= 0) progress.setProgress(percent);
// 只在 25 / 50 / 75 / 100 或阶段切换时播报，
// 不要每 1% 调 announceForAccessibility。
  • 回收：header 会被销毁重建；动画相位应来自状态与时间，而不是 View 内部的一次性标记。
  • 可见性：onWindowVisibilityChanged 停帧，onDetachedFromWindow 释放 shader。
  • 换挡：不确定 → 确定时先清掉上一轮进度，避免旧 100% 闪一帧。
  • 幂等：同一状态重复渲染不重置横扫相位；只在 busy / percent 真正变化时更新。

评估与建议

默认方案、增强方案与不建议做默认的方案

D · 数值胶囊 ●●●●●●●●●○●●●●● 中低低要数字时
E · 呼吸脉冲 ●●●○○●●●●○●○○○○ 低低长等待

01 · 最小闭环

A + 完成收束 + TalkBack

4dp 自绘控件，沿用启动页活动条的语言；确定态 240ms 平滑，完成时 100% 好色停 700ms。改动集中在一个 View 和 header 高度，最容易先落地。

02 · 明确百分比

D · 胶囊 + 右侧数字

慢镜像 / 大插件时，数字比任何动效都有用。需要把 header 的一行改成 [bar + 42dp 数字位]，并确保 percent < 0 时绝不显示数字。

03 · 分状态 · 已采用

F · 不确定呼吸 / 确定流光

排队、校验、安装用更安静的呼吸；下载用流光。两套参数共用一条 View，适合“不确定阶段多、下载阶段短”的真实任务。当前 PluginTaskProgress 按这套落地：成功绿色 100% 停 700ms，失败红色停在当前 percent 停 900ms；下载源原文案在右侧圆形感叹号弹窗里。

  • 插件市场 / 插件管理切换，动画不重置、不闪 0
  • 列表滚动回收后重新附着，相位连续、无残影
  • 确定 100% → 好色收束 700ms → 240ms 淡出 → GONE
  • 失败停在当前 percent，坏色 900ms 后淡出
  • 不确定 → 确定 → 不确定，三种换挡无旧值闪烁
  • 减少动效：静态 34% 光带或静态 100%
  • 深色：轨道 shell_raised、填充 shell_accent
  • 1.3× / 2× 字体，header 不因文字变高而错位
  • TalkBack：进度可读，只在里程碑与阶段切换播报
  • 后台 / 回前台：停帧，回来按真实状态继续
不建议把 C 的发光或 B 的分段做成默认。 C 的 glow 在低端屏与深色底上容易糊，长期使用会腻；B 的分段会被读成“五个阶段”，而真实数据只有一个 percent，容易变成假阶段。 两者都可以作为实验开关保留，但默认应当克制、可解释、可回退。

本页是离线设计预览：没有连接设备、没有触发插件任务、没有修改 app/ 下任何文件。 资源、深色、字体缩放、TalkBack 与真机刷新率仍需在设备上验收。
