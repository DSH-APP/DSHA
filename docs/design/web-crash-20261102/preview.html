崩溃后对话页 · 重绘方案 v2

实验性变更声明实验性 UI 绘制。崩溃现场依赖真实进程退出、渲染器崩溃与网络错误，无法快速稳定复现，验收不能一次完成；本预览为静态模拟。「现状」一栏是按代码推断，未在真机逐项复现。

新增「当前状态」表：把后台服务、自动恢复、网页内核、对话页面、连接逐层写明，不再只有一句结论。下方可以直接选情景，也可以逐项组合。

判定按层级从上到下，命中即停：
1 用户已停止          → 不是崩溃，窗口照常关闭
2 鉴权前退出          → failedWebPage → 启动恢复页
3 重启预算用尽        → RestartBudget.LIMIT=3，停止自动重启
4 无响应              → 保活每轮探测，UNAVAILABLE 连续 3 次（健康检查）
                        才 restartWebAutomatically（冷却 120 s）
5 鉴权后退出          → exited() 记失败；不会自动重启
                        （探测得到 UNCONFIGURED，不是重启候选）
   ├ App 重开接回     → suspendRuntimePage(exited=true)
   └ 本次打开         → 代次未变，retireEmptyHost 不收尾，
                        WebView 已销毁 → 现状推断为空白页
6 身份未确认          → suspendRuntimePage(exited=false)
7 正在启动            → loadSession：Web 尚未就绪
8 网页内核问题        → onRenderProcessGone / 能力检查 / 初始化
9 连接问题            → onReceivedError / HttpError / 凭据刷新
服务层结论优先：服务不在时，内核与连接只在状态表里列出。
v2 改了什么
  1. 结论从 8 种补到 17 种（19 个常见情景）：按服务 × 退出码 × 重启预算 × 健康检查 × 来源 × 内核 × 连接组合判定，每种都标明对应的代码入口。
  2. 新增「当前状态」表：一层一行，圆点颜色表示该层是否正常。退出码附一句通俗解释。
  3. 标出三类改动：仅重绘 只换样式；需改行为 现在不显示面板，要补入口；沿用 走启动恢复页或正常关闭。
  4. 平板竖屏 / 横屏版式保持 v1，状态表随左栏排布。
