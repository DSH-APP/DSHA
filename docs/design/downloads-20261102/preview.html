下载记录FileTransfersActivity · 交互原型

改了什么

  1. 标题可见：原页把「下载记录」只设成无障碍窗格名，屏幕上只有返回箭头。新版显示标题和实时摘要（条数 · 传输中 · 失败）。
  2. 一条记录一行：状态、大小、时间、位置合成一行元数据。完成态不再重复「已完成」「72.32 kB / 72.32 kB」「文件已保存并校验」，校验结果进详情。
  3. 同名可区分：显示完成时间与「已自动改名」标记。原页两条 preview.html 看不出差别。
  4. 一个主操作 + ⋮：每种状态只露最常用的一项，平板竖屏再露「分享」。原来 4 个等权大按钮，误触「移除记录」的概率高。
  5. 分组：需要处理（失败 / 暂停 / 待选位置）→ 正在传输 → 按日期的已结束记录；两类以上才出现筛选。
  6. 筛选改成等宽分段：全部 / 进行中 / 失败 / 已结束四段等分一行，不再横向滚出屏幕；数量跟在文字后，失败数用红色，没有记录的段置灰。
  7. 详情是二级页：手机和平板竖屏整页推入（返回键回到原滚动位置），平板横屏在右侧面板。从上到下：文件头 → 状态卡（下载 / 校验 / 保存三步）→ 主操作 → 保存位置 + 文件信息（平板并排两列）→ 管理区。
  8. 危险操作单独放：「取消下载」「移除记录」只在底部管理区和 ⋮ 菜单，带后果说明；取消已有进度的下载要二次确认，确认按钮用错误色。
  9. 原始信息收起：文档 URI、MIME、SHA-256 放进可展开的「技术信息」，默认只显示人能读的位置和说明。
  10. 说明放到用到的地方：底部常驻长句拆进移除确认、详情底注、分享提示和列表末尾的「说明」。
  11. 网页发起的分享 / 另存为：横幅说明进度，高亮目标记录，就绪后自动弹出选择器（试「网页触发分享 / 另存为」场景）。

状态 → 操作

落地到 Java 的要点

  • 时间与日期分组用现有 DownloadTask.createdAt；「已自动改名」可由 displayName ≠ artifact.name 判断，不需要新字段。
  • ListView + BaseAdapter 建议换 RecyclerView + ListAdapter（分组头作 view type、DiffUtil 只刷进度），避免每次状态变化重建按钮。
  • 平板横屏双栏按可用宽度 ≥ 900dp 切换，600–899dp 单列居中（最大 760dp）+ 详情弹窗。
  • 「移除已结束记录」是新入口：逐条调用 engine.remove，遇到 TASK_BUSY 跳过并提示。移除不可撤销，所以保留确认框而不是撤销条。
  • 文案进 tools/i18n/messages-extra.json（中英），布局跑 LayoutAuditInstrumentation 日夜、短屏、1.3 倍字体。
