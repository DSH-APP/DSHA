# 备份与恢复阶段验收（2026-09-07）

本记录针对正在开发中的应用优化，尚未发布为新的 GitHub Release。离线环境版本保持 9。

## 已修复行为

- 全量、对话、设置、插件使用不同文件名前缀，每次保存独立文件，保留之前的有效备份。
- 新归档格式 v3 保存真实 App/dsh 版本、范围、大小和逐文件 SHA-256；会话索引、附件及公开目录的实际数据进入快照。
- 插件携带源码、必要运行依赖、来源记录、上一版记录、安全启动状态及禁用标记；恢复到插件管理器支持的位置，官方模块重新建立链接。
- 通过实际 MediaStore URI 回读导出文件，核对长度和摘要后发布。Android 6—9 的直接导出使用同目录临时文件、同步和改名，失败保留旧文件。
- 先复制所选归档并完整预检，再展示范围、版本、文件数及影响。未知范围、冲突范围、截断、摘要不符、越界路径、缺失公开快照和空间不足均会中止。
- 恢复前停止 Web，候选数据全部就绪后按事务提交；失败回滚。事务日志支持进程中断后恢复，原生设置的回滚副本保留 Keystore 密文。
- 补建会话索引引用的可用工作目录，避免启动后会话被清出索引；恢复沿用当前设备的公开目录绑定。
- 备份与插件修改共用位于 `.dsh` 外的进程锁。未完成恢复期间禁止插件写入与 Web 启动。
- 每手动启动 Web N 次执行一次启动前自动备份（0 关闭），展示最近成功/失败及最近成功备份的预览入口；看门狗重启不计数。

## 证据

设备：Redmi M2012K10C，Android 13，arm64，4 KB 页。所有恢复目标均为本次创建的隔离样本目录；未对用户当前 `.dsh` 执行恢复，未卸载或清空主应用。

1. `tools/test-backup-device.py`：手机 Ubuntu/proot 中 16 项通过，包含四种范围往返、索引/附件/来源范围隔离、真实软链接、跨目录恢复、插件代码与运行依赖、官方模块和禁用标记、损坏归档、逐文件摘要、空间不足、提交中断、延后提交回滚、事务恢复及并发锁。
2. `tools/test-backup-device.py --plugins`：原有插件管理 18 项回归通过，验证共用锁改动没有破坏安装、更新、回退和安全启动。
3. `BackupInstrumentation`：四种范围全部通过。真实 MediaStore 导出 URI 可读；完整预检、Python 恢复和原生 ConfigStore 范围隔离一致；自动备份计数及原生设置事务回滚通过。测试导出的文件已删除。
4. `BackupInstrumentation -e realSnapshot true`：对现有环境只读打包和逐文件预检通过，未执行恢复。有效备份已保留在手机 `Download/DSHA/DSHA-backup-20260907-135015-164fc532.tar.gz`。
5. `:app:testStandardDebugUnitTest` 全部通过；新的范围断言、流复制/摘要/超限/中断测试通过。兼容版调试 APK 与测试 APK 构建通过。

测试运行器可通过 `-Pdsha.testRunner=com.deepseekharness.app.BackupInstrumentation` 指定；默认仍保留之前的 Rc13Instrumentation。

## 覆盖边界

Android 6—9 的导出分支已经实现，尚无对应实机验证；本记录不代表旧 Android 或 16 KB 页设备实测通过。自动备份已与真实 Web 启动及省电策略共同验收，见[运行恢复记录](optimization-runtime-verification.md)。最终 rc1.4 调试安装中再次完成 16 项备份和 27 项插件容器回归；双发布包及完整检查见 [rc1.4 验收记录](release-rc1.4-2026-09-07.md)。

旧归档没有逐文件摘要时会明确提示；旧包如果只保存了公开目录链接而没有数据快照，无法凭空恢复缺失内容，会中止而不是显示成功。原生 API Key 是否进入备份遵循既有“备份密钥”开关，设置文件和插件自行保存的凭据仍随原文件保留。
